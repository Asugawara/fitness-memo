# ADR-0007: 指標の種類を種目の明示属性にする（データから推論しない）

- **状態**: 採用
- **日付**: 2026-08-08
- **カテゴリ**: data-model
- **関連**: [ADR-0009](0009-group-metric-is-set-count.md)

## 背景

要件は「レップ数×重さをグラフにして、これまでの比較が簡単にできるように」。素直に `volume = Σ(weight × reps)` で実装できる。

しかし筋トレの種目には重量を持たないものがある。

- **自重種目**（プッシュアップ、懸垂、ディップス）: `weight = 0` になり volume が常に 0
- **時間種目**（プランク、デッドハング）: そもそも回数ではなく秒数

当初は「その種目の記録が**全て** `weight == 0` なら指標を総レップ数に切り替える」というデータからの推論を考えた。

## 決定

`Exercise` に **`kind: Kind`** を持たせ、**種目の作成時にユーザーが選ぶ**。データからの推論はしない。

```rust
pub enum Kind {
    Weighted,    // 指標 = Σ(weight × reps)、単位 "kg·回"
    Bodyweight,  // 指標 = Σ(reps)、単位 "回"。weight は「追加重量」として表示のみ
    Duration,    // reps を秒として扱う。指標 = Σ(reps)、単位 "秒"
}
```

プリセットは正しい `Kind` を付けて出荷する（ベンチプレス = Weighted、懸垂・プッシュアップ = Bodyweight、プランク = Duration）。種目タブから変更できるが、変更時に「グラフの単位が変わります」と警告する。

## 理由

推論方式は**加重カリステニクスで遡及的に壊れる**。

- ディップスを自重で 12 週記録する（全セット `weight = 0`）→ 指標は総レップ数で右肩上がりのグラフになる
- 13 週目にベルトで +10kg を付けて記録する
- 「全て 0」が偽になり、**系列全体が volume 指標に切り替わる**
- 過去 12 週分は `weight = 0` なので volume = 0 の直線に潰れ、末尾だけスパイクする

加重ディップス・加重懸垂はごく普通のトレーニング進行であり、しかも「強くなった」という最も嬉しい瞬間に**過去データが壊れる**。要件「これまでの比較が簡単にできる」が正面から破られる。

データの内容から意味を推論する設計そのものがバグで、意味は属性として持つべきだった。Strong や Hevy といった主要な筋トレアプリも、自重・加重自重・時間系を `weight == 0` の推論ではなく種目やセットのタイプ属性で持っている。

## 結果（トレードオフ）

- 種目作成時に選択が 1 つ増える。デフォルトを `Weighted` にして、プリセットは正しい値で出荷するので、実用上ほとんど意識されない。
- `Kind` を後から変更すると単位が変わり、グラフは不連続になる。ただしこれは**ユーザーの明示的な操作**であり警告も出るので、サイレントな遡及変更とは性質が違う。
- `Bodyweight` の `weight`（追加重量）は指標に folding しない。系列の一貫性を優先した。加重の進行はセット表示（`+10kg × 8`）で読む。
- `Duration` は `reps` を秒として扱う運用にした。専用フィールドを足すより「非常にシンプル」の要件に合う。単位ラベルが `秒` になるので取り違えは起きない。

## 検討した代替案

**「全て weight==0 なら総レップ数」の推論**: 上記のとおり加重移行で遡及的に壊れる。却下。

**`SetEntry` にタイプを持たせる**: セット単位で自重と加重を混在できるが、同一種目内で指標が混ざるので集計の意味が壊れる。種目単位のほうが正しい粒度。

**`weight` を `Option<f32>` にして「無し」を表現する**: 空欄と自重を区別できるが、「時間種目」は表現できない。`Kind` なら 3 つとも扱える。
