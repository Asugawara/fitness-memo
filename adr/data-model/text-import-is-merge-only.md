# テキスト取り込みは「足すだけ」に固定し、部位を増やさず、`at` を書かない

- **状態**: 破棄
- **日付**: 2026-08-09
- **カテゴリ**: data-model
- **関連**: [他アプリからの移行はスクショの文字起こしを貼り付けて受ける](../ux/migrate-by-ocr-paste.md)（なぜテキストなのか）, [`at` を `Option<i64>` にし当日入力時のみ埋める](at-optional-same-day-only.md), [「1日1種目1ログ」を不変条件にする](one-log-per-exercise-per-day.md), [ID を 60 bit 乱数にし、プリセットには固定 ID を与える](random-ids-for-safe-merge.md)

## 破棄した理由（2026-08-09）

前提だった[テキスト取り込みそのものを破棄した](../ux/migrate-by-ocr-paste.md)ので、この ADR も一緒に落ちる。取り込み経路が無くなった以上、「取り込みを Merge に固定する」規則が守る対象も無い。

実装（`src/import_text.rs`）は削除済み。**この ADR は判断の記録としてのみ残る。** 以下の本文は当時のまま。外から来たデータを既存の記録に重ねるときの規則——[ID が乱数なので名前でしか突き合わせられない](random-ids-for-safe-merge.md)、過去日のバックフィルに `at` を書かない、同じセット列を 2 度足さない——は、別の取り込み経路を作るときにもそのまま効く。

## 背景

[他アプリからの移行はスクショの文字起こしを貼り付けて受ける](../ux/migrate-by-ocr-paste.md) で、他アプリからの移行を「スクショの文字起こしを貼り付けて読む」形にした。この入力は **OCR の読み違いを構造的に含む**（`0` と `O`、`6` と `8`、行の分かれ方）。

JSON の読み込みと同じ画面に着地するが、入力の性質が違うので規則を分けた。

## 決定

### 1. 取り込みは `core::merge_db`（足すだけ）に固定する

`Pending` に `source: Source` を持たせ、`Source::Text` のときは**「置き換える」ボタンを描画しない**。`mode` はステージ時に `Mode::Merge` で固定する。

読み違いが混じり得るデータで既存を全部消す理由が 1 つも無い。取り込んだ結果が気に入らなければ、足された分を消せば済む。

### 2. 新しい部位を作らない

未知の種目の行き先は、**既存の部位から利用者が選ぶ**（`import_text::Assign::Into(GroupId)`）。選ばれなかった種目は取り込まない。

移行元の画面に写っているカテゴリ名（「Push Day」「胸・三頭」）をそのまま部位にすると、プリセットの 6 部位と意味が重なった部位が並び、以後ずっと種目が二重に分かれる。**部位はグラフの集計単位**（[部位別の指標を volume ではなくセット数にする](group-metric-is-set-count.md)）なので、増やすと過去の集計まで割れる。

`import_text::to_db` が返す `Db` の `groups` には**参照した既存の部位をそのまま入れる**。`merge_db` は ID 一致の枝で素通りするので副作用が無く、`Db` 単体で見ても整合する。

### 3. `ExerciseLog.at` は常に `None`

読み取ったセットは過去日のバックフィルなので、[`at` を `Option<i64>` にし当日入力時のみ埋める](at-optional-same-day-only.md) の規則どおり時刻を持たない。

ここに `now` を書くと、移行した瞬間に「最後のトレーニングから 0 分」になり、`core::elapsed_since_last` の出力が嘘になる。

### 4. 既存の種目に当たったら、取り込み先の名前で出す

`Bench Press` がプリセットの「ベンチプレス」に当たったとき、`to_db` は **`db` にある `Exercise` をそのまま複製**して返す。読み取った表記を入れると `merge_db` が `Conflict::Renamed`（改名）として報告し、「「Bench Press」は「ベンチプレス」として扱いました」が確認画面に並ぶ。**改名は起きていないので、起きたと言ってはいけない。**

### 5. 同じスクショを 2 回貼ってもセットを増やさない

`import_text::parse` は種目ごとの**かたまり**でセットを溜め、日に落とすときに「そのかたまりが既に並んで入っているか」を見る（`contains_run`）。入っていれば捨て、違うセット列なら足す（スクショが分割されている場合）。

1 行ずつ足す実装だと、足す側が毎回 1 セットしか持たないので既存と比べようがなく、2 回貼ると倍になる。これは [「1日1種目1ログ」を不変条件にする](one-log-per-exercise-per-day.md) が潰した壊れ方と同型。

## 理由

**移行は「動転している人」の操作ではないが、取り返しがつかない点は復旧と同じ。** 前のアプリを消した後に「実は半分しか入っていなかった」と気づく順序になりやすい。だから**足すだけ**にして、間違えても現状が壊れないようにした。

**ID は乱数なので、名前でしか突き合わせられない。** [ID を 60 bit 乱数にし、プリセットには固定 ID を与える](random-ids-for-safe-merge.md) の下では、外部から来たデータが既存の種目を指す手段は「同じ名前」しかない。だから `import_text` の照合キーは表記揺れ（全角 / 空白 / 中黒 / 大文字小文字）を潰したうえで、英語名 → プリセット日本語名の別名表を通す。

**別名表は ID ではなく名前に紐づける。** `presets.rs` の固定 ID を `import_text.rs` にも書くと、片方だけ直したときに静かに別種目へ繋がる。改名済みの端末では別名が当たらなくなるが、そのときは画面で部位を選び直せる。

## 結果（トレードオフ）

**「置き換え」で移行できない。** 空の端末に移す場合も「足すだけ」になるが、空なら結果は同じなので実害が無い。

**未知の種目は 1 つずつ部位を選ぶ手間がかかる。** 既定を「取り込まない」にしたので、選び忘れると入らない。読み取り結果に件数を出し、1 件も選ばずに進めたときは「新しい種目は部位を選ぶと取り込まれます」と言う。**黙って 0 件取り込むことはしない。**

**分割スクショの重複は完全には防げない。** かたまりが一部だけ重なる（1〜3 セット目と 2〜4 セット目）と足し合わさる。連続する同一列だけを見る単純な規則にしたのは、取りこぼしより重複のほうが画面で気づけるため。

## 検討した代替案

**未知の種目を「その他」部位に自動で入れる。** 部位を 1 つ増やすことになり、決定 2 と矛盾する。しかも自動で入ると、後から部位を直す作業がそのまま残る。

**種目名を編集距離で寄せる。** 「レッグカール」と「レッグエクステンション」のような近い名前を誤って同一視する。**間違って繋がった履歴は、間違いに気づけない**（グラフが滑らかに繋がってしまう）ので、完全一致 + 明示的な別名表に留めた。

**セットを常に連結する。** 同じスクショを 2 回貼ったときに倍になる。`merge_db` が `dedupe_by_exercise` で同じ罠を潰しているので、そちらに合わせた。
