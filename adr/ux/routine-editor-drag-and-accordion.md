# メニュー編集シートの「選択中」をドラッグで並べ替え、種目ピッカーを複数開けるアコーディオンにする

- **状態**: 採用
- **日付**: 2026-08-17
- **カテゴリ**: ux
- **関連**: [記録タブのカードとセットをドラッグで並び替え、`Vec` の並びをそのまま保存する](drag-to-reorder-in-record-tab.md), [種目タブを部位の折りたたみ一覧にし、1 つだけ開く](menu-groups-as-single-open-accordion.md), [保存したメニューから始める（種目タブを設定タブに改める）](start-from-a-saved-routine.md), [その日の記録から直接メニューを作れるようにする](save-a-day-as-a-routine.md), [設定タブの入口を節の一覧にし、中身は 1 階層下ろす](settings-as-a-list-of-sections.md), [トレーニングメニューを「名前 + 種目 ID の並び」だけのデータにする](../data-model/routines-as-named-exercise-lists.md), [アイコンに lucide を採り、`assets/icons/*.svg` を `include_str!` で埋め込む](../architecture/lucide-icons-as-included-svg.md), [シートをネイティブ `<dialog>` にし、手動の重なり順から降りる](native-dialog-for-sheets.md), [破壊的操作は静止時に警告色を持たない（カード削除をフッタへ畳む）](destructive-affordance-quiet-at-rest.md)

## 背景

メニュー編集シート（`views::routine` の `RoutineEditor`。設定タブの「メニューを追加 / 既存の行」と
記録タブの「＋ この日をメニューにする」の**両方**が開く）に 3 つ問題があった。

- **「選択中」の並びを直す手段が「外して入れ直す」しかない。** この並びは
  [トレーニングメニューを「名前 + 種目 ID の並び」だけのデータにする](../data-model/routines-as-named-exercise-lists.md)
  のとおり `Vec` の順そのもので、記録タブでメニューを開いたときのカードの並び ＝
  **その日どの順で消化するかという計画**になる。にもかかわらず入力はタップ順で固定で、
  2 番目に 1 種目挟みたいだけでも後ろを全部外して押し直すことになっていた
- **種目ピッカーが 6 部位 28 種目ぶん開きっぱなし。** 393×760 の実測で、組み終わった
  「選択中」を見返すにはピッカーを全部スクロールし切る必要がある。保存帯を sticky に
  したのと同じ問題（[保存したメニューから始める](start-from-a-saved-routine.md)）が、
  今度は「選択中」に対して起きていた
- **「このメニューを削除」がテキストリンク 1 行。** シートの最下部、保存帯の直前に
  地味な 1 行があるだけで、上に並ぶ種目ボタンの列に埋もれて見つからない

## 決定

**「選択中」の行番号を掴んでドラッグで並べ替えられるようにし、種目ピッカーを部位ごとの
アコーディオン（複数同時に開ける）にし、「このメニューを削除」に lucide の trash を足す。**

不変条件は 7 本。

- **ドラッグの幾何は `src/reorder.rs` をそのまま使う。** 新しい幾何を 1 行も書かない
- **掴む場所は行のほぼ全部（`.rtn-grab` ＝ 番号 + 種目名）。250ms の長押しで効き始める。**
  記録タブの `.card-head` と同じ扱いで、`.set-no` の即時開始は継がない（下記）
- **✕ は `.rtn-grab` の外に置く。** 「外すつもりのタップでドラッグが始まる」を
  構造で塞ぐ
- **ドラッグ中は `picked` の `Vec` を入れ替えない。** `transform` だけで見せて指を離した
  1 回で確定する。番号は `reorder::visual_index` を通して**見えている位置**を描く
- **スクロール容器は `.sheet-body`。** `window` のスクロール量を足さない（下記）
- **ピッカーは既定で全部閉。開閉は `RoutineEditor` ローカルの `RwSignal<Vec<GroupId>>`
  で、`OpenGroupCtx` を使わない**
- **trash は「このメニューを削除」だけ。「選択中」の ✕ は据え置く**

```
┌─────────────────────────────┐
│ メニュー名（必須）           │
│ [ 胸と脚の日            ]   │
│ [1  ベンチプレス      ]  ✕  │ ← [ ] の中を 250ms 押してから行を動かす
│ [2  チェストフライ    ]  ✕  │   ✕ は掴み口の外。「メニューから外す」で
│ [3  スクワット        ]  ✕  │   種目そのものは消えない
│ ›  ● 胸            5 種目   │ ← 押すと開く。複数の部位を同時に開ける
│ ›  ● 背中          5 種目   │
│ 🗑 このメニューを削除        │
├─────────────────────────────┤
│ [ 保存 ]                    │ ← sticky。掴んだ行はこの下を通る
└─────────────────────────────┘
```

## 理由

### ドラッグの幾何は再利用できるが、**座標系だけ**は作り直しになる

`src/reorder.rs`（`Slots` / `drop_index` / `pitch` / `offset` / `lift` / `move_item` /
`visual_index` / `neighbor` / `edge_scroll_step`）は `Db` も leptos も web-sys も知らない
純関数なので 1 行も変えずに載る。壊れるのは views 側で、**この並びが `.sheet-body`
（`overflow-y: auto`）という入れ子のスクロール容器の中にある**ことが効く。

- `scroll_y()` は `window().scroll_y()` だった。シートの中をいくらスクロールしても
  1px も動かないので、`Drag::advance` の `dy` が容器のスクロールぶんを取りこぼす
- 端の自動スクロールは `window().scroll_by()` を呼び、帯を `innerHeight` で決めていた。
  シートは `max-height: 78vh` で下端に貼るので、**画面上端の帯はシートの外**にある。
  つまり「下端まで運んで待っても 1px も進まない」

`views::drag::Scroller { Window, Element(id) }` を足して、**スクロール量・帯の内側の縁・
スクロールのさせ方**の 3 つをまとめて差し替える形にした。E2E で `Scroller::Window` に
差し戻すと「シートの下端で待っても `scrollTop` が 0 のまま」で確実に落ちる
（実際にその手順で確認した）。

**`Scroller` は要素ではなく DOM id を持つ。** `web_sys` の型は `Send + Sync` ではないので
`Drag` に載せると `RwSignal<Option<Drag>>` が `LocalStorage` 版でしか作れなくなり、掴む側
3 か所の型が連鎖して変わる（`views::mod` の `opener` が `StoredValue<_, LocalStorage>` なのと
同じ制約）。id は `views::Sheet` が `{testid}-body` で振り、`Scroller::of` が
`closest(".sheet-body")` で辿る。**呼び側に「自分がどのシートの中にいるか」を渡させない** —
`RoutineEditor` は入口が 2 つあるので prop で受ける形にすると、片方だけ間違った容器を
指しても**スクロールするまで差が出ない**（静止した容器のスクロール量は `measure_slots` と
`advance` の両方に同じだけ乗って打ち消し合うため、定数のズレは症状にならない）。

### 掴む場所は行のほぼ全部にし、長押しを入れる

★ **当初は番号（16px）だけをハンドルにし、細いから長押しは要らないと書いていた**
（`.set-no` と同じ扱い）。実装後の見直しで覆した — **記録タブのカードは帯を掴むのに、
同じアプリのメニュー編集では 16px の的を狙うことになり、操作感が揃わない。**
`.set-no` が番号だけで正しいのは**行の中に入力欄が 3 つある**からで、掴める場所を
そこしか作れないという事情による。「選択中」の行は 番号 / 種目名 / ✕ の 3 つだけなので、
その事情が無い。掴む場所は `.card-head` と同じく**行のほぼ全部**にする。

その帰結として**長押し（250ms）が要る**。
[記録タブのカードとセットをドラッグで並び替え](drag-to-reorder-in-record-tab.md) が
`.card-head` にだけ長押しを課したのは、`touch-action: none` を当てた帯からは
スクロールを始められず、即時開始だとスクロールのつもりのフリックが**画面を動かさないまま
順序を変える**からだった。ここでは行の高さが 46px 前後なので閾値は**約 24px** —
カードの 87px より小さく、フリック（100〜300px）はより確実に超える。同じ理由がより強く
当てはまるので、同じ 250ms を使う。

**掴めたことは持ち上げで必ず見せる。** 指が止まっていても掴めたと分かる必要があるのは
長押しの必須条件（あちらの ADR）。`.card` は静止時に枠があるので `border-color` を
`--accent` にするだけで済むが、「選択中」の行は枠を持たないので地色の変化だけでは弱い。
`outline`（`outline-offset: -1px`）で `--accent` の枠を足した。border ではないのは、
静止時に無い枠を足すと行が 2px 動くから。

### ✕ を掴み口の中に入れない

行が掴み口になると「外すつもりのタップでドラッグが始まる」が新しく生まれる。これを
`stop_propagation` で消して回る形にはしない — **✕ を `.rtn-grab` の兄弟に置けば
`pointerdown` がそもそもハンドルへ届かない**ので、構造で保証できる。`.card-head` に
削除ボタンが 1 つも無い（フッタへ畳んである）のと同じ形である。

掴み口を `<button>` にもしない。中身が `<span>` 2 つなので HTML としては可能だが、
行全体が押せるコントロールに見えると「押すと何が起きるのか」が嘘になる（起きるのは
長押しの並べ替えだけで、タップでは何も起きない）。キーボードからの並び替えは
`<li>` の `on:keydown`（Alt + ↑↓）が受ける。

### 番号は CSS の `counter()` では出せない

かつては `.rtn-picked li::before { content: counter(rtn) }` で描いていた。ドラッグ中は
`Vec` を入れ替えず `transform` だけで見せるので、**counter は DOM 順でしか数えられず、
「中点を越えた瞬間に番号が入れ替わる」を表現できない**。そのままだと 2 番目に見えている
行に「1」と書いてある状態になり、番号をハンドルにした前提（番号 ＝ 順番）が指を離すまで
嘘になる。記録タブのセット番号と同じくテキストで描き、`reorder::visual_index` を通した。

### `.rtn-picked` をキー付き `<For>` にする

素の `map` だと `picked` が動くたびに `<ol>` ごと作り直され、**ドラッグ中に DOM が
差し替わって pointer capture が落ちる**。同じ種目は 2 度入らない（`toggle` が push 前に
位置を見る。取り込んだデータも `core::normalize_routines` が重複を落とす）ので、
`ExerciseId` がそのままキーになる。

外側の「選択中があるか」も `Memo<bool>` にした。`picked.get()` を直に条件にすると、
種目を 1 つ足すたびに `<ol>` ごと作り直されてキーが効かなくなる。

### 重なり順は「保存帯が上、掴んだ行はその下」

`.rtn-save`（sticky）も `[data-drag="lift"]` も `z-index: 1` だったので、どちらが上かは
DOM 順という「たまたま」で決まっていた。`.rtn-save` を 2 にして意図を明示する。
**帯の下を通るのが正しい向き**なのは記録タブの `.add-wrap`（9）と `[data-drag="lift"]`（1）と
同じで、帯は常設のコントロール面である。下端へ運ぶ指は帯に届く前に端の自動スクロールの
帯（内側 72px）に入る。`styles.css` 冒頭の重なり順の一覧に、シートの中は `<dialog>` が作る
別の重なり文脈で外とは勝ち負けしないことを含めて追記した。

### ピッカーは複数開ける（設定タブとは別規則）

[種目タブを部位の折りたたみ一覧にし、1 つだけ開く](menu-groups-as-single-open-accordion.md)
の「1 つだけ開く」は**継がない**。あちらは種目マスタを 1 部位ずつ見に行く画面だが、
こちらは**メニューを 1 本組む間に胸と脚を行き来する**のが普通の使い方で、排他にすると
往復のたびに開き直すことになる。見た目とフック（`.grp-toggle` + `aria-expanded` で
シェブロンを回す。`<details>`/`<summary>` は使わない）はあちらに揃えた。

**`OpenGroupCtx` は使わない。** アプリ全体で 1 本の signal なので、ここで開いた部位が
設定タブの種目一覧にも漏れる（逆も同じ）。`RoutineEditor` ローカルの
`RwSignal<Vec<GroupId>>` に持つ。**`GroupBlock` 自体も再利用しない** — あれは
`views::settings` の private な `Editor` enum を prop に取っていて、部位を改名する鉛筆まで
一緒に付いてくる。メニューを組む画面に改名の入口は要らない。

**記録タブの「種目を追加」シート（`.sheet-group` のまま）には当てない。** あちらは
1 タップで 1 種目を出して閉じる画面で、往復しないので畳む理由が無い。
[記録タブのカードとセットをドラッグで並び替え](drag-to-reorder-in-record-tab.md) が
「『種目を追加』シートの並びには今も有効な案」として残した**直近順の自動並べ替え**も、
そちらの将来案として開いたままにしてある（この ADR は 1 文字も触っていない）。

### trash は削除だけ。「選択中」の ✕ は据え置く

[破壊的操作は静止時に警告色を持たない](destructive-affordance-quiet-at-rest.md) が
**グリフを揃えることを誤りとした**のと同じ判断が、ここでは逆向きに効く。
「選択中」の ✕ は**このメニューから外す**で種目そのものは 1 つも消えないので、trash に
すると押した人には種目を削除したように読める。逆に「このメニューを削除」は本当に
消えるので、アイコンで見つけられるべきである。trash の線色は `currentColor` なので、
この行の色（`.danger`）は 1 文字も変えていない。

lucide の `trash-2` を [アイコンに lucide を採る](../architecture/lucide-icons-as-included-svg.md)
の規則どおり（`viewBox` だけ残して属性を全部剥がす / `<?xml ?>`・DOCTYPE を書かない /
`role`・`aria-label` を付けない）追加し、**`assets/icons/LICENSE` と `index.html` の
ライセンスコメントの両方**を更新した。`trash-2` は上流の `icons/trash-2.json` の
contributors に `colebemis`（Feather の作者）が入っている ＝ Feather 由来なので、
ISC に加えて MIT の併記が要る。判別方法を LICENSE に書き足した。

## 結果（トレードオフ）

- **`views::day` から `views::drag` へ 12 個の項目が移った**（`Drag` / `Press` /
  `capture` / `blur_active` / `holds` / `release` / `alt_arrow` / `edge_scroll_tick` /
  `start_edge_scroll` / `end_press` / `PRESS` / `EDGE_SCROLLING`、加えて `views::mod` から
  `scroll_y` と `measure_slots`）。**3 つ目のハンドルが出た時点で、もう 1 実装書くか共有するかの
  二択だった**。`views::routine` がシートを 2 枚書かないのと同じ理由で共有を採った。
  `scroll_y` は `Scroller::Window.offset()` に吸収されて消えた
- **「選択中」の行からはシートの中をスクロールできなくなった**（`touch-action: none`）。
  **代償は記録タブより重い。** あちらの `.card-head` は 24px の帯が 5〜8 本で、間に
  スクロールできる領域がいくらでもある。こちらは 44px の行が縦に連なるので、10 種目の
  メニューを開くと `.sheet-body` の可視域（約 500px）のほぼ全部が「そこから指を滑らせても
  シートが動かない」帯になる。逃げ道は各行の右端の ✕（44px、`touch-action: manipulation`
  のまま）と、ピッカーや名前欄の側。**畳んだピッカーが効いているのはここでもある** —
  部位を閉じておけば「選択中」の下に必ずスクロールを始められる領域が残る。
  それでも「たまにスクロールが効かない帯がある」ほうが「気づかないうちにメニューの順が
  変わる」より明確にましだという `.card-head` の判断をそのまま採る
- **`reorder` に `edge_band` が 1 本増えた。** 容器が `2 * EDGE_BAND` = 144px より低いと
  上下の帯が重なり、`edge_scroll_step` は `client_y < top` を先に見るので**容器のどこに
  指を置いても上へスクロールし続ける**。ページ（約 760px）では起きないが、`.sheet-body` は
  `78vh` から見出しを引いた高さなので横向きや小さい端末で割りうる。
  [記録タブのカードとセットをドラッグで並び替え](drag-to-reorder-in-record-tab.md) が
  幾何を `reorder` に置いた理由（`views` はホストの `cargo test` が一度も触れない）が
  そのまま当てはまるので、`views` に書かず純関数にしてテストで固定した
- **ドラッグの代わりの `Alt` + ↑↓ も足した**（行の ✕ にフォーカスがあれば効く）。
  記録タブと同じ形で、WCAG 2.1.1 の非ドラッグ経路であると同時に E2E の座標に依存しない
  経路でもある。**2.5.7（ドラッグ操作）を満たすものではない**のも記録タブと同じ
- **長押しを入れたので `RoutineEditor` に `on_cleanup` が要るようになった。**
  このコンポーネントは**シートを閉じた瞬間に破棄される**（呼び出し側の signal が `None` に
  なると `Sheet` の中の `.map(..)` ごと消える）ので、待っている 250ms の間に閉じると
  タイマーだけが生き残り、破棄済みの signal を触って wasm が unreachable に落ちる。
  記録タブがタブ切替に対して同じことをしているのと同型で、`end_press()` と
  `EDGE_SCROLLING` を畳んでから消える。それでも**既にキューへ入った 1 発は止められない**
  ので、`arm` 側も `try_with_untracked` / `try_set` で受け止める（両方要る）
- **既定で全部閉じたぶん、既存メニューを編集するときに「どれが選ばれているか」が
  ピッカー側（`.pick.added`）からは読めなくなった。** 代わりに「選択中」が全部を名前で
  並べているので情報は失われていない。むしろ画面を開いた瞬間にそれが見えるようになった
- **シートを開き直したときに中身が先頭へ戻るようになった（シート 5 枚すべて）。**
  `<dialog>` は常時マウントなので `.sheet-body` の DOM 要素は閉じても生き続け、
  `scrollTop` を覚えたままになる。実測（Playwright / iPhone 15 Pro）で、メニュー編集
  シートを一度閉じて開き直すと `scrollTop` が 446 のまま ＝ **見出しも名前欄も画面外**で
  現れた（Chromium は中身が空になる 1 tick で 0 に潰れるので出ない）。**この ADR が
  作った不具合ではない**が、長いシートほど強く出るので、ここが一番長い画面になった
  今のうちに `views::Sheet` 側で塞いだ
- **E2E が 9 本増えた。** ドラッグは `page.mouse` で出す（合成 `dispatchEvent` では
  `setPointerCapture` が `NotFoundError` になり、実装が意図どおり「掴まない」ので
  検証にならない）。既存の `routine-pick` を押すテスト 4 か所は、部位を開いてから押す形に
  直した（`openAllPickGroups`）
- **長押しの E2E が固定できるのは「待ちがあること」までで、その長さではない。**
  実測（Chromium）で `PRESS_DELAY_CARD` を 0ms に落としてもフリックのテストは緑のまま
  だった — `mouse.move(steps: 8)` の合成入力が 0ms の `setTimeout` より先に処理される
  ため。落ちるのは待ちを丸ごと外して `pointerdown` で同期に掴む形にしたときで、そこは
  確認済み（現実的な退行はこちら）。**250ms が妥当かは実機でしか見られない。**
  加えてフリックのテストには「同じ座標で待てば掴める」を必ず添える — これが無いと
  掴めない場所を押していただけでも緑になり、テストが黙って空振りする
- **タッチ操作そのものは E2E で検証できていない。** `touch-action` の効き・慣性スクロール・
  ソフトキーボードは Playwright では再現しない。393×760 の実機形状で目視確認した

## 検討した代替案

**「選択中」に ↑↓ ボタンを置く**: E2E が確実に書けて iOS の実装リスクがゼロ。しかし
[種目タブを部位の折りたたみ一覧にし、1 つだけ開く](menu-groups-as-single-open-accordion.md)
が却下した理由（44px のボタンが一覧の役目を潰す）がそのまま効く。行は 番号 / 名前 / ✕ の
3 要素で 393px に収まっているが、2 個足すと長い種目名（「インクラインベンチプレス」）が
折り返す。しかも記録タブには既にドラッグがあるので、**同じアプリの中で並び替えの操作が
2 種類**になる。却下。

**番号（`.rtn-no`）だけをハンドルにする**: `touch-action: none` の帯が 16px で済み、
「選択中」の行のどこからでもシートをスクロールできる。長押しも要らないので、掴んでから
動かすまでの待ちがゼロになる。**当初はこれを採用していた**（`.set-no` と同じ扱い）。
却下したのは、**記録タブではカードの帯を掴むのに、メニュー編集では 16px の的を狙うことに
なり、同じアプリの中で操作感が食い違う**から。`.set-no` が番号だけで正しいのは行の中に
入力欄が 3 つあってそこしか空いていないからで、「選択中」の行にその事情は無い。
帯からスクロールできなくなる代償は、畳んだピッカーが残す領域と行右端の ✕ で受ける。

**✕ も掴み口の中に入れ、`stop_propagation` で外す**: 掴める面積が 44px 広がる。しかし
「押すと外れるボタン」と「押し続けると掴めるハンドル」が同じ矩形に重なるので、
`pointerdown` を止め忘れた経路が 1 つでもあると**外すつもりのタップでドラッグが始まる**。
兄弟に置けば構造的に起きない。44px は既に十分な標的なので、面積のために壊れうる形を
採る理由が無い。却下。

**`OpenGroupCtx` を共有して「1 つだけ開く」に揃える**: 規則が 1 つで済み、signal も増えない。
しかしアプリ全体で 1 本なので、**メニューを組むために開いた胸が設定タブの種目一覧でも
開きっぱなしになる**（逆も同じ）。加えて排他だと、胸と脚を行き来するたびに開き直す。
一貫性より、この画面での使い方を採る。却下。

**`views::settings` の `GroupBlock` をそのまま使う**: 実装がゼロで済む。しかし
`Editor` enum（private）を prop に取っており、部位を改名する鉛筆と「＋ 種目を追加」が
一緒に付いてくる。メニューを組む画面にマスタ編集の入口を出すと、シートの中からさらに
シートを開くことになる。却下。

**ピッカーを「直近に記録した順」で自動的に並べる**:
[記録タブのカードとセットをドラッグで並び替え](drag-to-reorder-in-record-tab.md) が
「『種目を追加』シートの並びには今も有効な案」として残した案で、こちらにも当てはまる。
しかし**部位の色と名前という既にある構造を捨てる**ことになり、「胸の日」を組むときに
胸の種目がどこにあるか探すことになる。折りたたみは構造を残したまま縦を畳むので、
まずこちらを入れた。**この案は今も却下していない**（あちらのシートと合わせて別途）。

**`Scroller` を prop で渡す**: 依存が型に出て、DOM のクラス名（`.sheet-body`）に
依存しなくなる。しかし `RoutineEditor` は入口が 2 つあり、**片方だけ間違った id を
渡しても静止した容器では症状が出ない**（定数のズレは `measure_slots` と `advance` の
両方に同じだけ乗って打ち消し合う）。スクロールして初めて壊れる配線は、配線しないほうが
よい。却下。

**`trash` ではなく `trash-2` を使わない**: 収録が 1 枚減る。しかし plain な `trash` は
20px に縮めると縦線が無いぶん筒に見え、同じ画面にある `.dot`（部位の丸）と線の密度が
揃わない。どちらも Feather 由来で表記の手間は同じなので、読めるほうを採った。
