# コピーは種目メモとセットメモを持ち込む（体調メモと体重は持ち込まない）

- **状態**: 採用
- **日付**: 2026-08-19
- **カテゴリ**: ux
- **関連**: [種目メモとセットメモを `ExerciseLog` / `SetEntry` に持たせ、空のメモは書き出さない](../data-model/notes-on-logs-and-sets.md)（決定 7 を改訂）, [メモは種目カードのトグル 1 つで開き、閉じても薄字で残す](exercise-and-set-notes-behind-one-toggle.md)（決定 5 のコピー規則を改訂）, [「前回をコピー」はセットが空のときだけ出す](copy-button-only-when-empty.md), [1 日分のメニューは候補リストから 1 タップで丸ごとコピーする](copy-whole-day-menu.md), [保存したメニューから始める（種目タブを設定タブに改める）](start-from-a-saved-routine.md), [セット追加は直前行の重量をコピーして回数欄へフォーカスする](set-entry-prefill-and-focus.md)

## 背景

[種目メモとセットメモを `ExerciseLog` / `SetEntry` に持たせ、空のメモは書き出さない](../data-model/notes-on-logs-and-sets.md) の決定 7 は、コピーからメモを外した。理由は「重量は**次のセットの計画値**、メモは**そのセットで起きたことの観測値**。複製すると起きていない観測が翌日に生える」。

**論として間違っていない。間違っていたのは、種目メモに何が書かれるかの予測である。**

実使用で種目メモに入ったのは観測ではなく**セッティング**だった。「セーフティ 2 穴目」「グリップ広め」「シート 4」— どれも器具の設定で、次に同じ種目をやるときに**必ずもう一度必要になる**情報である。それが毎回消えるので、毎回打ち直すか、打ち直さずに記憶に頼ることになった。

製品方針は「筋トレ中に追加するので最短距離で」。**毎回消えるメモは、書かれなくなる。** 書かれなくなったメモ欄は無いのと同じである。

## 決定

### 1. コピーの 3 経路はすべて、種目メモとセットメモを運ぶ

`core::copy_day`（1 日分）/ `core::apply_routine`（保存したメニュー）/ `views::day` の `copy_last`（カードの「前回をコピー」）。

`core` の 2 経路は `Seed::carry` の 1 箇所を共有する。決定 7 の実装が `sets_without_notes` の 1 箇所だったのと同じ形で、**畳む対象が「落とす規則」から「運ぶ規則」に反転しただけ**である。

**`copy_last` だけは別実装になる。** あちらは `Db` ではなく UI の `Row`（入力欄の文字列）を作るので、`Seed`（`Vec<SetEntry>` を持つ）を受け取っても結局フィールドごとに書き写すことになる。**「1 箇所」と言えるのは core の 2 経路までで、3 経路が同じものを運ぶことはコンパイラではなく E2E 3 本（`copy-last` / `menu-candidate` / `routine-candidate` にそれぞれ 1 本）が守っている。** 運ぶものを変えるときは 3 本とも直すこと。

### 2. `+ セット`（`add_row`）は引き続き運ばない

**あれはコピーではない。** 作るのは**まだ起きていない次のセット**で、重量はその計画値だが、書くべき観測はまだ存在しない。決定 7 の論はこちらには**そのまま当たり続ける**。

線は「計画値か観測値か」ではなく、**「過去のログを再現するか、次の 1 本を作るか」**で引き直した。

### 3. 体調メモ（`Session.note`）と体重は引き続き運ばない

非対称は意図である。「よく寝た」はその**日**に閉じた観測で、種目に紐付かない。日単位のものは日単位に留まる。[1 日分のメニューは候補リストから 1 タップで丸ごとコピーする](copy-whole-day-menu.md) の「なぜ体重・体調メモを複製しないのか」はそのまま生きている。

`copy_day_copies_the_exercise_note_and_the_set_notes` が両側を 1 本で固定している（種目メモ・セットメモは運び、体重・体調メモは運ばない）。

### 4. コピーは、既に何か書いてある場所には書かない

3 経路に共通の 1 文である。

- `copy_day` / `apply_routine`: `seed_day` の `has_logs_on(db, to)` ガードで、**ログのある日には 1 バイトも書かない**（従来どおり）
- `copy_last`: 今日の種目メモが空のときだけ前回のものを入れる。**フィールド単位で同じことを言っている**

**セット行のメモにも同じ規則が要る。** ボタンが見るのは「**保存済みの**セットが空か」なので、回数の無い行に書いたメモは保存されておらず画面にだけある状態で押せる。しかもその行には `note_orphan` が「回数を入れると保存されます」と出ていて、打った文字が生きていることを約束している。**数値は置き換え、メモは位置で残す** — 数値を前回どおりに流し込むのがこのボタンの目的そのものだが、メモは打ち直しの手が重く、約束もしている。

`copy_last` を条件付きにするのは、ボタンの表示条件（`show_copy`）が「今日のセットが空か」しか見ないため、**「メモだけ書いたカード」でも押せる**からである。上書きすると undo の無い破壊が最頻の場所に生まれ、[「前回をコピー」はセットが空のときだけ出す](copy-button-only-when-empty.md) が消したはずの 3 つの問題（置換か追記か / 誤タップ事故 / undo の必要性）が種目メモという別の入口から戻る。

回復手段も同 ADR と同じ形で残る（セット行を全部消せばボタンが戻る）。

### 5. メモ欄は自動で開かない

[メモは種目カードのトグル 1 つで開き、閉じても薄字で残す](exercise-and-set-notes-behind-one-toggle.md) の決定 2（既定は常に閉）と決定 3（閉じていても薄字で読める）をそのまま適用する。コピーしたメモはその場で薄字として読めるので、開く必要が無い。

開くと 3 セットで約 200px カードが伸びる。しかもそれが起きるのは「これから数値を打ち込む」直前で、決定 2 が守っている当のものである。

### 6. `at` は引き続き運ばない。`seed_day` の引数を `at` を持たない型にする

`Seed` は `exercise_id` / `sets` / `note` だけを持つ。`ExerciseLog` をそのまま渡すと元の日の `at` が付いてくる（[`at` を `Option<i64>` にし当日入力時のみ埋める](../data-model/at-optional-same-day-only.md)）ので、**「持ち込まない」を呼び出し側の注意力ではなくフィールドの不在で守る**。

従来の引数 `Vec<(ExerciseId, Vec<SetEntry>)>` にも `at` は入っていなかったので、**「`at` が無い」こと自体は新しくない**。変えたのは 2 つ。運ぶものが 3 つになると 3 つ組では「3 番目が種目メモ」が型から読めないこと、そして `carry` を分解代入（`let ExerciseLog { .. } = src`）で書いたので、**`ExerciseLog` にフィールドが増えた瞬間にここがコンパイルエラーになる**こと。運ぶ / 運ばないの判断を、決定が書いてある場所で必ず 1 回通す。

### 7. 「セットが 1 本も読めなかった TSV」の検知を、メモが生き残っても効くようにする

`parse_tsv` は回数を読む**前に**ログを push して `append_note` するので、種目メモの列に値があると**回数が全滅してもログがメモで生き残る**。`dedupe_logs` は「セットもメモも無い」ログしか落とさないので `out.sessions` が非空になり、`ImportError::Unreadable` の判定（`sessions.is_empty()` を見る）を素通りしていた。

**決定 1 によってこれが例外ではなく既定の形になる**（全記録日に種目メモが載る）ので、同時に塞ぐ。既存の条件式は書き換えず、`unread > 0 && セットが 1 本も無い` の枝を手前に足す。書き換えて条件を緩めると、**体重・体調メモだけの正当なファイル**（`unread == 0`）が `NoRecords` になる。

## 理由

### なぜ「観測値の複製」という懸念を受け入れるのか

**懸念は正しい。だが量が違った。**

「肩に違和感」が翌日に生えるのは実際に起きうる害である。しかし 3 経路のどれも**空の日 / 空のカードにしか流し込まない**ので、生えたメモは必ず**利用者がその場で見ている画面**に、薄字で、そのカードの中に出る。消すのはトグル 1 タップである。

対して「セーフティ 2 穴目」が毎回消えるのは、**消えたことに気づく手掛かりが画面に一切無い**。

**気づける害と気づけない害を同じ重みで扱っていたのが誤りだった。**

加えて、コピーは既に**セットの数値**という観測値を運んでいる。「前回 60kg×10 だった」も観測で、それを今日の入力欄に置くのは「今日 60×10 やる予定」への読み替えである。メモだけを観測値として除外していたのは首尾一貫していなかった。

### なぜ `append_note` を使わないのか

`core::append_note` は取り込みの**マージ**規則（部分一致で冪等に足す）であって、コピーの規則ではない。

流用すると 2 つ壊れる。**`\n` 区切りで足した結果が単一行 `<input>` の value sanitization に落ちて `"AB"` になり、次の 1 打鍵で利用者のメモが黙って壊れる**（[メモは種目カードのトグル 1 つで開き、閉じても薄字で残す](exercise-and-set-notes-behind-one-toggle.md) が `textarea` を却下しているので、単一行であることは動かせない）。もう 1 つは、部分一致ガードのせいで「軽め」が「今日は軽め」に含まれると足されない、というコピーとしては説明できない挙動になること。

### なぜ `copy_last` だけ DOM を直接触るのか

種目メモの入力欄は開いている枝が `value=ex_note.get_untracked()` で、あの閉包が追跡するのは `note_open` だけである。つまり **`ex_note` を書いても、開いている入力欄は古いまま残る**。その状態で 1 文字打つと `on:input` が DOM 側の古い値で上書きし、コピーしたメモが黙って消える。

セット行が同じ問題を起こさないのは、`copy_last` が新しい `Row.key` を振って `<For>` に DOM を作り直させているためで、**種目メモだけがキーを持たないので取り残される**。`NodeRef` で DOM も直す（`reps_ref` / `file_ref` と同じ作法）。

`value=` を reactive にする案は `<input>` の dirty value flag のせいで属性更新が反映されず、`prop:value` は IME の変換中にカーソルが飛ぶので採らない。

## 結果（トレードオフ）

**やっていない観測が翌日に生えうる。** 「3 セット目で肩に違和感」がコピーされる。薄字で見えるので気づけるが、消すのは利用者の仕事である。

**コピーの誤タップ後、セット行を全部消してもログがメモで残る。** その日は `has_logs_on` が true のままなので候補リストが戻らず、回復に「この日から外す」（確認ダイアログ付き）が要る。[メモは種目カードのトグル 1 つで開き、閉じても薄字で残す](exercise-and-set-notes-behind-one-toggle.md) の決定 5（セット 0 本でもメモだけのログは残す）の帰結で、コピーが到達経路を 1 つ増やしただけである。**回復は可能**なので仕様は変えない。

ただし**時刻は落とす**。セットを打った時点で `at` が押されるので、行を全部消すと「書いた時点の時刻」がメモだけのログに居座り、`export_tsv` がセット無しの行に実施時刻を書く。[`at` を `Option<i64>` にし当日入力時のみ埋める](../data-model/at-optional-same-day-only.md) の「メモだけのログに時刻を持たせない」に反するので、`write_log` はセットが空になったら `at` を `None` に戻す。旧実装ではログごと刈られていたので届かなかった経路で、コピーがメモを運ぶようになって初めて実際に踏めるようになった。

**「セットは打たずにメモだけ直した日」のセッティングは、次のコピーで古いものに戻る。** `copyable` と `last_log_before` はどちらも `!sets.is_empty()` で絞るので、メモだけのログはコピー元にならない。8/1 に「2 穴目」、8/5 にピンを動かして「3 穴目」と書いたがセットは打たなかった場合、8/8 のコピーは 8/1 の「2 穴目」を運ぶ。`.last-row` は数値しか描かないので、押す前にどちらが来るかを見る手段も無い。

**これは意図した選択である。** 種目メモだけ別の日から引けば最新のセッティングが来るが、**数値とメモが別の日から来る**ことになり、「運ばれたメモは必ず運ばれた数値と同じログのもの」という読み方が崩れる。メニュー展開が種目ごとに別の日から引くこと（決定 1）と合わせると、1 枚のカードの中に 3 つの日付が混ざりうる。1 つのログを丸ごと再現するほうを採る。

**メモが日をまたいで無期限に伝播する。** `copyable` / `last_log_before` はコピーで生えたログを区別せず、`recent_menus` は種目集合で重複排除するのでコピー先だけが候補に出る。1 月に書いた「セーフティ 2 穴目」が以降の全ての日に乗り続ける。`.last-row` は数値しか描かないので**押す前にどんなメモが来るかを見る手段が無い**。

**`merge_db` の位置埋めが混ざりやすくなる。** `core::same_sets` は重量・回数だけを位置で見るので、`[60×10, 60×10, 60×10]` のような全セット同値の日を片方の端末で並べ替えると、3 本のセットメモが互いに混ざる。手打ちでも再現するが、コピーがこの形を既定にする。

**セットが食い違ったとき、負けた側のセットメモが全損する。** [種目メモとセットメモを `ExerciseLog` / `SetEntry` に持たせ、空のメモは書き出さない](../data-model/notes-on-logs-and-sets.md) に明記済みの仕様だが、コピー前は複製日にセットメモが 0 本だったので失うものが無かった。

**`MergeReport::notes_added` が膨らむ。** 1 日コピーあたり最大 20（種目メモ 5 + セットメモ 15）。1 か月ぶんを別端末に取り込むと数百件になる。冪等性そのものは `append_note` の部分一致ガードが守るが、`is_noop` が偽になる頻度が上がる。

**`append_note` の部分一致ガードは方向で結果が変わる。** dst が短いと弾けないので、「軽め」（コピー由来）に「軽め 肩は平気」を取り込むと `"軽め\n軽め 肩は平気"` になる。逆向きは弾かれる。冪等ではある。

**保存 JSON が最大で倍増する。** 5 種目 × 3 セットに 8〜10 文字のメモを付けた 1 日で約 700 B → 約 1,400 B。`storage.rs` の `PRE_KEEP = 3` で本体 + 3 世代 = 最大 4 倍になるので、[localStorage の単一キーに JSON 全体を持つ](../storage/localstorage-single-key-json.md) の「10 年で約 1.24 MB」という見積りに直接効く。`skip_serializing_if` があるので**払うのは書いた人だけ**だが、超過時は `SAVE_FAILED` が `visibilitychange` の visible でしか出ない。見積りの更新は別途。

**「今日のメモを書いてから前回をコピー」の順で操作すると、セッティングは二度と来ない。** ガードが見るのは `ex_note` なのに、ボタンの表示条件が見るのはセットなので、**セット行を全部消してボタンを出し直しても効かない**（[「前回をコピー」はセットが空のときだけ出す](copy-button-only-when-empty.md) の回復経路はセットにしか効かない）。取り戻すには自分のメモを一度空にしてから押すしかなく、その手順は画面のどこにも出ていない。1 日分コピーの側も、メモがあると `has_logs_on` が true なので候補が出ない。

決定 4（既に書いてある場所には書かない）を選んだ以上、この行き止まりは避けられない。逆にすると今日書いたメモを undo 無しで壊すほうを選ぶことになる。**「壊さない」を優先した結果**として受け入れる。

**`+ セット` とコピーで挙動が違う。** 「メモが引き継がれるときと引き継がれないときがある」ように見える。線は決定 2 のとおり「過去のログを再現するか / 次の 1 本を作るか」で引いてある。

**種目メモが実質「種目マスタの注記」として使われ始める可能性がある。** [種目メモとセットメモを `ExerciseLog` / `SetEntry` に持たせ、空のメモは書き出さない](../data-model/notes-on-logs-and-sets.md) の決定 1 は `Exercise` にメモを置かないと決めた（毎日同じ注記が出て「今日どうだったか」が書けなくなる）。コピーで持ち越すのは、その一歩手前まで寄る。**それでも `Exercise` には置かない** — 持ち越されたメモは今日のログに属する独立した文字列で、上書きも削除も今日の中で閉じ、過去に遡って変わることがない。

## 検討した代替案

**セットメモだけ運び、種目メモは運ばない**: セッティングの置き場所は種目メモなので、実害のほうが丸ごと残る。却下。

**種目メモだけ運び、セットメモは運ばない**: 「1 セット目 アップ / 2 セット目 メイン」のような**セットの役割**もセットメモに入る。線を引く根拠が説明できない。却下。

**体調メモも運ぶ**: 「よく寝た」「腰が重い」はその日にしか当たらない。日単位のものを日単位に留める規則（決定 3）を崩す理由が無い。却下。

**`copy_last` で `append_note` して追記する**: 単一行 `<input>` が `\n` を落として次の打鍵でメモが壊れる。マージの規則をコピーに流用しない。却下。

**`copy_last` で常に上書きする**: undo の無い破壊を最頻の場所に置く。却下。

**コピーしたメモに印を付ける（「（前回）」を前置するなど）**: 出所は分かるが、利用者の文字列に勝手な文字が混ざる。TSV の書き出しにも載り、取り込みで `append_note` の部分一致判定を壊す。却下。

**コピー時にメモ欄を自動で開く**: 3 セットでカードが約 200px 伸びる。閉じていても薄字で読めるので開く必要が無い（決定 5）。却下。

**`seed_day` に `ExerciseLog` をそのまま渡す**: `at` を持ち込む口ができる。`Seed` が `at` を持たないこと自体を保証にする（決定 6）。却下。

**コピーで入ったメモは、セットが 0 本になったら一緒に落とす**: 誤タップの回復が 1 タップのままになるが、「コピー由来か自分で書いたか」を覚える状態が増え、[メモは種目カードのトグル 1 つで開き、閉じても薄字で残す](exercise-and-set-notes-behind-one-toggle.md) の決定 5（メモだけのログは残す）と衝突する。回復は可能なので却下。
