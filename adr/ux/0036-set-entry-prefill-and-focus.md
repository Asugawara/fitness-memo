# ADR-0036: セット追加は直前行の重量をコピーして回数欄へフォーカスする

- **状態**: 採用
- **日付**: 2026-08-08
- **カテゴリ**: ux
- **関連**: [ADR-0019](../pwa/0019-hide-tabs-when-keyboard-open.md), [ADR-0021](0021-copy-button-only-when-empty.md), [ADR-0023](0023-text-input-not-number.md)

## 背景

セット入力は「+ セット」で空行が増えるだけだった。実使用のフィードバックは **「セットの追加時に毎回埋める枠を押す必要がある」**。

実際の手数を数えると、1 セットあたり:

1. 「+ セット」を押す
2. 重量欄をタップ
3. 重量を打つ
4. 回数欄をタップ
5. 回数を打つ

セットは 60×10 / 60×8 / 60×6 のように **重量を据え置いて回数だけ変える**のが普通なので、2〜3 は毎回同じ値を打ち直していることになる。トレ中に息が上がった状態でやる操作としては重い。

## 決定

**「+ セット」で新しい行に直前行の重量をコピーし、回数欄へフォーカスを移す。**

```rust
let add_row = move |_| {
    let key = fresh_key();
    let weight = rows.with_untracked(|rs| rs.last().map(|r| r.weight.clone()).unwrap_or_default());
    rows.update(|rs| rs.push(Row { key, weight, reps: String::new() }));
    focus_key.set(Some(key));
};
```

フォーカスは `<For>` の children 内で回数入力に `NodeRef` を張り、`focus_key` を購読する `Effect` から `.focus()` を呼ぶ。発火後 `focus_key` は `None` に戻す。

残るのは **回数を打つ 1 手だけ**。

## 理由

**プリフィルとフォーカスは別々の効果を持ち、両方要る。** プリフィルだけだと回数欄をタップする 1 手が残る。フォーカスだけだと重量を打ち直す 2 手が残る。

**フォーカスが効かなくてもプリフィルが残る。** これが設計上の要点（下記）。

## iOS の制約

**`focus()` はユーザー操作起点のタスク内でしかキーボードを開かない。** `set_timeout` を挟むとユーザー活性化が切れて開かなくなるので、`Effect`（マイクロタスク）で完結させる。`Effect` が `Executor::spawn_local` で駆動されることは `reactive_graph-0.2.14` のソースで確認した。

ただし **standalone PWA で実際にキーボードが開くかは実機でしか確認できない**（DevTools でも Playwright でも再現しない領域は [ADR-0019](../pwa/0019-hide-tabs-when-keyboard-open.md) で既に踏んでいる）。

そのため **重量プリフィルをフォールバックとして機能する設計**にしてある。キーボードが開かなくても、ユーザーは回数欄を 1 回タップするだけで済み、退行しても「元の 5 手」には戻らない。

## `HtmlElement` の feature 宣言

`.focus()` は `web_sys::HtmlElement` のメソッドなので `Cargo.toml` の features に `HtmlElement` を追加した。同ファイルの規約どおり、tachys 経由で偶然有効になっている feature に寄りかからない（leptos のパッチ更新で無言に壊れる）。

## 結果（トレードオフ）

**重量だけ入った空行ができる。** `parse_reps` が空欄に `None` を返すので保存されず（[ADR-0023](0023-text-input-not-number.md)）、ゴーストセットにはならない。「+ セット」を押したまま何も打たずに離れても記録は汚れない。

**削除の判定に影響する。** 重量プリフィル済みで回数が空の行は「中身なし」として扱い、削除確認を挟まずに消す。プリフィルされた値をユーザーが打ったものと同一視すると、確認ダイアログが無駄に出る。

**「前回をコピー」との役割分担。** [ADR-0021](0021-copy-button-only-when-empty.md) の「前回をコピー」は**セットが空のときだけ**出る別の機能（前回のセット構成をまるごと再現する）。こちらは**入力中に 1 行ずつ足す**ときの話で、競合しない。

## 検討した代替案

**「+ セット」を廃止し、最終行が埋まったら自動で空行を足す。** ボタンを押す手数も消えるが、行が勝手に増える挙動は「まだ入力途中なのに次の行が生えた」と読める。明示的な追加操作は残したほうが構造が分かりやすい。

**自動フォーカスのみでプリフィルしない。** 重量を毎回打ち直すことになり、一番削りたかった手数が残る。

**重量欄にフォーカスする。** 変えるのは回数なので、重量欄に入ると「消してから打ち直す」操作を誘発する。
