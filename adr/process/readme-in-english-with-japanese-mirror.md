# README を英語で正とし、日本語版を `README.ja.md` に置く

- **状態**: 採用
- **日付**: 2026-08-19
- **カテゴリ**: process
- **関連**: [ADR を `adr/` にカテゴリ別で置く](adr-in-adr-directory.md), [静的メタデータを英語に統一し、`<html lang>` は実行時に切り替える](../seo/static-metadata-in-english.md), [GitHub の Social preview 画像を `assets/` に生成し、アップロードは手作業と割り切る](../seo/github-social-preview-image.md), [CI を `.githooks/pre-commit` で回す](../deploy/ci-in-pre-commit.md)

## 背景

README は 143 行すべて日本語だった。公開先は GitHub Pages で、リポジトリも公開されている。
アプリ本体を日英対応させ、静的メタデータも英語に統一したので、
**リポジトリを開いた英語話者が最初に読むもの**を決める必要がある。

ADR は 72 本すべて日本語で、README の本文からは相対リンクが 13 本刺さっている。

## 決定

**`README.md` を英語にし、日本語版を `README.ja.md` として残す。**

- `README.md` = 英語 = 正の入口。GitHub がリポジトリのトップに描くのはこちら
- `README.ja.md` = 同じ骨格の日本語版
- **両者はセクション構成を一致させ、同じコミットで直す**
- 両方の冒頭に中央寄せのロゴと、相手側への言語リンクを置く
- **ADR とコミットメッセージとコード内コメントは日本語のまま**
- 英語版の「Design decisions」に、ADR が日本語であることを `[!NOTE]` で明示する

移行は `git mv README.md README.ja.md` を**単独のコミット**にしてから英語版を書く。

## 理由

- **GitHub のトップに出るのは `README.md` だけ。** 日本語を正のままにして
  `README.en.md` を足す形だと、英語話者が最初に見る画面が日本語のままになり、
  「英語圏の入口を作る」という目的を果たさない。ファイル名の選択がそのまま目的の達成条件になる。
- **骨格を揃えると節単位で差分が取れる。** 片方を直した人が対応箇所を 2 秒で見つけられる。
  構成が分岐すると必ずドリフトし、しかも**本体の内容が生きている日本語側のドリフトのほうが害が大きい。**
- **リネームを単独のコミットにする。** 143 行の散文の blame 履歴が、
  英語版を書くコミットの巨大な差分に埋もれるのを避ける。
- **ADR は英訳しない。** ADR はほぼ毎回の変更で追記される作業文書で、README は
  数回の変更に 1 回しか触らない。**更新頻度が一桁違うものを 2 言語で維持すると、
  翻訳の陳腐化が「判断の記録」に及ぶ。** 記録としての信頼性を失うほうが、
  英語話者が読めないことより悪い。事実として明示し、言い訳しない。
- **英語版に 1 セクションだけ足した**（`Icons and share images`）。日本語版が
  「画面」節に押し込んでいたアイコン再生成の手順を独立させ、
  [GitHub の Social preview 画像を `assets/` に生成し、アップロードは手作業と割り切る](../seo/github-social-preview-image.md) の
  手作業ステップの置き場にした。日本語版にも同じ節を作って構成を揃えている。
- **翻訳のついでに日本語を「改善」しない。** 同じ PR で両方を書き直すと差分がレビュー不能になる。
  日本語側の変更は、構成を揃えるための移動と、新しい事実（言語切替・TSV の列名・
  種目名が変わらないこと）の追記だけに限った。

## 結果（トレードオフ）

- **2 文書が必ずドリフトする。** 機械的な担保は無く、レビュー規律だけが頼り。
  片方だけ直したコミットは何のエラーも出さずに通る。
- **英語話者は ADR を読めない。** README の本文から 13 本のリンクが刺さっているので、
  クリックした先で行き止まりになる。`[!NOTE]` で先に伝えているが、解決はしていない。
- **スクリーンショットは日本語 UI のまま。** `scripts/shots.mjs` が `locale: 'ja-JP'` を
  固定しており（seed が日本語の種目名を引くので外すと撮影が落ちる）、英語版 README にも
  日本語の画面が載る。英語で撮り直すには seed の翻訳が要る。README に注記してある。
- **リポジトリの言語統計に影響しない**（Markdown は数えられない）が、
  ファイルが 1 つ増えたぶん、ルート直下の見通しは少し悪くなった。

## 検討した代替案

**`.githooks/pre-commit` に「片方だけ変わっていたら止める」ガードを足す**:
[CI を `.githooks/pre-commit` で回す](../deploy/ci-in-pre-commit.md) が唯一の防波堤である以上、
発想としては正しい。しかし typo 修正や英語だけの言い回し調整のような
**片側だけが正しい変更で誤検知する**ので、`SKIP_HOOKS=1` の常用を招く。
一度そうなると他の検査もまとめて飛ぶので、防波堤そのものが弱くなる。
**却下、ただし「止める」ではなく「警告を表示するだけ」なら再検討してよい。**

**日本語を正のまま英語版を `README.en.md` にする**: 既存のリンクや blame が一切動かない。
しかし GitHub のデフォルト表示が日本語のままで、英語圏の入口という目的を果たさない。却下。

**英語 1 本にして日本語を捨てる**: 維持するものが 1 つになり、ドリフトが原理的に起きない。
しかし作者自身の作業文書を失う。ADR が日本語である以上、README だけ英語にしても
日本語の文脈は残り続けるので、捨てる意味も薄い。却下。

**ADR も英訳する**: 英語話者がリンク先まで読める。しかし 72 本 + 毎回の追記を
2 言語で維持することになり、必ず片方が古くなる。**古い ADR は無い ADR より悪い**
（決定の理由を誤って伝える）。却下。
