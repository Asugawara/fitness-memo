# 「前回をコピー」はセットが空のときだけ出す

- **状態**: 採用
- **日付**: 2026-08-08
- **カテゴリ**: ux
- **関連**: 表記と件数は [前回までの記録を日付で出し、何回分出すかを表示設定にする](past-records-by-date-with-a-count-setting.md)（本 ADR の「前回 —」を改訂。コピーの挙動は据え置き） / 日単位のコピーは [1 日分のメニューは候補リストから 1 タップで丸ごとコピーする](copy-whole-day-menu.md)（本 ADR の「空のときだけ出す」判断をそのまま日単位へ広げている） / [コピーは種目メモとセットメモを持ち込む（体調メモと体重は持ち込まない）](copy-carries-the-notes.md)（メモも運ぶようになった。「空のときだけ」はフィールド単位にも降りた） / [チップでラベルを選ぶと履歴とコピーが切り替わる](label-chips-switch-the-history-and-the-copy.md)（3 問題が「フォールバックしない」根拠になった）

## 背景

要件は「前回のレップ数、セット数を簡単に参照できて、コピーもできる」。この「コピー」は **「前回セットをプリフィル」のみ**と定義する（1 セットずつ複製、テキストでクリップボードへ、は含めない）。

当初の設計は種目カードに「前回をコピー」ボタンを常時表示するものだった。しかしこれには未定義の挙動が複数残っていた。

- 既に 2 セット入力した後に誤タップしたら、**置換**なのか**追記**なのか
- 置換なら入力済みデータが消える（undo なし）
- 追記なら重複行ができる
- 前回が存在しない初回のボタンをどう扱うか

## 決定

**「前回をコピー」ボタンは、その種目の今日のセットが空のときだけ表示する。**

前回が存在しない場合は「前回 —」と表示してボタンを出さない。

> **→ 表記を [前回までの記録を日付で出し、何回分出すかを表示設定にする](past-records-by-date-with-a-count-setting.md) で改訂。**
> 記録は日付（`8/20 (水)`）で出し、無いときは「記録なし」になった。**ボタンの出し方は変えていない**
> — 表示件数がいくつでも、コピーするのは先頭 1 件（＝ここで言う「前回」）だけである。

## 理由

表示条件を「セットが空のとき」に限ると、3 つの問題が同時に消える。

1. **置換か追記かの曖昧さが消える。** 空にしか出ないので常に「流し込む」で一意
2. **誤タップで入力済みセットを消す事故が起きない。** 消すものが無い
3. **undo が不要になる。** 破壊的な操作が存在しない

そのうえで UI 要素が 1 つ減るので、要件が唯一デザインについて指定した「非常にシンプル」にも寄る。

利用実態とも合っている。「前回をコピー」を押すのは種目カードを追加した直後であり、セットを打ち込んだ後に押したい場面はない。

## 結果（トレードオフ）

- 「入力し始めたけどやっぱり前回どおりにしたい」場合はボタンが出ない。セット行を全部消せば再び出るので、回復手段はある。
- ボタンの表示・非表示が切り替わるので、E2E で両状態を検証する（smoke 5: 空のときプリフィルされる / セットが入っているとボタンが出ない）。
- 「前回」の定義は `last_log_before(db, ex, before)` で「指定日より**厳密に**前で最も新しい記録」とした。今日の入力中も、過去日を編集中も、正しく前回を指す。

## 検討した代替案

**常時表示 + 確認ダイアログ**: 誤タップ事故は防げるが、最頻の操作に確認を挟むのは煩わしく、「非常にシンプル」に反する。却下。

**常時表示 + 追記**: 破壊はしないが重複行ができ、結局ユーザーが消す手間が増える。却下。

**1 セットずつ複製する「+」ボタン**: 同じ重量で回数だけ変えるときに速い。「コピー」の定義に含めなかったので v1 では入れない。

## 追記: この 3 問題が「フォールバックしない」根拠になった

種目ごとのラベル（[チップでラベルを選ぶと履歴とコピーが切り替わる](label-chips-switch-the-history-and-the-copy.md)）で、選んだラベルの履歴が 0 件のときに**ラベルなしの前回へ落とさない**と決めた根拠がここにある。

落とすと、ボタンの隣に「記録なし」と書いてあるのに押すと別のラベルの `70×10` が 3 行入る。**表示と行き先が一致しない**ので、本 ADR が消した 3 つの問題（置換か追記か / 誤タップで入力済みを失う / undo の必要性）が「ラベルを切り替えた直後」という別の入口から戻ってくる。

代わりに `show_copy` を**絞り込み後の履歴**から出し、0 件なら「記録なし」+ ボタン非表示にした。本 ADR の「空のときだけ出す」が「引ける前回があるときだけ出す」へ 1 段広がった形で、判断は反転していない。
