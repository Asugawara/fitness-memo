# フォーカスリングを明示し、記録タブの見出しを 1 本の階層にする

- **状態**: 採用
- **日付**: 2026-08-09
- **カテゴリ**: ux
- **関連**: [記録タブをカレンダー + 選択日エディタの単一画面にする](record-tab-calendar-with-day-editor.md), [`color-scheme` を宣言し、クラスなしの `<button>` を作らない](declare-color-scheme-for-ua-widgets.md), [シートをネイティブ `<dialog>` にし、手動の重なり順から降りる](native-dialog-for-sheets.md)

## 背景

アクセシビリティ監査を当てたところ、土台は既に整っていた。`<main>` / `<nav>` / `<header>` / `<section>` のランドマーク、アイコンボタンの `aria-label`、通知の `role="status"`、グラフの `role="img"` + `aria-label` はすべて入っている。`color-scheme` も [`color-scheme` を宣言し、クラスなしの `<button>` を作らない](declare-color-scheme-for-ua-widgets.md) で宣言済み。

残っていた穴は 2 つだった。

**`:focus-visible` の指定が 1 件も無かった。** 当時 `outline: none` はどこにも書いていなかったので UA 既定のリングは出る。ただし既定のリングが保証するのは「地の色に対して見えること」だけで、`--accent` でベタ塗りしたコントロール（`.primary` / `.opt.on` / `.seg-btn.active`）の上では塗りに沈む。

> **追記（同日）**: この決定のあと `outline: none` が 2 か所に入った。`.sheet`（`<dialog>` 自身）と `.icon-btn`（同じ節でグリフ側に出し直している）で、いずれも下の「アイコンボタンのリングはグリフに出す」「シートの初期フォーカス」の帰結。**操作できる要素からは 1 つも消していない。**

**記録タブに `<h1>` が 2 つあった。** [記録タブをカレンダー + 選択日エディタの単一画面にする](record-tab-calendar-with-day-editor.md) でカレンダーと選択日の入力欄を 1 画面に縦に並べた結果、`calendar.rs` の月見出しと `day.rs` の日付見出しが両方 `<h1>` になっていた。**1 画面に見出しの階層が 2 本立っている**状態で、支援技術のアウトラインからは前後関係が読めない。

## 決定

**1. フォーカスリングを明示する。**

```css
:where(button, a:any-link, input, select, textarea):focus-visible {
  outline: 2px solid var(--accent);
  outline-offset: 2px;
}

.primary:focus-visible,
.opt.on:focus-visible,
.seg-btn.active:focus-visible {
  outline-color: var(--accent-text);
  outline-offset: -4px;
}
```

**1-b. アイコンボタンだけは、リングを箱ではなくグリフに出す（同日に追加）。**

```css
.icon-btn:has(> .icon):focus-visible {
  outline: none;
}

.icon-btn:focus-visible > .icon {
  outline: 2px solid var(--accent);
  outline-offset: 4px;
  border-radius: 50%;
}

.notice .icon-btn:focus-visible > .icon {
  outline-color: var(--accent-text);
}
```

`.icon-btn` は 44px 角（タップ標的の規約値）なのに中身は 20px の `.icon` なので、箱に沿わせると外形 52px の角ばった四角になり、グリフの四辺に 12px の空白を挟んでリングが立つ。しかも 44px の箱は親にぴったり収める前提で置かれているので、その外へ 4px 出た時点でどこかを突き抜ける。実際、シートの ✕ は上辺が `.sheet` の角丸の外＝黒幕の上に出て、**上だけ長い青線**として見えていた。

グリフ基準なら外形 32px の円で、32 = 44 − 6×2 なので標的の内側に必ず 6px 余る。箱の padding にも `.set-row` の区切り線（`padding-left` + `border-left` でグリフが箱の中心からずれる）にも影響されない。`:has(> .icon)` で門番してあるので、中身が `.icon` でない `.icon-btn` が現れても既定の箱リングに戻るだけで、**リングが消えることはない**。

`box-shadow` ではなく `outline` のまま出すのは、強制カラーモードで色を差し替えてもらえるのが `outline` だから（下の「検討した代替案」と同じ理由）。

**1-c. `.seg-btn` のリングを内側に入れる（同日に追加）。**

`.segmented` は `overflow: hidden` で、`.seg-btn` は親の content box を隙間なく埋める。外側 2px のリングは親の外なので**上下の辺が丸ごとクリップされ**、隣のボタンに重なった縦棒だけが残っていた。`.active` は既に `-4px` だったので無事で、非 active だけが欠けていた。

**2. 記録タブの見出しを 1 本の階層に直す。**

| 要素 | 変更前 | 変更後 |
|---|---|---|
| カレンダーの月見出し（`calendar.rs`） | `h1` | `h1`（据え置き） |
| 選択日の日付（`day.rs`） | **`h1`** | **`h2`** |
| 「前回のメニューから始める」 | `h2` | `h3` |
| 種目カードの名前 | `h2` | `h3` |

## 理由

**`:focus` ではなく `:focus-visible`。** 指でタップしただけの要素にリングを出さないため。Safari はボタンをタップしてもフォーカスを与えないが（[シートをネイティブ `<dialog>` にし、手動の重なり順から降りる](native-dialog-for-sheets.md) で実測）、Chromium は与えるので `:focus` だと PC でタップのたびにリングが出る。

**`:where()` で詳細度を 0 にする。** 塗りボタン側の上書きがクラス 1 個（詳細度 0,1,0）で勝てるようにするため。素で `button:focus-visible`（0,0,1 + 疑似クラス）と書くと、上書き側との関係が読みづらくなる。

**塗りの上では `--accent-text` で抜き、オフセットを負にする。** `--accent-text` は「強い塗りの上に載せる文字色」としてモード間で反転するトークン（実測値は `.notice` のコメントにある）。オフセットを外側（正）に出すと、ボタンの `--accent` とリングの `--accent` が接して境界が消えるので、塗りの内側へ 4px 入れる。

**日付見出しを `h2` に落とすほうが、月見出しを落とすより正しい。** 記録タブの主語は「今見ている月」で、選択日はその中の 1 つ。逆にすると、カレンダーが日付見出しの従属物ということになって構造が実態と合わない。

**種目カードを `h3` に落としたのは、`h2` のままだと選択日と同列になるから。** 種目は選択日にぶら下がるものなので 1 段深い。

## 結果（トレードオフ）

**`.day-head h1` / `.card-head h2` のセレクタを追従させた。** 見出しレベルにぶら下がった CSS があると、レベルを変えたときに黙って効かなくなる。今回は 3 箇所（`.day-head h1` → `h2`、`.day-head.past h1` → `h2`、`.card-head h2` → `h3`）。

**見た目は変わらない。** `font-size` はクラスとセレクタで指定しており、`h1, h2, h3 { margin: 0; font-weight: 600 }` で UA 既定も潰してある。E2E のスナップショット的な検証（レイアウト系のテスト）が 1 件も落ちなかったのはそのため。

**フォーカスリングは iPhone の通常操作では出ない。** Safari はタップでフォーカスを与えないので、実機で見えるのは外付けキーボードを使ったときと、PC ブラウザで開いたとき。それでも入れるのは、出ないと**キーボードだけで操作している人が現在位置を完全に見失う**から。

> **追記（同日）**: 上の一文には**シートという例外があり、しかも例外が出るのは iPhone Safari のほうだった**。`show_modal()` の dialog focusing steps はタップ起点でも「中の最初のフォーカス可能要素」＝ ✕ にフォーカスを与える。これは両エンジン共通だが、**それを `:focus-visible` と判定するのは WebKit だけ**（実測表は [シートをネイティブ `<dialog>` にし、手動の重なり順から降りる](native-dialog-for-sheets.md) にある）。つまり **iPhone Safari では、シートを指でタップして開いただけで ✕ に青枠が出ていた**。Chromium では出ない。
>
> ここでの教訓は 2 つある。**「Safari はタップでフォーカスを与えない」から「Safari ではリングが出ない」を導くと逆に着地する。** タップで与えないのは利用者の操作によるフォーカスで、`show_modal()` の初期フォーカスは UA が能動的に与える別の経路。**そして「タップではリングが出ない」を前提に幾何を確かめずにいたのが、`.icon-btn` の 52px のリングがシートの外へ突き抜けていることに気づかなかった原因**でもある。実機で出ないと思っている見た目は、誰も見ていないのではなく**確かめていないだけ**のことがある。

## やらなかったこと

**`px` → `rem` 化はしない。** アクセシビリティのガイドは相対単位を勧めるが、このアプリの `px` は装飾ではなく**閾値**である。

- `input { font-size: 16px }` は iOS がフォーカス時にページごとズームする境界そのもの
- `--tabbar: 56px` / `min-height: 44px` はタップ標的の規約値

`rem` 化すると、これらがルートのフォントサイズに依存して動く。利用者が文字サイズを上げた瞬間に iOS のズーム閾値を割り込む、という**直そうとした問題を作り出す**変更になる。代わりに「iOS の文字サイズを最大にしても、200% ズームでも読めて押せる」を実機で確認する方に倒す。

**skip link は入れない。** ナビゲーション（ボトムタブ）が**ページ末尾**にあり、本文の前に繰り返しコンテンツが無い。飛ばす対象が存在しないので、置いても 1 つ増えるだけで何も短縮しない。

## 検討した代替案

**塗りボタンに `box-shadow` で二重リングを出す。** 地色 + アクセントの 2 本を重ねる定番手法で、どんな背景でも見える。ただし `outline` と違って角丸に沿わせる指定が別途要り、`.primary` / `.opt` / `.seg-btn` で角丸が違うぶんルールが増える。2 色を出し分ける現在の形で足りている。

**`prefers-contrast: more` でリングを太くする。** ガイドは「低コントラストのアクセントを使っている場合に検討」としている。このアプリのリングは `--accent`（地に対してライト 4.9 / ダーク 6.9）なので該当しない。
