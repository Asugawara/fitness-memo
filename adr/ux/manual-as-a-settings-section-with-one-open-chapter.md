# 使い方マニュアルを設定タブの節にし、章は 1 つだけ開く

- **状態**: 採用
- **日付**: 2026-09-09
- **カテゴリ**: ux
- **関連**: [設定タブの入口を節の一覧にし、中身は 1 階層下ろす](settings-as-a-list-of-sections.md), [種目タブを部位の折りたたみ一覧にし、1 つだけ開く](menu-groups-as-single-open-accordion.md), [記録タブの「種目を追加」シートを部位のアコーディオンにし、1 つだけ開く](record-add-sheet-groups-as-single-open-accordion.md), [ホーム画面への追加の案内を記録タブ末尾のバナー + 手順シートにする](install-guide-banner-and-sheet.md), [フォーカスリングを明示し、記録タブの見出しを 1 本の階層にする](focus-ring-and-heading-order.md), [UI の状態に `Db` の ID を置いてよい条件を決める（寛容な受け口と既定への受け皿）](../storage/db-ids-in-ui-state-behind-a-fallback.md), [マニュアルの図は `public/` に配信するスクリーンショットにし、`<img>` で参照する](../architecture/manual-figures-as-served-screenshots.md)

## 背景

機能が増えた結果、**アフォーダンスが無い / 入口が隠れている**機能が溜まった。

- グラフをタップすると読み取り欄が別の点へ動く
- 「＋ メモ」1 つでピン・インターバル・種目メモ・セット行のメモの **4 つ**が一斉に開く
- カードの見出し行は 250ms 長押しで並び替えが始まるが、セット行は番号を掴んだ瞬間に動く
- 空の日にだけ候補リストが出て、選んだ瞬間その日が「実施済み」になる
- 部位の折りたたみは 3 か所にあり、同時に開ける数が違う

どれも UI を見ただけでは気づけない。README には書いてあるが、**アプリを使っている人は README を読まない。**

置き場所の候補は 3 つあった。ボトムタブを増やす / シートで出す / 設定タブの中に節を作る。タブを増やす案は [ホーム画面への追加の案内を記録タブ末尾のバナー + 手順シートにする](install-guide-banner-and-sheet.md) が既に「記録・推移・設定はすべて日常操作で、ヘルプは一生に 1 回開く画面。その 1/4 を使い切る価値がない」と却下しているので、実質はシートか節かである。

## 決定

**設定タブに `SettingsPage::Manual` を足し、11 章のアコーディオンにする。同時に開く章は 1 つ。** 行はトップの **8 行のうち 7 行目**（`InstallHelpLink` の直後、言語の直前）。

```
設定
  データの書き出し / 読み込み
  トレーニングメニュー          2
  種目                        28
  過去の記録の表示数            1
  ホーム画面への追加のしかた
  使い方                      ← 追加
  言語                      日本語
```

**加えて、記録タブに初回だけ手掛かりを出す。**`<DayEditor />` の直前、✕ で消せる 1 回限りの案内で、CTA を押すと設定タブのマニュアル節へ飛ぶ。

```rust
/// マニュアルで開いている章。**同時に開くのは 1 つ**。
pub struct OpenManualCtx(pub RwSignal<Option<usize>>);
```

- 章の骨格は `src/manual.rs` の `MANUAL_CHAPTERS`、文言は `src/i18n.rs` の `ChapterText`
- 見出しは h1（節名、`back_head`）→ h2（章名）の 1 本
- マークアップは `.fold-group` と同じ `<h2><button class="grp-toggle" aria-expanded=…>` + `{icon(icon::CHEVRON_RIGHT)}`。クラスは `.man-group`
- 開いた章は `scroll_into_view_if_needed`（`block: nearest`）で画面に入れる
- 永続化はしない

## 理由

### 節にする（シートにしない）

- **タブを往復するとシートは必ず閉じる。** `views::mod` の `match tab.get()` はタブを切り替えるたびに `Settings` を丸ごと作り直すので、`Settings` の中に持った `RwSignal<bool>` はリセットされる。マニュアルは**「読む → 記録タブで試す → 戻る」**で読まれるものなので、戻るたびに開き直すのでは使えない。`SettingsPageCtx`（`App` が持つ）に載る節なら残る。
- **「`Sheet` が本文を DOM に恒久的に置く」は却下理由にならない。** `Sheet` の中身は `move || editor.get().map(..)` の形で**開いているときだけ描いている**（`views::settings` の編集シート、`views::routine`）。DOM に居座るという前提が事実でない。**有効な理由は「タブ往復で閉じる」だけである。**
- 節にすると `back_head` が付いて `<h1>` が節名になる。**画面に h1 は常に 1 つ**という規約（[フォーカスリングを明示し、記録タブの見出しを 1 本の階層にする](focus-ring-and-heading-order.md)、E2E が `main h1` の個数を固定）にそのまま乗る。

### 行の位置

- **`InstallHelpLink` の直後に置いたのは、性格が近いからである。** どちらも「アプリの使い方の説明」で、どちらも一生に数回しか開かない。隣接させて 1 つの帯にすると、探す人はその帯だけ見れば済む。
- **既存 6 行は 1 行も動かない。** 先頭の「データの書き出し / 読み込み」は「データを失う前に見つけてもらう」ために固定されており（[設定タブの入口を節の一覧にし、中身は 1 階層下ろす](settings-as-a-list-of-sections.md)）、末尾の「言語」は探しに来る頻度が最も低いので末尾にある。マニュアルはその間で、ヘルプの隣。
- **`count` は `None`。** 章数を出しても「入らずに気づける」（同 ADR の件数の理由）にならない。8 と書かれて意思決定が変わる人はいない。

### 1 章だけ開く

- **[種目タブを部位の折りたたみ一覧にし、1 つだけ開く](menu-groups-as-single-open-accordion.md) と [記録タブの「種目を追加」シートを部位のアコーディオンにし、1 つだけ開く](record-add-sheet-groups-as-single-open-accordion.md) に揃える。** このアプリで「1 つだけ開く」は既に 2 か所あり、複数開けるのはメニュー編集シートの「選択中」だけである（1 本組む間に胸と脚を行き来するという固有の事情がある）。マニュアルは**1 章読んで閉じる**画面で、章を往復しない。
- **閉じた 11 行なら見出しが一望できる。** 全部開くと 11 章 × 3〜4 段落が縦に並び、目当ての章を探すのに長いスクロールが要る。閉じていれば位置が固定され、手が場所を覚える。
- **開いた章のぶんだけネットワークに飛ぶ。** 図はオフラインシェルに載せていない（[マニュアルの図は `public/` に配信するスクリーンショットにし、`<img>` で参照する](../architecture/manual-figures-as-served-screenshots.md)）ので、章を開くと `<img>` が 1〜2 枚取りに行く。全部開く形にすると、マニュアルを開いた瞬間に 190KB を取ることになる。**これは SW シェル除外の帰結であって、独立した理由ではない。**
- **`aria-expanded` と `.grp-toggle` を写したので、CSS の追加は 2 ブロックで済んだ。** `.grp-toggle[aria-expanded="true"] > .icon { transform: rotate(90deg) }` が効くので新しいアイコンは要らない。ただし **`.fold-group > h3` のリセットは流用できない** — `.grp-toggle` は `.card-head`（flex アイテム）か `.fold-group > h3`（唯一の子）の中でしか成立する形になっていない。マニュアルは h2 なので `.man-group > h2` に同じリセット（`font-size: inherit` / `font-weight: inherit`）を書いた。`.fold-group` を流用して `<h3>` にする案は、見出し階層が h1 → h3 に飛ぶので採らない。

### `OpenManualCtx` を `App` に置き、永続化しない

- **`App` に置くのは `OpenGroupCtx` / `SettingsPageCtx` とまったく同じ理由。** タブ往復で `Settings` が作り直されるので、コンポーネント内のシグナルにすると記録⇄設定の往復のたびに全章が閉じる。せっかく節を保っているのに、その中で章を探し直しては意味がない。
- **永続化しない理由は `OpenGroupCtx` とは違う。** あちらの理由は「`Db` の ID が宙に浮く」だが、**章 index は `usize` なので宙に浮きようがない**（章を消したら index が別の章を指すが、それは `MANUAL_CHAPTERS` の長さで弾ける）。[UI の状態に `Db` の ID を置いてよい条件を決める（寛容な受け口と既定への受け皿）](../storage/db-ids-in-ui-state-behind-a-fallback.md) の言い方に合わせるなら、**条件を満たせないからではなく、満たす必要が無いから**である（記録⇄設定の往復に耐えればよく、アプリの再起動をまたぐ要求が無い）。一生に数回読むものを次回起動時まで覚えておく価値がない。理由を取り違えると、次に触る人が「ID じゃないから永続化してよい」と読む。
- **再マウント時に開いている章を画面へ入れる。** `settings.rs` の `open_group` と同じ `Effect` + `scroll_into_view_if_needed`。`block: nearest` なので既に見えている章は 1px も動かない。これが無いと、末尾の章を開いたときに見出しが画面外のまま本文だけが下に伸びる。

### 記録タブに初回だけ手掛かりを出す

- **設定の 6 行目に置くだけだと、この ADR は自分の目的を潰す。** [設定タブの入口を節の一覧にし、中身は 1 階層下ろす](settings-as-a-list-of-sections.md) が「2 タップ先に置くと、必要な人ほど辿り着かない」と書いており、**「気づきづらい機能の説明」が気づきづらい場所にある**という矛盾がそのまま起きる。マニュアルを必要とする人は、設定タブを開いて 6 行目を読む人ではない。
- **置き場所は `<DayEditor />` の直前。記録タブの末尾ではない。** [ホーム画面への追加の案内を記録タブ末尾のバナー + 手順シートにする](install-guide-banner-and-sheet.md):78 の実測では、393×659・記録ゼロでも install バナーの上端は **685px = 可視域外**（記録があれば更に下。3 種目で文書高 1671px）。そこへ置くと矛盾を引き継ぐだけである。末尾配置の根拠（「毎回目に入って邪魔」）は**毎回出る常駐バナーの理屈**で、✕ で消える一回限りの手掛かりには当たらない。同 ADR 自身が「後から『やはり届いていない』となったときは、位置を戻すのではなく対象を絞って可視域へ戻す方向を検討すること」と書いており、**その指示どおりに従った**。E2E で `boundingBox().y + height <= 659` を固定してある。
- **install バナーとの排他は `applicable` 単独では書けない。** `applicable`（`!is_standalone() && storage_may_split()`）だけを見ると、次の 3 つで**永久に出ない**。
  - install バナーを ✕ で消して Safari のタブで使い続ける人（バナーの実際の出現条件は `!dismissed && applicable`）
  - PC ブラウザ（`storage_may_split()` は UA に `Android` を含まない限り真）
  - Playwright の `chromium` project（Desktop Chrome UA・非 standalone）→ **pre-commit の E2E で `manual-hint` が既定で 0 件になり、肯定側のテストが書けない**

  目的は「2 つのバナーを縦に並べない」だけなので、`applicable && !install_hint_dismissed()` として **install バナーが実際に出ているときだけ避ければ足りる。** 肯定側の E2E は `fakeStandalone` / `UA_ANDROID` で条件を作る。
- **トーンは `.notice` に寄せない。向きが逆である。** `.notice` は `background: var(--warn)` の橙ベタ塗りで、復元失敗・保存失敗の警告枠である。[ホーム画面への追加の案内を記録タブ末尾のバナー + 手順シートにする](install-guide-banner-and-sheet.md) 自身が「`.notice` のようなベタ塗りにしない。常駐するものに同じ強さを与えると、どちらが緊急かが読めなくなる」と書いている。マニュアルの手掛かりは警告ですらないので、**第 3 のトーンを新設した** — `--surface` の面 + `--line` の枠、CTA だけ `--accent`。install バナー（`--warn` の枠線）より弱く、`.notice`（橙ベタ塗り）より静かな位置。
- **CTA はこのアプリ初の画面間プログラム遷移になる。** 記録タブ → 設定タブ → `SettingsPage::Manual` には `TabCtx::switch(dates, Tab::Settings)` と `SettingsPageCtx.set(SettingsPage::Manual)` の 2 書き込みが要る。**`TabCtx` を消費する view はこれまで 1 つも無かった**（`rg TabCtx src/views/` が `mod.rs` とコメントしか返さなかった）。押したときに `dismiss_manual_hint()` も呼ぶ（読みに行った人にもう出す必要はない）。遷移先が `SettingsPage::Manual` になることを E2E で固定した。
- **永続化は `install_hint` とまったく同じ仕組みに乗せる。** `UiState` に `#[serde(default)] manual_hint_dismissed: bool` を足すだけ。**`bool` + `#[serde(default)]` にすること** — `src/storage.rs` のコメントが繰り返し警告しているとおり、パースが落ちると `UiState` 全体が巻き添えで消える（`install_hint_dismissed` も `lang` も飛ぶ）。

## 結果（トレードオフ）

- **設定タブのトップが 7 行になった。** `e2e/smoke.spec.mjs` の `toHaveCount(6)` を 7 に直してある。**この 1 行を直さないと pre-commit の Playwright が落ちてコミットできない**ので、行を足す人は必ず気づく（静かに壊れない）。
- **`assets/3-menu.png`（README の設定タブ）が古くなる。** 行が 1 本増えた画面なので撮り直しが要る。[UI 関連パスを触ったコミットでだけスクリーンショットを撮り直す](../deploy/screenshots-in-pre-commit-on-ui-paths.md) は README を pre-commit で撮らないので、**手で `--only=readme` を叩くまでずれたままになる**。
- **手掛かりは 1 回しか出ない。** ✕ を押した人・CTA を押した人には二度と出ない。そのあとマニュアルへ行く手段は設定タブの 6 行目だけになる。[ホーム画面への追加の案内を記録タブ末尾のバナー + 手順シートにする](install-guide-banner-and-sheet.md) の ✕ と同じ構図で、**「消えるのは案内だけで中身は消えない」**が成立する前提に乗っている。
- **手掛かりは 1 度きりの評価でリアクティブではない。** `install_showing` はコンポーネントのマウント時に 1 回だけ評価する。install バナーを ✕ で消しても、**同じタブでは**手掛かりが出てこない（タブを切り替えれば `match tab.get()` が `Calendar` ごと作り直すので再評価される）。`InstallBanner` 自身の環境判定が同じ粒度なので、揃えてある。
- **install バナーの `dismissed` シグナルを直接見ていない。** コンポーネントが別なので見えず、`storage::install_hint_dismissed()` を独立に評価している。同じ画面で install バナーを ✕ したその瞬間には手掛かりが出ないが、上記のとおり再マウントで揃う。
- **記録タブに 1 要素増えた。** 初回だけとはいえ、`<DayEditor />` の直前という**記録の導線のまん中**に案内が入る。[ホーム画面への追加の案内を記録タブ末尾のバナー + 手順シートにする](install-guide-banner-and-sheet.md) が「最初の画面に常駐する警告が記録の導線を邪魔する」を理由に末尾へ落としたのと**逆向きの判断**である。差は常駐かどうかで、こちらは ✕ で消える 1 回限りだから許容した。**もし「邪魔だ」という声が出たら、位置ではなく出現条件（例: 記録が 0 件の日だけ）を絞ること。**
- **章の並べ替えが 3 ファイルの往復になる。** `src/manual.rs` の `MANUAL_CHAPTERS` と `src/i18n.rs` の `JA_MANUAL` / `EN_MANUAL` を同じ順で並べ替える必要がある。順序がずれても**コンパイルは通る**（長さが同じなので）。`every_language_has_the_same_manual_chapters` は章数と非空しか見ないので、**見出しと本文が入れ替わったマニュアルは検出できない。** この穴は [i18n crate を入れず、`src/i18n.rs` の struct + `const` 2 枚で文言を持つ](../architecture/i18n-hand-rolled-string-table.md) への追記に書いた。
- **図のある章とない章が混ざる。** 11 章のうち図を持つのは 6 章で、`progress-target`（閉じた `<select>` しか写らない）・`labels`（定義は設定タブの編集シート、選択は記録タブのカードと 2 画面にまたがり、1 枚では両方を写せない）・`reorder`（静止画で伝わらない）・`backup`（文章で足りる）・`whats-new`（読み終えると二度と出ないシートで、図を残す価値が薄い）は本文だけである。読む人からは「図が出る章と出ない章がある」ように見えるが、**図は補助であって本文が主**という位置づけなので受容する。`e2e/manual.spec.mjs` の「図が無い章にも本文がある」で、空の章が出ないことを固定した。
- **`OpenManualCtx` で `App` が持つコンテキストが 1 つ増えた。** `DbCtx` / `DateCtx` / `TabCtx` / `KbCtx` / `OpenGroupCtx` / `SettingsPageCtx` / `LangCtx` に続く 8 本目。増やす基準は「タブ往復で失いたくない UI 状態か」で一貫している。

## 検討した代替案

**シート（`<dialog>`）で出す**: `views::help` の手順シートと同じ形にでき、設定タブのトップから 1 タップで開く。しかし**タブを往復すると必ず閉じる**（`match tab.get()` が `Settings` を作り直す）。マニュアルは「読む → 記録タブで試す → 戻る」で読まれるものなので、これは致命的である。却下。

**ボトムタブを 4 つ目として増やす**: 最も見つけやすい。しかし [ホーム画面への追加の案内を記録タブ末尾のバナー + 手順シートにする](install-guide-banner-and-sheet.md) が同じ判断を既に下している（「記録・推移・設定はすべて日常操作で、ヘルプは一生に 1 回開く画面。ルーターを持たない構成ではタブが唯一の最上位ナビゲーションなので、その 1/4 を使い切る価値がない」）。却下。

**章を折りたたまず全部開いた 1 枚のページにする**: 実装が最も単純で、`Ctrl+F` 相当（ブラウザのページ内検索）が全章に効く。しかし 11 章 × 3〜4 段落 + 図 12 枚が縦に並び、目当ての章まで長くスクロールすることになる。図をオフラインシェルから外している以上、開いた瞬間に約 214KiB を取りに行くことにもなる。却下。

**複数の章を同時に開けるようにする**（メニュー編集シートと同じ）: 2 つの章を見比べられる。しかし比べる場面が思いつかない（章は独立した機能の説明で、メニュー編集の「胸と脚を行き来する」に当たる事情が無い）。このアプリで「1 つだけ開く」が既に 2 か所あるので、例外を作る理由が要る。却下。

**開いている章を `localStorage` に永続化する**: アプリを再起動しても続きから読める。しかしマニュアルは一生に数回読むもので、「途中まで読んで翌日続きを読む」文書ではない。`localStorage` への書き込みが増えるだけである。`OpenGroupCtx` / `SettingsPageCtx` と同じ扱いで揃える。却下。

**手掛かりを出さず、設定タブの行だけにする**: 実装が減り、記録タブが 1 要素も増えない。しかし「気づきづらい機能の説明」が 2 タップ先にあるという矛盾が残り、この機能を作った目的そのものが達成されない。却下。

**手掛かりを記録タブの末尾（install バナーの隣）に置く**: 記録の導線を一切邪魔しない。しかし実測で上端 685px = 可視域外なので、**目的（気づかせる）を自分で潰す**。却下。
