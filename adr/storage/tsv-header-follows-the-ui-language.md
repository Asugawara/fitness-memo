# TSV の見出しは UI 言語で書き、読み込みは日英どちらも受ける

- **状態**: 採用
- **日付**: 2026-08-19
- **カテゴリ**: storage
- **関連**: [書き出しを TSV にし、保存形式（JSON）と分ける](tsv-export-for-spreadsheets.md), [取り込みは「足すだけ」に固定する](import-is-merge-only.md), [書き出しは共有シートを主経路にし、iOS では `<a download>` を使わない](share-sheet-over-download.md), [プリセット名は初回投入の言語で固定し、ユーザーデータとして扱う](preset-names-are-user-data-seeded-once.md)

## 背景

書き出しの TSV は 12 列の見出し行を持ち、その並びと綴り（`日付` / `部位` / `種目` …）が
外部仕様として凍結されている。TSV は `schema` に当たる欄を持てないので
`Unsupported` を返す手段が原理的に無く、代わりに進化規則を課してある:

1. **列は足すだけ。** 既存の列名と意味は永久に変えない
2. **取り込みは列を名前で引き、知らない列は無視する**（位置で読まない）
3. 足した列は「無くても読める」ものだけにする

英語対応にあたり、この見出しをどうするかを決める必要がある。

## 決定

**見出しの表を日英 2 枚持ち、書き出しは UI の言語に従う。取り込みは両方を受ける。**

```rust
const TSV_HEADER_JA: [&str; 12] = ["日付", "部位", "種目", …];
const TSV_HEADER_EN: [&str; 12] = ["Date", "Muscle group", "Exercise", …];

pub fn tsv_header_row(lang: Lang) -> [&'static str; 12] { … }
fn is_known_header_cell(cell: &str) -> bool {
    TSV_HEADER_JA.contains(&cell) || TSV_HEADER_EN.contains(&cell)
}
```

パーサは各列の `match` に英語の別名を足す（`"日付" | "Date" =>` の形）。
既存の別名（`重量` / `体重`）はそのまま残す。**大文字小文字は現行どおり厳密一致。**

既存 12 列の日本語の綴りは **1 文字も変えない。**

## 理由

- **読めない列名は書き出しの存在意義を消す。** この形式を選んだ理由は
  [書き出しを TSV にし、保存形式（JSON）と分ける](tsv-export-for-spreadsheets.md) のとおり
  「Google スプレッドシートでそのまま開いて読めること」だった。英語のユーザーが開いて
  列名だけ日本語なら、その目的を半分しか達していない。
- **取り込みが両方を受けるので、進化規則 1 を破らない。** 日本語の綴りは残したまま
  英語を**足しただけ**なので、過去に書き出したファイルは全部そのまま読める。
  「列は足すだけ」の精神が、列だけでなく列名の別名にも同じように効く。
- **往復が言語を跨いで閉じる必要がある。** 端末 A が日本語、端末 B が英語という状況は
  普通に起きるし、同じ人が途中で言語を切り替えることもある。片方向しか読めない形式は、
  そのどちらでもデータを失う。`cargo test` で 4 方向（ja→ja / ja→en / en→ja / en→en）を固定した。
- **種目名の側も両言語で引ける**ので、見出しだけ通っても中身が割れる、ということが起きない
  （[プリセット名は初回投入の言語で固定し、ユーザーデータとして扱う](preset-names-are-user-data-seeded-once.md)）。
- **`時刻` / `Time` は書き出し専用のまま。** 読まない列に別名を足す必要はないが、
  見出しの表には入れておく（`is_known_header_cell` が `NotDb` と `NoHeader` を
  切り分けるのに使うので、載っていないと英語のファイルが「うちのものではない」と判定される）。
- **大文字小文字を緩めない。** 今も `重量` / `体重` の別名を手で列挙する方針でやってきた。
  `eq_ignore_ascii_case` に変えると全列の判定が変わるので、必要になったら別 PR で検討する。

## 結果（トレードオフ）

- **英語の綴りも、出した時点で永久の外部仕様になった。** `Muscle group` を後から
  `Group` に変えると、それ以前に書き出したファイルが読めなくなる。日本語の 12 語と
  同じ重みで凍結される。バイト一致テストを両言語ぶん置いてある。
- **見出しは言語で分かれるが、`部位` / `種目` 列の中身は `Db` 由来なので言語が混ざりうる。**
  英語の見出しの下に日本語の種目名が並ぶファイルは普通に出る（既存ユーザーが
  英語に切り替えて書き出した場合）。読めないわけではないので受容する。
- **`match` の腕が 2 倍近くになった。** 12 列 × 日英 + 既存の別名で、
  1 つの `match` が 11 腕・各腕 2〜4 パターンになっている。列を足すときの手数も増える。
- **パーサの関数名を変えた。** `tsv_header` は新設の `tsv_header_row`（書き出し用）と
  紛らわしいので `tsv_cols` に改名した。既存の呼び出しは 1 箇所だけだったので影響は小さい。

## 検討した代替案

**英語見出しに一本化する**: 表が 1 枚で済み、`match` も増えない。しかし日本語のユーザーが
書き出したシートの列名が読めなくなる。これは現在の全ユーザーに対する退行なので却下。

**日本語見出しのまま凍結する**: 実装もテストも一切変わらず、最も安全。しかし英語のユーザーが
スプレッドシートを開くと列名だけ日本語という状態になり、書き出しの存在意義を半分失う。
「変更が無い」ことと「正しい」ことは違う。却下。

**`# lang=ja` のようなメタ行を先頭に足す**: 書き出した言語を機械的に判定できる。
しかし進化規則 1（列は足すだけ / 既存の意味を変えない）に反するし、
**スプレッドシートで開いたときに 1 行目が謎の行になる**。表として読めることが
この形式の全てなので、そこを汚すのは本末転倒。却下。

**見出しを言語非依存の機械名にする**（`date`, `group`, `exercise` …）: 表が 1 枚で済み、
言語を跨いだ往復も自明になる。しかし**スプレッドシートで開いたときに読めなくなる**ので、
[書き出しを TSV にし、保存形式（JSON）と分ける](tsv-export-for-spreadsheets.md) の目的を
真っ向から否定する。表示名を別に持って 2 段にする案もあるが、TSV は 1 行しか見出しを持てない。却下。
