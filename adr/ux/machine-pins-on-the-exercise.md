# マシンのピンは種目に持たせ、メモのトグルに相乗りさせる

- **状態**: 採用
- **日付**: 2026-08-19
- **カテゴリ**: ux
- **関連**: [メモは種目カードのトグル 1 つで開き、閉じても薄字で残す](exercise-and-set-notes-behind-one-toggle.md)（入口を共有する相手）, [種目メモとセットメモを `ExerciseLog` / `SetEntry` に持たせ、空のメモは書き出さない](../data-model/notes-on-logs-and-sets.md)（スコープの対比）, [破壊的操作は静止時に警告色を持たない（カード削除をフッタへ畳む）](destructive-affordance-quiet-at-rest.md), [数値入力に `type="number"` を使わない](text-input-not-number.md), [表計算で開ける TSV で書き出す](../storage/tsv-export-for-spreadsheets.md), [取り込みは「足すだけ」に固定する](../storage/import-is-merge-only.md), [UI の状態を `Db` に入れず別キーに置く](../storage/ui-state-in-separate-key.md), [コピーは種目メモとセットメモを持ち込む（体調メモと体重は持ち込まない）](copy-carries-the-notes.md)（住み分けの相手）

## 背景

ジムのマシンはシート高・バー位置・背もたれ角度をピンで固定する。**毎回同じ穴に合わせたい**のに、このアプリにはその番号を置く場所が無かった。1 台のマシンで複数のピンを合わせるので、1 種目に複数持てる必要がある。

既にメモは 2 つある（[種目メモとセットメモを `ExerciseLog` / `SetEntry` に持たせ、空のメモは書き出さない](../data-model/notes-on-logs-and-sets.md)）が、**どちらもその日のもの**で日をまたいで残らない。3 つ目を同じ語・同じ場所に足すと、「どのスコープの話か」の読み分けが崩れる。

> **補足（同日に採った [コピーは種目メモとセットメモを持ち込む（体調メモと体重は持ち込まない）](copy-carries-the-notes.md) との関係）**: あちらでコピー操作が種目メモを運ぶようになったので、「日をまたいで残らない」は厳密には「**コピーしたときだけ運ばれる**」になった。ただし運ばれた先は**その日のログに属する独立した文字列**で、貼り付いてはいない（直しても過去に遡らない）。ピンは 1 か所直せば全日に効く。**この ADR の決定は 1 つも変わっていない** — スコープの読み分けが要る、という背景がむしろ強まっている。数値で表せる設定はピン、自由記述はメモ。

制約は [メモは種目カードのトグル 1 つで開き、閉じても薄字で残す](exercise-and-set-notes-behind-one-toggle.md) が測ったものがそのまま効く。**カード内に 44px のタップ標的を新設できる場所が無い**（どこに作っても 44px × カード枚数だけ縦に純増し、5 種目で 220px）。さらにヘッダは `e2e/smoke.spec.mjs` が `.card-head button` を 0 件で固定していて、置いた瞬間に落ちる。

## 決定

### 1. `Exercise.pins: Vec<String>`。種目に貼り付く永続設定にする

```rust
#[serde(default, skip_serializing_if = "Vec::is_empty")]
pub pins: Vec<String>,
```

**`SCHEMA` も `storage::KEY` も上げない。** `model.rs` の規則そのもので、`#[serde(default)]` 付きの追加は旧版が未知フィールドとして黙って無視するので `migrate` が `Err` を返さない。ここで上げると逆に旧版が `RestoreError::Unsupported` で退避し、**前方互換を積極的に壊す側になる**。`skip_serializing_if` により、ピンを使わない利用者の JSON は**今までとバイト単位で同一**のまま。

**`Vec<u32>` にしない。** `7.5` 刻みのマシンがあり、穴に `A` や `赤` と刻んであるものも実在する。入力欄は数字キーパッドに倒すが（決定 3）、取り込んだ値を型の都合で落とさない。

上限は 8 本 × 6 文字。これは UI の制限ではなく**取り込みのための門番**で、`drop_unrepresentable_weights` と同じ立場（UI からは入らないが取り込みには入りうる）。文字数は **char で数える** — バイトで切ると UTF-8 の途中で割れて panic する。

正規化は `core::normalize_exercises` / `core::set_pins` が `clean_pins` を共有する。**2 経路に分けて書かない** — 食い違うと「画面で消えたはずの値が取り込みで生き返る」が起きる。

- 空白を含む要素は分割する。`normalize_routines` の「取り込んだデータを trim しない」規則とは矛盾しない。あちらが守るのは**利用者が書いた自由記述の中身**で、こちらが守るのは「1 要素 = 空白を含まない 1 個の値」という**構造の不変条件**（TSV のセル内区切りが空白なので、崩れると往復が一致しない）
- **重複は消さない。**「シート高 3 / バー位置 3」は正当な入力
- **並べ替えない。** `Vec` の順が「上から下へ触る順」そのもの

### 2. 入口を増やさない。種目メモと同じトグル 1 つで開く

`＋ メモ` を押すと、種目メモ・全セット行のメモに加えて**ピン欄も一緒に開く**。ピン専用のトグルもアイコンも作らない。

これで**新しい 44px のタップ標的が 0 個**になり、カードの高さが 1px も増えない。[メモは種目カードのトグル 1 つで開き、閉じても薄字で残す](exercise-and-set-notes-behind-one-toggle.md) が「例外は `.card-foot` だけ」と測った予算を、1 つも消費せずに済む。

フッタのラベルは `＋ メモ` のまま変えない。393px 幅で「この日から外す」91px +「＋ メモ」58px +「今日 1,080」73px の間隔 58px は同 ADR が測った値で、ラベルを伸ばすと破壊的操作との距離が縮む。

### 3. 位置はセット行群の下・種目メモの上

読み順が「準備（ピン）→ 観測（メモ）」になる。`.last-row` の直下に置かないのは同 ADR 決定 4 と同じ理由で、12px `--muted` の行が前回の記録の続きに読めるため。

すぐ下の種目メモとは**先頭の「ピン」ラベルの有無**で読み分ける。同 ADR は「字下げの有無だけで読ませ、ラベル文字は要らない」としたが、あれはメモ 2 つ（行のメモ / 種目のメモ）が同じ語で呼べるからで、ピンは別の語を持つ。ラベル 1 語で足りるなら足す。

入力欄は `type="text"` + `inputmode="decimal"`（[数値入力に `type="number"` を使わない](text-input-not-number.md)）。`kb_focus` / `kb_blur` は必須。

### 4. 閉じている間もピンは薄字で読める

`ピン 3・5・2` を 12px + `var(--muted)` で出す。`.ex-note-read`（種目メモ）と同じ段・同じ左端。

**これが「タップして開く」より速い。** マシンの前に立った利用者はカードを見た時点で番号を読み終えていて、タップが 1 回も要らない。開くのは値を直すときだけ。

**`opacity` は使わない**（非テキストの 3:1 を割り、ダークで消える）。

### 5. 削除は ✕、当たり判定は 44px のまま

チップ内の ✕ は `.icon-btn` の 44px 角を縮めない。**静かにするのは色と文字サイズだけで、当たり判定ではない**（[破壊的操作は静止時に警告色を持たない（カード削除をフッタへ畳む）](destructive-affordance-quiet-at-rest.md)）。393px 幅では 3 個 / 行で折り返す。

列間 10px とチップ内 2px の 5 倍差で「✕ がどのチップのものか」を間隔だけで読ませる。

**並べ替えは持たない。** カード内には既に 2 つのドラッグ・スコープ（`.card-head` / `.set-no`）があり、3 つ目を入れると `Slots` の模型がもう 1 セット増える。要素は 2〜4 個なので ✕ → ＋ の 2 タップで足りる。

### 6. 開閉状態は `storage::UiState` に入れない

`note_open` に相乗りしているので自動的にそうなる。種目ごとの開閉は `ExerciseId` の集合 = `Db` 参照になり、[UI の状態を `Db` に入れず別キーに置く](../storage/ui-state-in-separate-key.md) の前提から外れる。

### 7. TSV に `ピン` 列（13 列目）を足す

書かないと**機種変更でピンだけ消える**。[表計算で開ける TSV で書き出す](../storage/tsv-export-for-spreadsheets.md) が「落ちてよいのは名前から作り直せるものだけ」（色・並び順・`archived`）としているのに対し、ピンは**どこからも再構成できない利用者の入力**。`メニュー` 列を足したときとまったく同じ理由。

進化規則どおり末尾に足すだけで、既存 12 列の意味は変えない。取り込みは名前で引き、この列を持たない古いファイルも今までどおり読める。

**その種目がファイル中で最初に現れた行にだけ書く**（体重・種目メモの「使ったら空にする」と同じ手）。毎行書くとシートで同じ文字列が縦に伸び、行数ぶん容量も増える。

種目マスタ行の「手つかずのプリセットは書かない」判定に `pins.is_empty()` を足した。**足さないと、記録にもメニューにも出てこないプリセットに付けたピンだけが黙って消える。**

### 8. 取り込みは上書きしない / 空なら埋める

`merge_db` の `fill_pins` と `parse_tsv` の `take_pins` の両方で、**手元のピンが空のときだけ**入れる。

★ `merge_db` 側が**この機能の成否を分ける**。プリセットは固定 ID を持つので、新品端末への復元は必ず「ID 一致」の枝を通り、その枝は取り込み側の `Exercise` を丸ごと捨てていた。ここを直さないと、記録は全部戻るのにピンだけが落ちる。

上書きしないのは [取り込みは「足すだけ」に固定する](../storage/import-is-merge-only.md) と、マシンが**端末ではなくジムに紐づく**から。上書きすると引っ越し先で入れ直した値が古いファイル 1 枚で巻き戻る。`Conflict` は積まない（`order` / `archived` を黙って落としているのと同じ粒度）。

### 9. 設定タブの種目編集シートには置かない

`ExerciseEditor` が担当するのは「種目マスタの同一性と可視性」（名前 / 部位 / アーカイブ）で、ピンは「そのマシンをどう物理的にセットするか」。層が違ううえ、あれはモーダルシートの中で**マシンの前で開く場所ではない**。

入口が 1 つなら、同じフィールドに書き込む `RwSignal` のミラーも 1 本で済む。

## 理由

**「その日のこと」と「その種目のこと」を、カードの上下で分ける。** メモが 2 つとも日に属しているのに 3 つ目だけ種目に属するのは分かりにくい。位置（セット行群の下・メモの上）とラベル（「ピン」の 1 語）の 2 つで区別を作り、色は使わない — `--muted` は 1 つしか無く、[メモは種目カードのトグル 1 つで開き、閉じても薄字で残す](exercise-and-set-notes-behind-one-toggle.md) が既にそれを使い切っている。

**入口の数はカードの高さそのもの。** 1 日 5〜8 枚並ぶ画面では、44px の標的 1 個が 220〜352px の縦に化ける。「トグルを増やさない」は見た目の趣味ではなく、トレ中のスクロール量を決める設計制約。

**閉じたまま読めるなら、開く必要が無い。** 決定 4 は決定 2 の裏返しでもある。静止時に読めるからこそ、入口を 1 つに畳んでも情報は失われない。

## 結果（トレードオフ）

**`＋ メモ` のラベルが実態より狭い。** 押すとピン欄も開くが、ラベルは「メモ」としか言わない。フッタの間隔予算を守るほうを採った。

**iOS のテンキーから英字ラベルは打てない。** `inputmode="decimal"` なので `A` / `赤` は画面から入力できない。型が `String` なのは**取り込んだ値を落とさない**ためで、キーボードは 99% を占める数字の速度に倒した。

**ピンとメモの両方があるカードは 12px 薄字が 2 行並ぶ。** ラベルの有無で読み分けるが、同 ADR 決定 4 が避けた「トークンが同一な行の連続」に片足を踏んでいる。

**TSV が 13 列になる。** 既存のシートで列幅や数式の範囲を設定していた人は作り直しになる。

**リロードするとピン欄は閉じる。** 薄字が残るので情報は失われない（`note_open` と同じ）。

**ピンの並べ替えが無い。** 順を直すには ✕ → ＋ の 2 タップ。

## 検討した代替案

**種目名の横（ヘッダ右端）にアイコンを置き、タップで開く。** 当初の要望はこの形だった。`e2e/smoke.spec.mjs` の `.card-head button` が 0 件という契約が却下する。回避するには `routine.rs` の `.rtn-grab` 方式（掴み口を内側に閉じ込め、ボタンは外の兄弟）でヘッダを割る必要があり、ヘッダの高さが 24px → 44px（カード 5 枚で 100px）に伸び、掴み口が 44px 狭くなり、旧「カード削除の入口」の事故地点と同じ列に標的が戻る。

**フッタに 4 個目のボタンを置く。** 393px 幅で `space-between` の空きが 58px → 約 35px に詰まり、同 ADR が事故として挙げた「41px しか離れていない」より破壊的操作に近づく。フッタの 3 者が全部「その日のもの」なのに、ピンだけスコープが違うという読み分けの問題も残る。

**`.last-row`（前回の記録）の行末に置く。** 12px `--muted` の実績表示にコントロールが混ざり、カードの読み順に割り込む。前回の記録が無い日は `前回 —` の 1 語しか無く、置き場所として不安定。

**`Vec<u32>` にする。** `7.5` 刻みと記号ラベルのマシンを表現できない。入力途中の空文字も持てず、パースを 1 段挟むぶん「入力中に文字が消える」面が増える。

**閉じているときは数値を出さず、アイコンの色だけで有無を伝える。** 「あまり目立たない形で」には合うが、マシンの前で 1 タップ余分にかかる。薄字 1 行のコストのほうが安い。

**TSV に列を足さない。** 機種変更でピンだけ消える。`archived` が既にその状態だが、あれは画面から復元できる（アーカイブし直せる）のに対し、ピンは元の値がどこにも残らない。

**設定タブの種目編集シートにも編集口を置く。** アーカイブ済み種目のピンを直せなくなる点は本当の穴だが、記録タブに出ない種目のマシン設定を直したい状況が想像できない。要望が出たら 1 行で足せるので、この判断は安く反転できる。
