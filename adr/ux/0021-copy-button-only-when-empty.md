# ADR-0021: 「前回をコピー」はセットが空のときだけ出す

- **状態**: 採用
- **日付**: 2026-08-08
- **カテゴリ**: ux
- **関連**: 日単位のコピーは [0037](0037-copy-whole-day-menu.md)（本 ADR の「空のときだけ出す」判断をそのまま日単位へ広げている）

## 背景

要件は「前回のレップ数、セット数を簡単に参照できて、コピーもできる」。「コピー」の解釈を利用者に確認したところ、**「前回セットをプリフィル」のみ**が選ばれた（1 セットずつ複製、テキストでクリップボードへ、は選ばれず）。

当初の設計は種目カードに「前回をコピー」ボタンを常時表示するものだった。しかしこれには未定義の挙動が複数残っていた。

- 既に 2 セット入力した後に誤タップしたら、**置換**なのか**追記**なのか
- 置換なら入力済みデータが消える（undo なし）
- 追記なら重複行ができる
- 前回が存在しない初回のボタンをどう扱うか

## 決定

**「前回をコピー」ボタンは、その種目の今日のセットが空のときだけ表示する。**

前回が存在しない場合は「前回 —」と表示してボタンを出さない。

## 理由

表示条件を「セットが空のとき」に限ると、3 つの問題が同時に消える。

1. **置換か追記かの曖昧さが消える。** 空にしか出ないので常に「流し込む」で一意
2. **誤タップで入力済みセットを消す事故が起きない。** 消すものが無い
3. **undo が不要になる。** 破壊的な操作が存在しない

そのうえで UI 要素が 1 つ減るので、要件が唯一デザインについて指定した「非常にシンプル」にも寄る。

利用実態とも合っている。「前回をコピー」を押すのは種目カードを追加した直後であり、セットを打ち込んだ後に押したい場面はない。

## 結果（トレードオフ）

- 「入力し始めたけどやっぱり前回どおりにしたい」場合はボタンが出ない。セット行を全部消せば再び出るので、回復手段はある。
- ボタンの表示・非表示が切り替わるので、E2E で両状態を検証する（smoke 5: 空のときプリフィルされる / セットが入っているとボタンが出ない）。
- 「前回」の定義は `last_log_before(db, ex, before)` で「指定日より**厳密に**前で最も新しい記録」とした。今日の入力中も、過去日を編集中も、正しく前回を指す。

## 検討した代替案

**常時表示 + 確認ダイアログ**: 誤タップ事故は防げるが、最頻の操作に確認を挟むのは煩わしく、「非常にシンプル」に反する。却下。

**常時表示 + 追記**: 破壊はしないが重複行ができ、結局ユーザーが消す手間が増える。却下。

**1 セットずつ複製する「+」ボタン**: 同じ重量で回数だけ変えるときに速い。利用者の選択に含まれなかったので v1 では入れない。
