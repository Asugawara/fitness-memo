# 記録タブ: 種目を外す / メモを開閉 / 外す確認 で視界が飛ばないようにする

- **状態**: 採用
- **日付**: 2026-09-21
- **カテゴリ**: ux
- **関連**: [メモは種目カードのトグル 1 つで開き、閉じても薄字で残す](exercise-and-set-notes-behind-one-toggle.md)（決定 4「開いた瞬間フッタが下がる」に対処）, [記録タブのカードとセットをドラッグで並び替え、`Vec` の並びをそのまま保存する](drag-to-reorder-in-record-tab.md)（`card_order` / DOM id の作法を継ぐ）

## 背景

記録タブ（`src/views/day.rs`）はページ全体（`window`）がスクロール容器で、カードの高さが**一瞬で**変わる操作が 3 つある — 種目を外す（空カード / 中身ありカードの確認箱）、メモの開閉。どれもスクロール位置を補正していなかった。`scrollY` が据え置かれるので、縮んだ分だけ下の内容が上へ滑り込み、利用者は「押した種目ではない場所」を見ることになる。

主対象は iOS Safari（standalone PWA）。WebKit には scroll anchoring が無いので生のジャンプが出る。Chromium は `overflow-anchor: auto` で部分的に隠すため、既定の E2E（Chromium）では症状が再現しにくい。

## 決定

1. **途中の種目を外す**: 外した位置に来たカード（= 直下）を画面上端へ（`scroll-margin-top` 12px）。
2. **最後の種目を外す**: 何もしない（ブラウザのクランプに任せる）。「直上を先頭へ」は直上が高いときだけ上へ飛んで合計が消えるので却下。
3. **メモを開く**: カード上端は固定のまま。開いた結果「メモ」ボタンが sticky の帯の裏に隠れるときだけ、隠れた分だけスクロールして見せる。収まっていれば 1px も動かさない。
4. **メモを閉じる**: 押した「メモ」ボタンの画面上の位置を固定する（カードは指の上方向に縮む）。そのうえでカードの見出しが画面外に残るときだけ、カードを `nearest` で収める。カードが「見える領域」より高いときは `nearest` の規則どおり下端揃えになり、ボタンは帯の上に残る。
5. **外す確認箱**: 画面最上端へ飛ばすのをやめ、隠れているぶんだけ出す。フッタは画面に残り「はい」が指の近くに出る。
6. 本番 CSS の `overflow-anchor` は触らない（Chrome 利用者の挙動を E2E の都合で変えない）。E2E 側で `body{overflow-anchor:none}` を注入して iOS の症状を再現し、注入なしの Chromium 実行も 1 組置いて anchoring との共存を固定する。

## 理由

**閉じるときボタンを固定するのは「指の下が動かない」が最優先**で、縮む方向を上にすれば見出しは自然に下りてくる。開くときに固定しないのは、固定すると見出しが上へ消えてしまうから（カードが伸びる方向は下だけ）。

**`nearest` + `scroll-margin` は宣言的で WebKit と同じ規則。** JS で sticky の帯の高さを測る方式にすると `.kb-open`（キーボード対策でタブバー/帯を隠す状態）で 0 になって暴走する。CSS 変数（`--reveal-bottom`）にすれば `.kb-open` 中は単に余分に空くだけで壊れない。

**viewport 座標の差分で測る理由。** Chromium の scroll anchoring は本番で有効のままなので、閉じたときに Blink が先に `scrollY` を補正することがある。補正量を文書座標の差分（`rect.top + scrollY`）で測ると、anchoring が同じフレームで先に足した分を二重に足してボタンが下へ飛ぶ。viewport 差分なら、anchoring が既に保っていれば差分は 0 になり何もしない。

**見出しが見えているときは `nearest` を呼ばない理由。** フッタ下端はカードの margin box 下端よりかなり上にあるので、無条件に呼ぶと帯の直上に居るだけのカードまで数十 px 動いてしまう。

**Leptos の microtask → rAF の順序。** click ハンドラの中で `viewport_top` を同期に呼べば signal 更新前の layout を測れる。DOM 更新は click ハンドラのタスク末尾（`queueMicrotask`）で終わるので、次の rAF はその更新後の layout を見る。同じ paint に補正が乗る。

## 結果（トレードオフ）

- 「はい」を押した指の座標に、先頭へ来た次カードの内容が来る残留ハザードがある。「はい」は左寄せ、✕（`remove-set`）は右端で列が違うが、内容依存なので構造的な保証は無い。
- 閉じたカードが領域より高く見出しが画面外のときは、`nearest` が下端揃えになりボタンが帯の直上まで下がる（見出しは出ない）。
- `--reveal-bottom` の 82px（8 + 66 + 8）は `.add-wrap` の高さと二重管理。E2E（V5）で釘付けしている。
- 開くときフッタが下がる挙動そのものは残る（隠れていなければ何もしない、が下がること自体は変えていない）。
- 実機（iOS Safari）での目視は未確認。

## 検討した代替案

- **次カードの画面位置を保つ Blink 式の補正**（外す操作全般）。動きは小さくなるが、利用者が明示的に「下の種目を先頭へ」を選んだので採らない。
- **最後のカードを外したとき直上を先頭へ**。直上が高いときだけ上へ飛んで合計が見えなくなる。
- **メモを開くときもボタンの位置を固定する**。固定すると見出しが上へ消えてカードの文脈を見失う。
- **メモを閉じるときカードが収まっていれば何もしない**。フッタの見た目位置がケースによって動いたり動かなかったりして予測できなくなる。
- **本番の `overflow-anchor: none`**。E2E の都合で Chrome 利用者の挙動を変えることになる。
- **JS で sticky の帯の高さを測る**。`.kb-open` で帯が消えると 0 になり補正が暴走する。
- **文書座標（`rect.top + scrollY`）の差分で測る**。Chromium の scroll anchoring と二重補正になる。
