# ADR-0022: トレ前情報とトレ中情報を排他表示にする

- **状態**: 採用
- **日付**: 2026-08-08
- **カテゴリ**: ux
- **関連**: [ADR-0021](0021-copy-button-only-when-empty.md), [ADR-0006](../data-model/0006-at-optional-same-day-only.md)

## 背景

要件が唯一デザインについて指定したのは「非常にシンプルなデザイン」だけである。一方で今日タブに載せたい情報は複数ある。

- 最後のトレーニングからの経過時間（明示要件）
- 部位ごとの経過時間（v1 追加機能として選ばれた）
- 体重・体調メモ（同）
- 種目カード（前回の記録 + 今日のセット入力）

全部を常時並べると、セットを入力している最中にも「最後のトレーニングから 2日5時間」という巨大な数字が画面上部を占める。これはトレーニング中には無用な情報である。

## 決定

**その日のログが空か否かで、経過時間ヒーローと部位チップの表示を切り替える。**

ログが空のとき（トレ前）は大きく見せる。

```
8/8 (金)                                    今日

        最後のトレーニングから
              2日5時間

  胸 3d   背中 6d   肩 —   腕 4d   脚 1d   体幹 8d

  ＋ コンディション
              [ 種目を追加 ]
```

1 種目以上追加されたら（トレ中）1 行に畳む。

```
8/8 (金)                                    今日
最後から 2日5時間 · 胸 3d
```

**畳んだ側に出す部位チップは「今日やった部位」だけ**にする。過去日を編集中はヒーロー自体を出さない。

## 理由

- **画面の目的が時間で切り替わる。** トレーニング前は「前回いつやったか / どの部位が空いているか」を眺めて今日のメニューを決める。トレーニング中は「前回の数字」と「今日の入力欄」しか見ない。同じ画面が 2 つの目的を順番に持つので、排他にするのが素直である。
- **情報を消すのではなく畳むので、必要なら読める。** 経過時間は 1 行になっても残っている。完全に消すと「今日は何日ぶりだったか」を確認できなくなる。
- **「非常にシンプル」を要素数ではなく「同時に見えるものの数」で解釈した。** 機能を削るのではなく、その瞬間に不要なものを小さくする。
- **経過時間の計算基準を「今日を始める前」に固定した。** ここが実装上の要点である。素直に `elapsed_since_last(db, now, today)` を呼ぶと、**1 セット入れた瞬間に「たった今」に化けて意味を失う**（今日のログが最新セッションになるため）。今日のセッションを除いた snapshot を作り、それに `core` の関数を当てている。

```rust
let before_today = Memo::new(move |_| {
    let today = dates.today.get();
    db.with(|d| {
        let mut snapshot = d.clone();
        snapshot.sessions.remove(&core::date_key(today));
        snapshot
    })
});
```

- **`Memo` にしているので、今日のキー入力では下流が再評価されない。** `Db` は入力 1 文字ごとに変わるが、`before_today` は今日のセッションを除いた値なので**入力しても値が変わらず**、ヒーローと部位チップの再描画が起きない。パフォーマンスと表示の安定の両方に効いている。
- **前回比をセッション中に表示しない**のも同じ判断である。途中の不完全な合計を前回の完了セッションと比べても意味がない。比較は推移タブで行う。
- **部位チップの濃淡は単色系に統一した。** 部位カラー × 経過濃淡の二重符号化にすると、色から意味が読めなくなる（赤が「胸」なのか「久しぶり」なのか判別できない）。チップは `--chip-0`〜`--chip-3` の単色系で新しさだけを示し、部位カラーはカレンダーのドットと種目シートの見出しに残した。

## 結果（トレードオフ）

- **`Db` のクローンが `before_today` の再計算ごとに発生する。** `dates.today` か `Db` の構造（今日以外）が変われば `Db` 全体をコピーする。10 年分で 1 MB 程度なので実測上問題ないが、素直な実装ではない。`core` 側に「特定日を除外して計算する」引数を足せばクローンは不要だったが、`core.rs` の API に UI 都合の引数が入るのを避けた。
- **画面が入力開始のタイミングで大きく動く。** 1 種目追加した瞬間にヒーローが畳まれるので、レイアウトが跳ねる。アニメーションを入れていないので唐突ではあるが、「モードが変わった」ことが伝わる副作用もある。
- **畳んだ側のチップが「今日やった部位」なので、意味が変わる。** トレ前は「全部位の経過」、トレ中は「今日やった部位の（今日を始める前の）経過」を示す。同じ見た目で意味が違うのは分かりにくい可能性がある。トレ中は「今日はここをやっている」という確認として機能すると判断した。
- **過去日を編集中はヒーローと部位チップが出ない。** 「今」の情報なので過去日には意味がないが、その日の文脈情報（その日までの経過）は失われる。過去日は入力のための画面と割り切った。
- 表示の分岐が増えるので E2E で両状態を見る必要がある（`data-testid="hero"` が `folded` クラスを持つか、`group-chip` の数が 6 か今日の部位数か）。

## 検討した代替案

**全部常時表示する**: 実装が最も単純で、レイアウトが動かない。しかしセット入力中に不要な情報が画面の 3 分の 1 を占め、種目カードを見るのにスクロールが必要になる。「非常にシンプル」に反する。却下。

**経過時間を別タブ / 別画面に置く**: 今日タブが入力専用になり最もシンプルになる。しかし「最後のトレーニングからの経過時間」は**アプリを開いた瞬間に見たい情報**であり、タブを切り替えて見るものではない。要件の位置づけと合わない。却下。

**折りたたみを手動トグルにする**: ユーザーが制御できる。しかし操作が 1 つ増え、状態を永続化するか毎回リセットするかの判断も必要になる。ログの有無という既にある状態で自動的に決まるので、手動にする理由がない。却下。

**トレ中はヒーローを完全に消す**: 最もシンプル。しかし「今日は何日ぶりか」を入力中に確認できなくなる。1 行なら場所を取らないので畳む方を選んだ。

**部位チップを部位カラーで塗る**: 部位の識別が容易になる。しかし経過の新しさも色で示す必要があるため二重符号化になり、どちらの意味なのか読めなくなる。却下。
