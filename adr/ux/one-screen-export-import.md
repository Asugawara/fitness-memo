# 書き出し / 読み込みを 1 画面に畳み、逃げ道 UI を常設しない

- **状態**: 採用
- **日付**: 2026-08-15
- **カテゴリ**: ux
- **関連**: [書き出しを TSV にし、保存形式（JSON）と分ける](../storage/tsv-export-for-spreadsheets.md), [取り込みは「足すだけ」に固定する](../storage/import-is-merge-only.md), [`<input type="file">` を隠してボタンから開く](hidden-file-input-behind-a-button.md), [書き出しは共有シートを主経路にし、iOS では `<a download>` を使わない](../storage/share-sheet-over-download.md)（textarea の常設を撤回）, [パース失敗時は上書きせず退避する](../storage/quarantine-on-parse-failure.md)（退避データの UI 救出を撤回）

## 背景

シートが「万一のための逃げ道」で膨らんでいた。

- 「書き出し」/「読み込み」のペイン切替（segmented tabs）
- 折りたたみ「うまくいかないとき」— コピーボタン + **JSON 全文の textarea**
- 折りたたみ「貼り付けで読み込む」— textarea + 「読み込む」
- 折りたたみ「**保管中のデータ（N 件）**」— `.bak-` / `.pre-` / `.newer-` の一覧と「中身を見る」「削除」
- 取り込みモードの 2 択「置き換える」/「足すだけ」
- 控えが取れなかったときの「もう一度押すと実行します」（強制 2 度押し）

**書き出しに最短 3 タップ、読み込みに最短 5 タップ**かかっていた。しかも 5 本の逃げ道は「常時見えている」コストを毎回全員に払わせていた。「筋トレ中に追加するので、基本的には本当に最短距離で」というこのアプリの前提から外れている。

## 決定

**1 画面に「書き出す」と「読み込む」を並べ、上に挙げたものを全部畳む。**

```
種目 30 ・ 記録 19 日 ・ 210 セット
[            書き出す            ]
「ファイルに保存」を選ぶと、機種を替えても残ります。表計算アプリでそのまま開けます
────────────────────────────────────
[            読み込む            ]
書き出したファイルを選びます。今ある記録は消えず、足りない分だけ足します
```

- **書き出しは 1 タップ**（共有シートが開く）
- **読み込みは 3 タップ**（読み込む → ファイル選択 → 取り込む）
- 確認状態では本文を**丸ごと差し替える**
- 「元に戻す」は取り込み直後だけ、**通知の直下**に出す

**残したもの**: 取り込み前の確認画面（現在 / 取り込み後 / 何が増えるか）、取り込み直前の自動退避（`.pre-`）、直後の「元に戻す」（2 段確認つき）。

**条件付きで残したもの**: 共有に失敗したときだけ現れる「文字でコピー」。静止時の要素数はゼロ。

## 理由

### 判断基準は 1 行で書ける

**消したのは全て「稀な失敗のための常設 UI」、残したのは全て「破壊的操作を止める道具」。**

この線で切ると、迷う項目が無くなる:

| 消した | 何のためにあったか | なぜ消せるか |
|---|---|---|
| ペイン切替 | 2 つの機能を分ける | 1 画面に 2 つ置けば足りる。分けるほど内容が無い |
| JSON 全文 textarea | 共有もクリップボードも駄目な端末の最後の逃げ道 | 下記 |
| 貼り付けで読み込む | 同上（往復の片側） | 同上 |
| 保管中のデータ | 破損退避を iPhone 単体で救出する | 下記 |
| モード 2 択 | 移行と統合を分ける | [merge に固定した](../storage/import-is-merge-only.md)ので選択肢が 1 つになった |
| 強制 2 度押し | 控えが取れないまま進むのを止める | 下記 |

### textarea を常設しない

[書き出しは共有シートを主経路にし、iOS では `<a download>` を使わない](../storage/share-sheet-over-download.md) は「**textarea への全文表示は残す**」と決めていた。「Web API を一切使わないので、iOS のどのバージョン・どの表示モードでも必ず動く」から。**この撤回が今回いちばん重い判断**なので、理由を分けて書く。

- **`canShare({files})` が偽になる iOS は Web Share Level 2 非対応**、つまり iOS 14 以下相当で、[ブラウザサポートは Safari を基準にし、polyfill を入れない](../architecture/browser-support-policy.md) の外側にある
- **`Route::Clipboard` は残した。** `copy_text` は成否を Promise で返すので、share と同じ「成否が分かる経路」として質が揃っている。**textarea だけが「成否の概念が無い」経路**だった
- **TSV になったことでクリップボード経路の価値が上がった。** JSON 全文は人間には読めない塊だったが、TSV はメモアプリでも表計算でもそのまま読めて、シートに貼れば列に分かれる
- **失敗した人にだけ「文字でコピー」を出す。** 常設のコストを払わずに、逃げ道は残る

**受け入れた欠損**: クリップボードで出した文字列を**アプリに戻す口が無くなった**（貼り付け欄を消したので）。往復が閉じるのは共有シートが使える端末だけになる。全員の UX を毎日悪くして、サポート方針の外の端末のために textarea を 2 つ常設する取引は割に合わない。

### 「保管中のデータ」を消す

[パース失敗時は上書きせず退避する](../storage/quarantine-on-parse-failure.md) は「退避データを UI から読む手段がない … iPhone 単体では実質的に救出不可能」という穴を、この一覧で塞いだと追記していた。**それを再び開ける。**

- 一覧は `.bak-` / `.pre-` / `.newer-` という**内部表現をそのまま画面に出していた**。「取り込み前の控え」「読み込み失敗の退避」「新しい版のデータ」を読み分けられる利用者は、この一覧を必要としない
- **出る場面が偏っている。** 救出が要るのは「起動時に `restore-notice` が出たとき」だけ。それ以外の 99% の訪問では、意味の分からない折りたたみが 1 つ増えているだけ

**`.bak-` / `.newer-` の退避書き込みと `.pre-` の 3 世代剪定は続ける。** 消したのは読む口だけで、原本は残る。

**本来の置き場所は起動時の `restore-notice` バナー**（「以前のデータを復元できませんでした（退避済み）」）で、そこから救出導線を出すのが筋。`views/mod.rs` の担当なので**別タスクにした**。この ADR はその穴が開いていることを記録する責任を負う。

### 控えが取れなくても止めない

旧実装は `snapshot_current()` が `None` を返すと実行せず、「もう一度押すと実行します」を出していた。

これは**容量が逼迫した端末で毎回 2 タップを強いるだけ**で、結果は変わらない（利用者は 2 回押す）。止めることで防げるのは「戻せないと知らずに実行する」だけなので、**実行して結果の文言で伝える**ほうが短くて誠実。

```
取り込みました（7 日分 ・ 67 件の記録 を追加）
（控えを保存できなかったので、元に戻せません）
```

### 「元に戻す」を通知の直下へ

旧実装では読み込みペインの**末尾**にあり、どのメッセージに紐づく操作なのか読み取れなかった。通知の直下に置けば「今の取り込みを取り消す」と読める。シートを閉じたら破棄する規則は変えない（iOS の PWA は何日もレジュームされるので、残すと数日後に誤タップされる）。

### 確認中は「元に戻す」も見せない

`pending` があるとき undo ボタンを描かない。1 画面 1 判断であることに加えて、**`Pending::merged` は巻き戻す前の `db` から作ってある**ので、確認中に巻き戻されると古くなる。その状態で「取り込む」を押すと `db.set(p.merged)` が走り、**巻き戻しが 1 タップで打ち消される。**

同じ理由で `do_undo` の成功時に `pending` を捨てる。二重の防御にしたのは、片方だけ直す人が出たときに壊れ方が静かだから。

**`confirm_undo`（2 段確認の武装）も、`note` を上書きする操作では必ず解く**（書き出し / コピー / 読み込み）。解かないと、警告文だけが画面から消えて武装が残り、**次の 1 タップで無警告に巻き戻る。**

### 確認画面に「入れ替わる記録」を出す

`MergeReport::is_noop` を単独で信じてはいけない。`Conflict::SetsDiverged` は既存のログを丸ごと差し替えるのに、カウンタはどれも増えないので `is_noop` は真になる。そのまま「新しく取り込むものはありません」と出すと、**セットが入れ替わる取り込みを「何も起きない」と言って実行させる**ことになる。

判定を `change_text` に 1 本化し、`conflicts` が空でないときは「入れ替わる記録があります」と言う。併せて**衝突の一覧を確認画面（押す前）にも出す** — 実行後にだけ見せていると、「取り込んだ側のセットを採りました」を読むのが手遅れになる。

### 確認中は書き出しを見せない

`pending` があるときは本文を丸ごと差し替える。**1 画面 1 判断**にするのが理由で、確認中に誤タップで書き出しが走ると共有シートが上に被さって確認が流れる。

## 結果（トレードオフ）

- **`views/backup.rs` が 584 行 → 約 390 行**。`Pane` / `Mode` の 2 enum、`pasted` / `mode` / `force` / `backups` の 4 シグナル、`refresh_backups` と `Effect` が消えた
- **`payload` Memo を消した副産物で速くなった。** `Sheet` は常時マウントなので、`<textarea prop:value=move || payload.get()>` のレンダーエフェクトが生き続け、**シートが閉じている間も `db` が変わるたびに DB 全体を直列化していた**。今はクリックハンドラの中で 1 回だけ作る
- **`storage::backup_keys` / `remove_key` を private にした。** `snapshot_current` の剪定だけが呼ぶ
- **`.json-box` / `.backup-list` と `.sheet-body details` / `summary` の CSS を削除。** アプリ内の `<details>` はこれで全滅した（`menu.rs` は「`<summary>` は interactive content なので使わない」と明記して避けている）
- **E2E の観測点が変わった。** 旧テストは textarea の中身を読み、貼り付け欄から注入していた。今は共有シートを差し替えて `ShareData` を控え、隠した input へ `setInputFiles` する。**結果として iOS 主経路の形（`files` だけを `.tsv` で渡す）を初めて機械検証している**

## 検討した代替案

**タブは残して中身だけ減らす。** 2 つしか無いものにタブを付ける理由が無い。1 画面に収まる。

**書き出しと読み込みを別シートにする。** [取り込み前の自動退避 → 適用 → 元に戻す の分岐が 2 本になる](../ux/migrate-by-ocr-paste.md)（破棄済み ADR が同じ理由で「シートを増やさずペインを足した」と書いている）。データを失う経路が 1 本しかない、という状態は `views/backup.rs` の `apply` / `do_undo` を読めば検証できることで成り立っている。

**`<details>` を 1 つだけ残す（「うまくいかないとき」に全部まとめる）。** 折りたたみが 1 つでも、その中に「JSON 全文」「貼り付け」「保管中のデータ」が同居すると、開いた人が何を選べばいいか分からない。使う場面がそれぞれ違うものを 1 つの箱に入れるのは整理ではない。
