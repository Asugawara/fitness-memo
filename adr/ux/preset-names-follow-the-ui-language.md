# プリセット名は表示時に言語へ追従させ、改名したものだけ据え置く

- **状態**: 採用
- **日付**: 2026-08-20
- **カテゴリ**: ux
- **関連**: [プリセット名は初回投入の言語で固定し、ユーザーデータとして扱う](../storage/preset-names-are-user-data-seeded-once.md)（この ADR が置き換えた）, [言語はブラウザに従い、選んだらそれを優先する](language-follows-the-browser-then-the-setting.md), [ID を 60 bit 乱数にし、プリセットには固定 ID を与える](../data-model/random-ids-for-safe-merge.md), [TSV の見出しは UI 言語で書き、読み込みは日英どちらも受ける](../storage/tsv-header-follows-the-ui-language.md)

## 背景

[プリセット名は初回投入の言語で固定し、ユーザーデータとして扱う](../storage/preset-names-are-user-data-seeded-once.md) は
「プリセット名は初回投入の言語で固定し、言語を切り替えても一切変えない」と決めた。

実際に動かしてみると、**日本語で初期化した端末を英語にしたときに、画面のほぼ全部が
英語になるのに種目名と部位名だけ日本語で残る。** 記録タブの部位チップ（胸 / 背中 / 肩 …）も
種目カードの見出しも日本語のままで、英語で使う人にとっては「対応していない」のと同じに見える。

利用者から「プリセットは英語版も追加して、表示を切り替えられるようにしたい。
自分で追加した種目に関しては、追加したものだけでよい」という要望があった。

## 決定

**表示のときだけ言語の綴りを引く。`Db` の保存名は一切書き換えない。**

```rust
/// 保存名が、その固定 ID のプリセット名の**どちらかの言語の綴り**と一致すれば
/// 未改名なので今の言語の綴りを返す。違えば利用者が付けた名前なのでそのまま返す。
pub fn exercise_name(id: ExerciseId, stored: &str, lang: Lang) -> &str
pub fn group_name(id: GroupId, stored: &str, lang: Lang) -> &str
```

適用範囲を 3 つに分ける。

| 対象 | 挙動 |
|---|---|
| **未改名のプリセット** | 言語に追従する（「ベンチプレス」⇄ "Bench Press"） |
| **改名したプリセット** | 利用者が付けた名前のまま。二度と書き換えない |
| **自分で追加した種目・部位** | 固定 ID を持たないので素通り。常にそのまま |

**`views` からは `ex_name()` / `grp_name()` を必ず通す**（`Exercise.name` を直接描かない）。

**TSV の書き出しも表示名を使う。** 取り込みは今までどおり日英どちらの綴りでも
固定 ID に寄せるので、往復は言語を跨いでも閉じる。

**重複名チェックは表示名で比べる。**

## 理由

- **保存名を書き換えないので、前の決定の利点が全部そのまま残る。** マージは固定 ID で
  当たるので `Conflict::Renamed` が湧かないし、改名は正当な操作として守られるし、
  日英の端末のデータを混ぜても種目が割れない。**変わったのは表示だけで、データは不変。**
- **未改名の判定に両言語を見るのが要点。** 保存名は初回投入の言語のままなので、
  日本語で入った端末では常に「ベンチプレス」、英語で入った端末では常に "Bench Press" が
  保存されている。どちらの綴りも受ければ、何回言語を往復しても判定がぶれない。
  片方だけを見る実装だと「一度英語で表示した = 改名された」と誤判定しうる
  — 前の ADR が「言語を 2 回切り替えると壊れる」として却下した破綻は、
  **両言語を見ることで消える。**
- **判定は必ず「その固定 ID 自身の `Names`」と比べる。** 全プリセットを横断して
  探すと、「ダンベルプレス」を「ベンチプレス」に改名した種目が
  ベンチプレス扱いになり、英語で 2 つとも "Bench Press" になる。
  ID で引いてからその 1 件とだけ比べる。
- **TSV に表示名を書く。** 保存名をそのまま出すと、英語で使っている人のシートに
  日本語の種目名が並ぶ。書き出しの存在意義は「スプレッドシートで開いて読めること」
  （[書き出しを TSV にし、保存形式（JSON）と分ける](../storage/tsv-export-for-spreadsheets.md)）なので、
  見出しを UI 言語にした（[TSV の見出しは UI 言語で書き、読み込みは日英どちらも受ける](../storage/tsv-header-follows-the-ui-language.md)）のと
  同じ理屈が中身にも及ぶ。
- **往復は閉じる。** 解決の梯子の 3 段目（プリセット名 → 固定 ID）が日英どちらの綴りでも
  当たるので、英語で書き出したファイルを日本語の端末に入れても 0x11 に寄る。
  `merge_db` は ID 一致の枝を通るので保存名も上書きされない。
  ホストのテストで 4 方向すべてを固定した。
- **重複名チェックを表示名にしないと、同じ名前が 2 つ並ぶ。** 英語で使っている人が
  部位に "Chest" と打ったとき、保存名で比べると「胸」と衝突せず素通りして、
  画面に "Chest" が 2 つ出る。**画面で同じに見えるものは、画面で見えるとおりに弾く。**

## 結果（トレードオフ）

- **`Exercise.name` を直接描くと壊れる。** 型では守れないので、`views` には
  `ex_name()` / `grp_name()` を通す規約をコメントで置いてある。新しい表示箇所を
  足す人がここを踏み外すと、その画面だけ言語が追従しない。
- **偶然もう一方の言語のプリセット名そのものに改名すると、未改名と見なされる。**
  「ベンチプレス」を手で "Bench Press" に改名すると、日本語に戻したとき
  「ベンチプレス」に戻る。同じ種目を指す綴りなので実害が無く、判定を単純に保つほうを採った。
- **保存名が「表示されない名前」になった。** 日本語で初期化した端末を英語で使い続けると、
  `localStorage` の中身は日本語なのに画面はずっと英語になる。エクスポートも表示名なので、
  保存名を目にする経路は DevTools だけ。デバッグのときに一瞬戸惑う。
- **表示のたびに線形探索が走る。** `PRESETS` は 6 部位 34 件で、種目 1 件につき
  最大 28 回の比較。一覧の描画で数百回走るが、`&'static str` の比較なので実測に出ない
  （[読み込みと操作は実測して、何も入れないと決めた](../architecture/measure-before-optimizing-and-do-nothing.md) の基準で、
  今のところ何もしない）。
- **E2E の日本語の期待値は無傷。** `playwright.config.mjs` が `locale: 'ja-JP'` を
  固定しているので、既存 spec が見る名前は今までどおり日本語。

## 検討した代替案

**前の決定のまま（初回投入の言語で固定）**: 実装が単純で、表示とデータが常に一致する。
しかし英語で使う人の画面に日本語の種目名が並び続ける。利用者の要望に反する。却下。

**言語切替時に `Db` の保存名を一括で書き換える**: 表示・書き出し・マージの整合が
考えるまでもなく取れる。しかし他端末とマージしたときに `Conflict::Renamed` が
34 件並ぶし、「設定を触ったらデータが書き換わった」という挙動そのものが、
記録アプリとして踏んではいけない一線。却下（前の ADR と同じ結論）。

**保存名を空にして、プリセットは常に表から引く**（`name: Option<String>`）:
「未改名」の判定が不要になり、上の「偶然もう一方の綴りに改名」の曖昧さも消える。
しかし `Db` のスキーマ変更になり、保存キーの世代を切る話になる
（[保存キーを schema 世代ごとに切り、旧キーを読み取り専用で残す](../storage/storage-key-per-schema-generation.md)）。
既存ユーザー全員のデータを移行する必要があるうえ、旧版へロールバックすると
種目名が全部消えて見える。表示だけで済む話に払うコストではない。却下。

**TSV には保存名を書く**: ファイルの中身が UI の言語に依存しなくなり、往復も自明。
しかし英語のシートに日本語の種目名が並ぶという、この ADR が直そうとしている問題が
書き出しの中だけ残る。取り込みが両言語を受ける以上、表示名で書いても往復は閉じる。却下。
