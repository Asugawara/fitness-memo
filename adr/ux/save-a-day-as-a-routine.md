# その日の記録から直接メニューを作れるようにする

- **状態**: 採用
- **日付**: 2026-08-16
- **カテゴリ**: ux
- **関連**: [保存したメニューから始める（種目タブを設定タブに改める）](start-from-a-saved-routine.md)（この ADR が却下した代替案を採り直す） / [トレーニングメニューを「名前 + 種目 ID の並び」だけのデータにする](../data-model/routines-as-named-exercise-lists.md) / [1 日分のメニューは候補リストから 1 タップで丸ごとコピーする](copy-whole-day-menu.md) / [ホーム画面への追加の案内を記録タブ末尾のバナー + 手順シートにする](install-guide-banner-and-sheet.md)

## 背景

[保存したメニューから始める（種目タブを設定タブに改める）](start-from-a-saved-routine.md) は、メニューを作る場所を設定タブだけに置いた。同 ADR は「検討した代替案」で次を明示的に却下している。

> **記録タブから直接メニューを作れるようにする（「この日をメニューとして保存」）**: 導線としては最短だが、記録タブに「今日を記録する」以外の操作が増える。メニューを作るのは一度きりで、トレ中の操作ではない。将来足すとしても、まず設定タブ側だけで足りるかを見てからにする。今回は却下。

**「まず設定タブ側だけで足りるかを見てから」と書いた、その次の判断がこれである。** 足りなかった。

設定タブだけだと、メニューを作る手順はこうなる。

1. 記録タブで今日のトレーニングを終える
2. 「この構成は良かった」と思う
3. 設定タブへ移る
4. 「＋ メニューを追加」を押す
5. **さっき自分がやった 5 種目を、28 種目のピッカーから思い出しながら選び直す**

5 が丸ごと無駄で、しかも間違える。目の前に正解（その日のカード）が並んでいるのに、それを見ながら別の画面で打ち直している。これは、この機能全体が潰そうとした「毎回カレンダーを遡って正しい日を探し当てる」と同じ形の手数である。

## 決定

**記録タブの選択日に記録があるとき、「＋ この日をメニューにする」を出す。** 押すと設定タブとまったく同じメニュー編集シートが、**その日の種目を初期選択にした状態**で開く。

- 置く場所は「種目を追加」より**下**（折り返しの下）の控えめなリンク
- 対象は選択中の日。カレンダーで日を選べるので、**任意の過去日**をメニューにできる
- 初期選択に入れるのは `core::day_exercises`（= `copyable`）を通した種目。**アーカイブ済みは入れない**
- シートの中で種目を足し引きしてから保存できる（同じ編集シートなので当然そうなる）

## 理由

### なぜ却下した判断を覆すのか

却下の根拠は 2 つあった。それぞれ今どうなったかを見る。

**「記録タブに『今日を記録する』以外の操作が増える」** — これは正しい懸念だが、**置き場所で解ける**ことが分かった。[ホーム画面への追加の案内を記録タブ末尾のバナー + 手順シートにする](install-guide-banner-and-sheet.md) が既に同じ問題を「記録の邪魔をしないよう折り返しの下に置く」で解いている。トレ中に見える範囲（カレンダー → カード → 種目を追加）には 1 ピクセルも入らない。

置き場所は `InstallBanner` に倣って **`<section class="day">` の外**（`views::calendar`）にした。`.add-wrap`（「種目を追加」）は `position: sticky` で包含ブロックが `.day` なので、`.day` の中で帯より後ろに置いた要素は `.day` の末尾までスクロールしきるまで帯の下に潜りうる。外に出せば帯は `.day` で止まり、構造的に干渉しない。位置関係は E2E で固定した。

**「メニューを作るのは一度きりで、トレ中の操作ではない」** — 前半は正しく、後半が誤りだった。作るのは一度きりだが、**作りたくなる瞬間はトレ直後**である。そこが記録タブなのだから、導線もそこにあるのが自然だった。「トレ中の操作ではない」を「記録タブに置かない理由」にしたのが、当時の推論の穴。

### なぜ設定タブに「記録から作る」を置く形にしないのか

設定タブの「メニューを追加」シートの中に「最近の記録から」の一覧を置く案も採れた。記録タブを 1 バイトも触らずに済む。

採らなかったのは、**日を選び直す手間が戻る**から。「8/12 と 8/10 のどっちが良かった日だっけ」をリストの 2 行から思い出すのは、カレンダーを遡るのと同じ作業である。記録タブなら「今まさに見ている日」が対象なので、選ぶ操作そのものが要らない。

### なぜ判定を `cards` ではなく `core::day_exercises` にするのか

カードには「種目を追加で出しただけで、まだ 1 セットも打っていない」ものが混ざる（`views::day` の `pick()`）。`cards` が空でないことを条件にすると、**押しても何も保存されないリンク**が出る。`day_exercises` は `copyable` を通すので、[1 日分のメニューは候補リストから 1 タップで丸ごとコピーする](copy-whole-day-menu.md) の候補・`copy_day` と同じ集合になる。

系として、その日を丸ごとコピーした結果と、その日から作ったメニューを開いた結果は**種目単位で一致する**（数値は種目ごとの直近から入るので別）。

### なぜアーカイブ済み種目を入れないのか

`copyable` と同じ規則。アーカイブ済みは「種目を追加」シートにも出ないので、メニューに入れても記録タブでは開かない行になる（`core::expandable` が外す）。作った直後に「アーカイブ済みの 1 種目は記録タブに出ません」と出る状態を、こちらから作りにいくことはない。

### なぜ編集シートを共有するのか

`RoutineEditor` を `views/routine.rs` へ切り出し、設定タブと記録タブの両方から開く。専用の簡易シート（名前 + その日の種目だけ）を書く案もあったが、**保存の検証（名前必須・種目 1 つ以上）・trim・並び順が 2 実装に割れる**。違いは「初期選択」と「削除ボタンの有無」だけなので引数で吸収できる。

副産物として、**その日やった bonus 種目を外す / その日やらなかった種目を足す**が同じ画面でできる。専用シートだと、これをやるには保存してから設定タブで開き直すことになっていた。

### なぜ「開いた瞬間の種目集合」を握るのか

シートの状態を `bool` にして中で `Db` から引き直す形にすると、シートを開いたまま裏で `Db` が動いたとき（デバウンス保存、visible 復帰の取り込み）に**選択が入れ替わる**。`Option<Vec<ExerciseId>>` を持って開いた瞬間の集合を握る。

## 結果（トレードオフ）

- **記録タブに「記録する」以外のボタンが 1 つ増えた。** 折り返しの下・非 sticky・記録がある日だけ、の 3 条件で邪魔にならない位置に留めているが、増えたことは事実として書いておく。次に何かを足したくなったときは、ここが 2 つ目になることを踏まえて判断すること
- **メニューは記録の複製ではなく、その時点のスナップショット。** あとでその日の種目を増やしても、作ったメニューは追随しない（メニューは種目 ID の並びしか持たない）。追随させるには「この日をメニューにする」をもう一度押して作り直すか、設定タブで編集する
- **同名のメニューが増えやすくなった。** 同じ構成の日を 2 回メニュー化できる。名前は必須なので「（名前なし）」が並ぶことはないが、「胸の日」が 2 本になることはある。設定タブから 1 タップで消せる
- 記録がある日にしか出ないので、**未来日には出ない**（未来日にはそもそもカードが無い）。「前回のメニューから始める」の未来日ガードとは別経路だが、結果は揃う

## 検討した代替案

**設定タブの「メニューを追加」シートに「最近の記録から」を置く**: 記録タブを触らずに済むが、日を選び直す手間が戻る（上記）。却下。

**両方に置く**: どちらの場面でも最短になるが、入口が 2 つに増えるぶん UI も実装も一番大きくなる。まず記録タブ側だけで足りるかを見る。却下（この判断自体、前 ADR と同じ形なので、足りなければまた採り直す）。

**名前を自動で付ける（「8/12 の記録」など）**: 保存が 1 タップで終わるが、日付を名前にしたメニューは候補リストで「最近の記録から」と見分けが付かなくなる。メニューの同一性は名前なので、そこは利用者に決めてもらう。却下。

**セットの数値も一緒に保存する**: 「その日をそのまま再現する」ならこうだが、[トレーニングメニューを「名前 + 種目 ID の並び」だけのデータにする](../data-model/routines-as-named-exercise-lists.md) が「目標値を持つと記録が伸びても腐る」で却下済み。数値が要るなら「最近の記録から」でその日をコピーすればよい。却下。
