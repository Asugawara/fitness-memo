# セット削除は確認を挟まない（カード削除の確認は残す）

- **状態**: 採用
- **日付**: 2026-08-09
- **カテゴリ**: ux
- **関連**: [セット追加は直前行の重量をコピーして回数欄へフォーカスする](set-entry-prefill-and-focus.md)（改訂）, [破壊的操作は静止時に警告色を持たない（カード削除をフッタへ畳む）](destructive-affordance-quiet-at-rest.md)（射程を明確化）

## 背景

実使用のフィードバックは **「セットの削除をするたびに確認が入るのは、さすがに不便」**。

行の ✕ を押すと、中身のある行では `.row-confirm` が行内に折り返して開き、「削除 / やめる」をもう 1 タップ要る。

踏む回数を数えると重さが分かる。セットは 1 種目で 3〜5 行、それが 1 日 3〜5 種目。削除は「行を足しすぎた」「重量を打ち間違えて行ごと作り直す」で日常的に出る。**息が上がった状態で 2 タップ、しかも 2 タップ目は 12px の文字**（`.row-confirm` の `font-size: 12px`）。

対して、確認が守っているものは **1 行分の重量と回数**でしかない。誤爆しても打ち直しは数秒で、[セット追加は直前行の重量をコピーして回数欄へフォーカスする](set-entry-prefill-and-focus.md) の重量プリフィルが効くので実際には回数を打つ 1 手しかかからない。**確認のコストのほうが、守っているものより高かった。**

## 決定

**セット削除は確認を挟まず、✕ の 1 タップで消す。中身の有無で分岐しない。**

`pending_remove` シグナル、`request_remove`（空判定）、`.row-confirm` の描画と CSS をすべて削除した。残るのは `remove_row` だけ。

```rust
let remove_row = move |key: u32| {
    rows.update(|rs| rs.retain(|r| r.key != key));
    // 行が 0 本になると入力欄ごと消えるので、必ず空行を 1 本残す
    if rows.with_untracked(Vec::is_empty) {
        let key = fresh_key();
        rows.update(|rs| rs.push(Row::blank(key)));
    }
    commit();
};
```

**[セット追加は直前行の重量をコピーして回数欄へフォーカスする](set-entry-prefill-and-focus.md) の「重量プリフィル済みで回数が空の行は中身なし扱いで確認を挟まない」という判定は、この決定に吸収されて不要になった。** あの判定は「確認が存在する」前提の例外規定だったので、確認そのものが無くなれば書くことが無い。

**カード削除（`confirm_close`）の確認は残す。** [破壊的操作は静止時に警告色を持たない（カード削除をフッタへ畳む）](destructive-affordance-quiet-at-rest.md) の `.warn-box` はそのまま。

## 理由

**スコープが違うので、確認の有無を分けるのは規則違反ではなく規則そのもの。** 1 セットは数秒で打ち直せる。1 種目まるごとはその日のその種目の記録が全部消える。同じ「破壊的操作」でも失う量が 1 桁違うものに同じ作法を強いるほうが雑で、これまで「行にもカードにも確認がある」という見た目の対称性のほうを優先していた。

[破壊的操作は静止時に警告色を持たない（カード削除をフッタへ畳む）](destructive-affordance-quiet-at-rest.md) で「そろえるのは作法であって、見た目ではない」と書いたが、**射程は「静止時に警告色を持たない」までで、「確認を挟む / 挟まない」までは含まない。** そこは今回はっきりさせた。静止時の色の規則（入口は常に `--muted`、`--warn` は `.warn-box` だけ）はそのまま生きている。

**確認を外したので、離す設計が唯一の事故対策になった。** ✕ は `margin-left: auto` で右端へ寄せたうえ、`border-left` と `padding-left: 12px` で回数欄から離してある（`.set-row .icon-btn`）。ここを詰めると回数欄の直後（gap 6px）に来て一気に誤爆しやすくなる。**確認という後段の網が無くなったぶん、この距離は前より重い。**

## 取り消しを付けなかった

「即削除 + 数秒の『元に戻す』トースト」は検討して見送った。

トーストというパターンがアプリのどこにも無い。`backup.rs` の「元に戻す」はシート内に置いた静的なボタンで、時限で消える通知ではない（しかもシートを閉じたら持ち越さない、と明示的に決めてある）。**1 行の削除の救済のためにグローバルな時限 UI を 1 つ増やすのは割に合わない。** [破壊的操作は静止時に警告色を持たない（カード削除をフッタへ畳む）](destructive-affordance-quiet-at-rest.md) でオーバーフローメニューを却下したのと同じ判断。

打ち直しが数秒で済むこと自体が救済になっている、というのが本質。

## 保証するので、破る入力のテストを書く

`src/lib.rs` が `views` を wasm32 に cfg ゲートしているため `cargo test` はこの経路を通らない。**E2E がこの決定の唯一のカバレッジ。** `e2e/smoke.spec.mjs` に 3 本置いた。

- 中身のある行（60×10 + 60×8）が **1 タップで消え、`remove-set-confirm` が一度も現れない**こと。合計が 1,080 → 600 になること
- **最後の 1 行を消しても空行が 1 本残る**こと（重量欄・回数欄が空で存在する）。ここが壊れると打ち直す先が消える
- 確認 UI が DOM のどこにも生えないこと（`remove-set-confirm` / `remove-set-yes` / `remove-set-no` / `.row-confirm` が全部 0 件）。確認を戻すならこのテストを消す判断を通すことになる

既存の「カード削除の入口は静止時に警告色を持たない」テストは、`[data-testid=remove-set]` の色を `.card-foot` と比べている。✕ から死んだクラス `danger-btn` を落としたが色は `.icon-btn` の `--muted` のままなので、このテストは無改造で通る。

## 結果（トレードオフ）

**誤タップで入力済みのセットが即座に消える。** 受け入れる。守っていたのは 1 行で、打ち直しは重量プリフィルのおかげで回数 1 手。

**カードは 1 行、ライブラリのない CSS は 1 ブロック軽くなった。** `.row-confirm`（10 行）と `pending_remove` まわりの分岐が消えた。

**`danger-btn` を落とした。** `class="icon-btn danger-btn"` の `danger-btn` は `public/styles.css` にもビルド成果物にも定義が無い死んだクラスだった（✕ の色は `.icon-btn` の `--muted` から来ていた）。確認を外して ✕ の周辺を触るついでに削除した。**もし誰かが後から `.danger-btn { color: var(--warn) }` を足していたら、静止時に警告色が出て [破壊的操作は静止時に警告色を持たない（カード削除をフッタへ畳む）](destructive-affordance-quiet-at-rest.md) の色テストが落ちていた。** 名前だけ残っている状態は罠なので消すのが正しい。

## 検討した代替案

**確認を「中身が 2 つとも埋まっている行」だけに絞る。** 分岐が細るだけで、いちばん踏む「打ち間違えた行を消す」場面がまさにその条件を満たすので、体感はほとんど変わらない。

**長押しで削除にする。** wasm 側でタッチ処理を書くことになり Playwright で検証できず、iOS のテキスト選択と競合する（[破壊的操作は静止時に警告色を持たない（カード削除をフッタへ畳む）](destructive-affordance-quiet-at-rest.md) で同じ理由でスワイプを却下している）。トレ中に長押しを要求するのは 2 タップより重い。
