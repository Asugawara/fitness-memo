# 種目タブを部位の折りたたみ一覧にし、1 つだけ開く

- **状態**: 採用
- **日付**: 2026-08-09
- **カテゴリ**: ux

## 背景

種目タブは 6 部位 28 種目（プリセット）を**全部同時に**縦へ並べていた。部位のカードがあり、その中に所属種目の行が常に開いている形である。

2 つの問題があった。

- **どの部位があるかを見るだけで長いスクロールが要る。** 部位を確認したいだけなのに 28 行を通り抜けることになる。閉じた状態なら 6 行で済む
- **44px のアイコンボタンが画面を埋める。** 部位ヘッダに `↑` `↓`、種目行にも `↑` `↓` があり、6 部位ぶんのヘッダだけで 12 個、開いた部位の種目行にさらに 2 個ずつ並ぶ。並び替えの実用価値（1 部位あたり 4〜5 種目で、記録タブの追加シートはセクション内でスクロールしない）に対してノイズが勝っている

加えて部位の名前と色を変えるのは「部位名をタップ」だった。名前がリンク色（`--accent`）で、押すと編集シートが開く。折りたたみを入れると同じタップに「開く」と「編集する」の 2 つの意味が乗ってしまう。

## 決定

**部位は既定で全部閉じ、ヘッダを押すとその部位だけが開く。同時に開くのは 1 つ。並び替えの UI は種目からも部位からも取り除く。編集の入口は右端の鉛筆（lucide）に分ける。**

```
[›] ● 胸              5 種目  [✎]     ← 閉じた状態。タップ標的は 2 つだけ
[v] ● 肩              4 種目  [✎]
    ショルダープレス
    サイドレイズ
    …
    ＋ 種目を追加
```

- 開閉の状態は `App` が持つ `OpenGroupCtx`（`RwSignal<Option<GroupId>>`）1 本。**永続化はしないが、タブを跨いでは保つ**
- **開いた部位は必ず画面に入れる**（`scroll_into_view_if_needed`、`block: nearest`）
- ヘッダのタップ標的は「ヘッダ幅のほぼ全部を占める開閉トグル（`.grp-toggle`）」と「右端の鉛筆（`.icon-btn`）」の 2 つだけ
- シェブロンは左端。開いている間だけ CSS で 90 度回す。フックは `aria-expanded`
- 部位名は `<button>` から `<span>` になり、色は `--accent` から `--text` へ
- `Group.order` / `Exercise.order` を変える手段は無くなる（採番は `add_group` / `add_exercise` の追加順のまま）

## 理由

- **閉じた 6 行は 1 画面に収まる。** ヘッダ 52px × 6 + カード間 12px × 6 ＝ 384px で、iPhone 15 Pro の 852px に対してスクロールが要らない。これが今回の要求そのものである。
- **1 つだけ開くのは、複数展開だと改修が黙って無効化されるから。** 全部開いた瞬間に元の「28 行が並ぶ」状態に戻る。部位を移るのが 1 タップで済む（複数展開だと「閉じる + 開く」の 2 タップか、散らかったまま）という利点もある。1 部位を開いた状態は「ヘッダ 6 個 + 種目 4〜5 行 + フッタ」でおよそ 1 画面に収まり、**今どこにいるかと他にどこがあるかが同時に見える**。
- **`<details>` / `<summary>` は使えない。** `<summary>` は interactive content なので、中に鉛筆ボタンを置くのは不正 HTML である（iOS Safari では子ボタンのクリックが summary の既定動作にも届く）。[ホーム画面への追加の案内を記録タブ末尾のバナー + 手順シートにする](install-guide-banner-and-sheet.md) が同じ理由で「箱は `<div>`、シートを開くボタンと閉じるボタンを兄弟にする」を採っており、そこに揃えた。加えて後述の自動展開でプログラムから開く必要がある。
- **開閉を永続化しないのは、`GroupId` の置き場が無いから。** UI 状態は `fitness-memo/ui/v1` に置ける（[UI の状態を `Db` に入れず別キーに置く](../storage/ui-state-in-separate-key.md)）が、あの ADR は「`Db` を一切参照しない。ID も日付キーも入れない」を性質として課しており、前提が崩れる例として `last_selected_exercise: ExerciseId` を名指ししている。開いている部位の `GroupId` はまさにその形で、`Db` から部位が消えれば宙に浮く。**永続化はしない。**
- **ただしシグナルは `Menu` ではなく `App` に置く。** `mod.rs` の `match tab.get()` はタブを切り替えるたびに `Menu` を作り直すので、コンポーネント内に置くと記録⇄種目を往復するたびに全部閉じる。**筋トレ中はその往復が常**（種目を足す → 記録タブで前回重量を見る → もう 1 種目足す）なので、戻るたびに部位を探して押し直すことになり、この改修が縮めたはずのタップ数を別のところで増やす。`OpenGroupCtx` はプロセス内の寿命しか持たないので、[UI の状態を `Db` に入れず別キーに置く](../storage/ui-state-in-separate-key.md) の境界（永続化された UI 状態が `Db` を参照しない）はそのまま守られる。
- **開いた部位を必ず画面に入れるのが、自動展開の前提条件。** `open_group.set(..)` は「開く」だけで視界を動かさない。アーカイブ済みセクションは一覧の**一番下**にあり、新規部位は**末尾**に作られるので、そこから自動展開しても対象は画面の外で開く。ユーザーから見れば何も起きていないのと同じで、下の表が塞いだつもりの失敗がそのまま残る。`block: nearest` にしてあるので、既に見えているカード（＝ヘッダをタップして開いた場合）は 1px も動かない。`scroll_to_id`（`block: start` 相当）を使うと、開くたびに視界が上端へ飛ぶ。
- **並び替えを消したのは、ノイズが実用価値を上回っていたから。** 部位ヘッダに 色ドット / 名前 / 件数 / シェブロン / 鉛筆 / ↑ / ↓ を全部並べると、右端に 44px のボタンが 3 つ × 6 部位 ＝ 18 個が同時に画面へ出る。「部位を見渡せるようにする」という改修の目的を自分で潰すことになる。シートへ退避する案も検討したが（下記）、種目側の矢印を消す以上、部位側だけ残す理由が弱い。
- **編集を鉛筆に分けたのは、1 つのタップに 2 つの意味を持たせないため。** ヘッダ全体が「開く」で、鉛筆が「名前と色を変える」。左 = 状態 / 右 = アクションで並びも分かれる。鉛筆の `aria-label` には部位名を入れて「胸 の名前と色を編集」にした。
- **シェブロンを左端に置いたのは、開閉状態を縦一列でスキャンできるから。** 右端に置くと鉛筆と隣接して「どちらが展開でどちらが編集か」が読めなくなる。
- **`aria-expanded` を回転の CSS フックにした。** 見た目が a11y 属性に依存するので、属性が黙って落ちると気付ける。`aria-controls` は付けない（折りたたみ時に本文 DOM が消えるので参照が宙に浮く。`aria-expanded` 単独が disclosure の標準形）。
- **回転にトランジションを付けない。** `public/styles.css` には現在 `transition` も `animation` も 1 つも無く、`prefers-reduced-motion` のガードも置いていない。ここで 1 つ入れると全部に要るようになる。

### 自動展開（入れないと機能がバグに見える）

折りたたみは「見えなくなる」機構なので、**利用者の操作の結果が閉じた中に隠れる**経路を全部塞いだ。

| 契機 | 対応 | 塞いだ失敗 |
|---|---|---|
| 部位を新規作成 | その部位を開く | 新規部位は空。閉じたままだと「＋ 種目を追加」が見えず行き止まりに見える |
| 種目を新規追加 | その部位を開く | 追加したのに何も起きないように見える |
| 種目の部位を移す | 移動先を開く | 「種目が消えた」ように見える |
| **アーカイブから戻す** | 戻した先の部位を開く | **最重要。**閉じたままだとアーカイブ行が消えるだけで、種目がどこへ戻ったか分からない |
| 部位を削除 | 開いていたなら閉じる | 消えた ID を保持しない後始末 |

いずれも「開く」だけでは足りず、**開いたカードを画面に入れる**ところまでが 1 セットである（上記の理由節を参照）。アーカイブ復帰は `group_id` が実在するときだけ開く — `core::migrate` と `merge_db` は宙に浮いた `group_id` を宙に浮いたまま残す設計なので（`ArchivedSection` の `(部位なし)` 表示はそのためにある）、存在しない ID を渡すと「読んでいた部位が閉じるだけで何も開かない」という、塞ぎたかった失敗の最悪形になる。

## 結果（トレードオフ）

- **`Group.order` / `Exercise.order` はユーザーが変更できなくなり、プリセットの宣言順 → 以後は追加順で固定される。** この order が決めているのは種目タブの表示順だけではない。
  - `src/views/day.rs` 記録タブ「種目を追加」シートの**部位セクション順とその中の種目順**（トレ中の唯一のホットパス）
  - `src/views/progress.rs` 推移タブの種目セレクタ（`(group_rank, e.order, e.id)`）
  
  つまり「よく使う種目をシートの先頭に持ってくる」手段が失われた。1 部位 4〜5 種目でセクション内スクロールが発生しないため実効影響は小さいと判断したが、**将来ここが不満になったら矢印を戻すのではなく「直近に記録した順で並べる」を検討する**。手で並べ替えるより厳密に良く、「筋トレ中に最短距離で」に直接効く。
- **開閉状態はリロードで失われる。** タブ往復では保つが、`OpenGroupCtx` はプロセス内の寿命しか持たない。永続化しない決定の当然の帰結で、既定の「全部閉じている」は毎回同じで予測でき、部位の全体像が必ず見える状態でもある。
- **`views` に `scroll_into_view_if_needed` が増えた。** 既存の `scroll_to_id`（`block: start`）との違いは `block: nearest` の 1 点だけで、`web-sys` の feature が 2 つ（`ScrollIntoViewOptions` / `ScrollLogicalPosition`）増えている。似た名前の関数が 2 つ並ぶので、次に使う人はどちらが要るのか doc を読む必要がある。
- **アコーディオンのスクロールは `Effect` 1 本に集約した。** `open_group` を購読して開いたカードへ寄せる形なので、自動展開の呼び出し側（4 か所）はスクロールを気にしなくてよい。逆に言えば、`open_group` を経由しない開き方を足すとスクロールが漏れる。
- **`.grp-name` が `--accent` から `--text` になり、代わりに鉛筆を `--accent` にした。** `public/styles.css` に「名前がタップで開くことが見て分かる必要がある」というコメントが残っていたが、前提（タップ ＝ 編集）が変わったのでコメントごと書き換えた。ただし**名前から色を抜いただけだと改名の手掛かりがヘッダから完全に消える** — 件数テキストと同じ `--muted` の鉛筆に気づくまで、改名したい人は名前を押し続けることになる。`.icon-btn` の既定色を上書きして鉛筆だけ `--accent` にし、そこが編集の入口だと色で分かるようにした。破壊的操作ではないので [破壊的操作は静止時に警告色を持たない（カード削除をフッタへ畳む）](destructive-affordance-quiet-at-rest.md) の「静止時に警告色を持たない」には触れない。
- **部位の削除を拒む文言が状況で変わるようになった。** 削除ガードはアーカイブ済みも所属種目に数える一方、ヘッダの「N 種目」は非アーカイブしか数えない。折りたたみでその件数が**唯一の手掛かり**になったので、所属種目が全部アーカイブ済みのとき（ヘッダが「0 種目」なのに削除できない）は「アーカイブ済み種目が N 件あるため削除できません」と名指しする。混在時は従来どおり総数を出し、`delete-blocked-archived` で内訳を添える。
- **`move_exercise` / `move_group` / `swap_neighbor` に加えて `renumber_exercises` も消え、`next_order` に置き換わった。** これは並び替え削除の副作用として**必要になった**変更である。`renumber_exercises` は部位内の `order` を「非アーカイブ → アーカイブ済み」で 0.. に振り直す設計で、`set_archived(.., false)` が `order = u32::MAX` を打ってから呼ぶことで「戻したものは末尾へ」を実現していた。並び替えの矢印があった頃はそれで良かった（2 タップで戻せた）が、矢印を消した今は**アーカイブして戻すだけで種目が永久に末尾へ落ち、直す手段が無い**。しかも同じ `order` が記録タブ「種目を追加」シートの並びを決めているので、よく使う種目を誤ってアーカイブ → 復帰すると、以後ずっとシートの最下段に出る。`next_order`（アーカイブ済みも含めた最大値 + 1）に変え、`set_archived` は `order` に触らないようにした。飛び番が空くが `order` は相対順序にしか使わないので害はない。**機能を削るとき、その機能を前提に書かれた別のコードが残っていないかを見る必要がある。**
- **testid が入れ替わった。** 追加 `group-toggle` / `group-edit`、削除 `group-up` / `group-down` / `exercise-up` / `exercise-down`、`group-name` は `<button>` → `<span>`。既存 E2E は 5 箇所を修正し、`groupItem()` / `openGroup()` のヘルパを足した。`groupItem` が `hasText` を `group-item` に直接掛けず `has: group-name` で絞っているのは、**開いた部位のカードが所属種目の名前も含む**ため（部位名が種目名の部分文字列だと誤マッチする）。

## 検討した代替案

**native `<details>` / `<summary>` を使う**: 開閉が UA 任せになり JS もシグナルも要らない。しかし `<summary>` の中に鉛筆ボタンを置けない（interactive content のネスト）。ヘッダを `<summary>` にして鉛筆を外に出すとレイアウトが崩れ、鉛筆を中に入れると iOS Safari で子ボタンのクリックが summary のトグルにも届く。`stop_propagation` で塞ぐ形は脆い。加えて自動展開でプログラムから開くのに `NodeRef` を持ち回ることになる。却下。

**複数の部位を同時に開けるようにする**: 見比べができ、状態も直感的。しかし全部開けば元の状態に戻るので、改修が黙って無効化される。部位を移るのに 2 タップ要る。却下。

**開閉状態を `fitness-memo/ui/v1` に永続化する**: 再訪時に 1 タップ節約できる。しかし [UI の状態を `Db` に入れず別キーに置く](../storage/ui-state-in-separate-key.md) が「`Db` を参照しない」を性質として課しており、`GroupId` はその境界を越える。節約の大きさに見合わない。却下。

**部位の ↑↓ をヘッダに残す**: 並び替えは記録タブのセクション順を決めているので、消す影響は種目より大きい。しかし 44px のボタンが 18 個並ぶと一覧の役目が潰れる。却下。

**部位の ↑↓ を編集シート（鉛筆の中）へ退避する**: ヘッダは 2 標的のまま並び替えを残せる。「3 / 6」の位置表示と端での無効化を添えれば、一覧を見なくても動いたことが分かる。有力案だったが、種目側を消す以上、部位側だけ残す理由が弱い。並び替えの概念自体をアプリから外して単純にした。将来必要になればこの形で戻す。

**ドラッグ&ドロップで並び替える**: 矢印より直接的で、ボタンも要らない。しかし iOS のタッチ操作で確実に動かすのは実装も E2E も難しく、そもそも並び替えの実用価値が低いと判断したのが今回である。却下。

（★ **記録タブの `logs` / `sets` の並びについては後に採用した** — [記録タブのカードとセットをドラッグで並び替え、`Vec` の並びをそのまま保存する](drag-to-reorder-in-record-tab.md)。ここで却下したのは**種目マスタ**（`Exercise.order` / `Group.order`）の並び替えであり、そちらは今も持たない。「実用価値が低い」の判断が分かれたのは、こちらがマスタ一覧の見せ方の話で、あちらが「その日にどの順でやるか」という計画そのものだから。「iOS のタッチで確実に動かすのは難しい」のほうは今も生きていて、あちらは掴む場所を絞る・長押しで誤爆を塞ぐ・幾何を純モジュールに出す、で受けている。）
