# メモは種目カードのトグル 1 つで開き、閉じても薄字で残す

- **状態**: 採用
- **日付**: 2026-08-09
- **カテゴリ**: ux
- **関連**: [種目メモとセットメモを `ExerciseLog` / `SetEntry` に持たせ、空のメモは書き出さない](../data-model/notes-on-logs-and-sets.md)（保存側）, [破壊的操作は静止時に警告色を持たない（カード削除をフッタへ畳む）](destructive-affordance-quiet-at-rest.md), [セット追加は直前行の重量をコピーして回数欄へフォーカスする](set-entry-prefill-and-focus.md), [セット削除は確認を挟まない（カード削除の確認は残す）](set-delete-without-confirmation.md), [数値入力に `type="number"` を使わない](text-input-not-number.md), [記録タブをカレンダー + 選択日エディタの単一画面にする](record-tab-calendar-with-day-editor.md), [コピーは種目メモとセットメモを持ち込む（体調メモと体重は持ち込まない）](copy-carries-the-notes.md)（決定 5 のコピー規則を改訂）

## 背景

種目ごと・セットごとの自由記述が要る（[種目メモとセットメモを `ExerciseLog` / `SetEntry` に持たせ、空のメモは書き出さない](../data-model/notes-on-logs-and-sets.md)）。一方でこのアプリの主目的は**セットの管理**で、入力はトレーニング中に行う。重量を打つ → 回数を打つ → `+ セット` の動線に何も割り込ませてはいけない。

つまり「メモが要る」と「メモが場所を取ってはいけない」を同時に満たす必要がある。

制約を先に測った。カード内で 44px のタップ標的を**新設できる場所が無い**。タップ標的は縮められない（[破壊的操作は静止時に警告色を持たない（カード削除をフッタへ畳む）](destructive-affordance-quiet-at-rest.md) が「静かにするのは色と文字サイズだけで、当たり判定ではない」と決めている）ので、ヘッダ直下・`.last-row` の下・`+ セット` の隣のどこに入口を作っても **44px × カード枚数**だけ縦に純増する。5 種目並べれば 220px で、同 ADR が「行を 1 本消して 31px 縮めた」判断の逆走になる。

例外が 1 つある。`.card-foot` は既に 44px の `.link-btn`（「この日から外す」）を抱えているので、高さが `max(44, span) + padding` で決まっている。**ここに 2 個目の 44px ボタンを入れてもフッタの高さは 1px も増えない。**

## 決定

### 1. 入口はカード 1 枚に 1 つ。`.card-foot` の中央に置く

`＋ メモ` / `－ メモ` の文字ラベル 1 個。押すと**種目メモ欄と全セット行のメモ欄が一斉に開く**。行ごとのトグルは作らない。

横位置も測った。393px 幅の footer は「この日から外す」91px +「＋ メモ」58px +「今日 1,080」73px で、`space-between` の空きが各 58px。[破壊的操作は静止時に警告色を持たない（カード削除をフッタへ畳む）](destructive-affordance-quiet-at-rest.md) が事故として挙げた「`+ セット` と 41px しか離れておらず右端が完全一致」より離れており、**3 者が別の列**（左端 flex-start / 中央 / 右端）にいる。

ヘッダは構造的に禁止されている。`e2e/smoke.spec.mjs` が `card-head button` を 0 件で固定しているので、ヘッダに置いた瞬間に落ちる。

色は `.card-foot .note-toggle { color: var(--muted) }` で `.link-btn` の `--accent` を落とす。カードでいちばん彩度の高い色を「めったに使わない開閉」に与えない。詳細度の事情も `.card-remove` と同じで、`.link-btn`（0,1,0）と同詳細度では上書きできないので子孫セレクタ（0,2,0）で書く。

新しいアイコンは足さない。[アイコンに lucide を採り、`assets/icons/*.svg` を `include_str!` で埋め込む](../architecture/lucide-icons-as-included-svg.md) の仕組みはあるが、`＋ コンディション` と同じ文字ラベルのほうが静かで、既存の折りたたみと作法がそろう。

### 2. 既定は常に閉。`ConditionRow` の「値があれば最初から開く」は継がない

これが今回いちばん重要な判断。

`ConditionRow`（体重・体調メモ）は `!weight0.is_empty() || !note0.is_empty()` で初期値を決めており、値があれば最初から開く。**あちらが自動で開くのは、閉じているとき値がまったく見えないから**で、自動オープンが値を見せる唯一の手段だった。決定 3 でその必要が消えている。**決定 2 と決定 3 は同じ判断の裏表。**

継ぐと、一度メモを書いた種目が**永久に入力欄 N+1 本ぶん高いカード**になる（3 セットで約 200px）。それが日をまたいで復活する。コンディションは 1 日 1 個、種目カードは 1 日 5〜8 個なので、同じ作法のコストが 5〜8 倍で効く。

開閉状態はカードローカルの `RwSignal<bool>` だけに持ち、`storage::UiState` には入れない。あのキーの前提は「`Db` を一切参照しないフラグ」（[UI の状態を `Db` に入れず別キーに置く](../storage/ui-state-in-separate-key.md)）で、種目ごとの開閉は `ExerciseId` の集合 = `Db` 参照になる。種目を削除すると dangling し、マージで別端末の ID が混ざる。

リロードで閉じるのは仕様。薄字が残るので情報は失われず、追記はトグル 1 タップ。日付を変えるとカードが `<For>` のキーごと作り直されるので、開閉も自動で閉に戻る。

### 3. 閉じている間も、入力済みのメモは薄字で読める

`var(--muted)` / **12px** / セットメモは 23px 字下げ。

12px は `.last-row`（前回の記録）と同じ段で、どちらも「本文ではない利用者のデータ」。13px は `.card-foot` と同段になって静かさが崩れ、11px は `--warn` 専用の段で自由文には小さすぎる。

23px は `.set-no`（1.4em @12px = 16.8px）+ `gap` 6px = 22.8px から出した重量欄の左端。**薄字と入力欄で同じ値を使うので、開閉しても文字の左端が動かない。** `em` にしないのは入力欄が 16px 固定（iOS のズーム閾値）で `1.9em` が 30.4px になり薄字と揃わないから。

**`opacity` は使わない。** [体重を推移グラフの第2軸に常時重ねる](body-weight-second-axis-always-on.md) と同じ方針（非テキストの 3:1 を割り、ダークで消える）。従属関係はトークン・サイズ・字下げの 3 つ、すべて幾何と色で作る。

長いメモは折り返す。1 行省略にしないのは、**静止時にメモを隠すと「閉じていても読める」という前提そのものが崩れる**から。

`.set-row` の `gap` を `6px` → `2px 6px` に変えた。行間は `padding: 3px 0` の 6px なので、折り返し行の gap が同じ 6px だとその行が上下どちらの `set-row` に属するか等距離で読めない。`.warn` にも潜在していた問題が、メモ欄を足して実害になった。

### 4. 種目メモはセット行群の下（`.last-row` の直下ではない）

`.last-row` の直下に置くと、12px `--muted` の行が 2 本続く:

```
前回 8日前  60×10 60×8   1,080     ← .last-row
調子は普通                          ← 種目メモの薄字
```

トークンが同一なので「前回の記録の続き」に読める。`--muted` は 1 つしか無いので色で分けられず、区別は**位置**でしか作れない。カードの読み順「名前 → 前回 → セット → 合計」の先頭に割り込ませるのも本末転倒。

セット行群の下に置けば、**字下げの有無だけで「行のメモ（23px）/ 種目のメモ（字下げなし）」が読める**（ラベル文字が要らない）。押した場所（フッタのトグル）と現れた場所も近い。

### 5. セットメモはセットに従属し、種目メモはログを生かす

非対称にするのが正しい。

- セットメモ: 回数が無い行のメモは保存されない・行削除で一緒に消える・`+ セット` でプリフィルしない・コピーで持ち込まない
- 種目メモ: セットが 0 本でも**カードとして残る**

> **→ 「コピーで持ち込まない」だけ採り直した（[コピーは種目メモとセットメモを持ち込む（体調メモと体重は持ち込まない）](copy-carries-the-notes.md)）。** セットメモも種目メモもコピーの 3 経路で運ぶ。**`+ セット` でプリフィルしないことと、「種目メモはログを生かす」（セットが 0 本でもカードとして残る）は変わっていない。**

`load_cards` はその日のカードの集合を `session.logs` から引いている。メモだけのログを落とすと、リロードで**カードごとこの日から消える**。「今日は肩が痛いので飛ばす」と書いた種目が翌朝消えるのは記録アプリとして壊れている。

保存されないセットメモは黙って捨てない。行に `.warn` で「回数を入れると保存されます」を出す。`weight_missing`（回数あり × 重量なし）とは条件が排他なので 2 つ同時には出ない。

「この日から外す」の確認判定（旧 `has_sets`）は `has_content` に変え、種目メモも数える。**セットだけで判定すると、メモだけのカードが「空」扱いで確認なしに消え、書いたメモが黙って捨てられる。**

### 6. 行削除には確認を足さない

[セット削除は確認を挟まない（カード削除の確認は残す）](set-delete-without-confirmation.md) をメモ付き行だけ破らない。破ると「どの行が確認を出すか」が中身依存になって予測できなくなる。

## 理由

**「静かさ」は色では作れない。** `--muted` は 1 つしか無く、薄字にしたい要素（前回の記録・種目名の部位・フッタ）が既にそれを使っている。だから今回の従属関係は**サイズ（12px）と字下げ（23px / 0px）**で作った。[体重を推移グラフの第2軸に常時重ねる](body-weight-second-axis-always-on.md) が線の細さと破線で従属を作ったのと同じ論法。

**プリフィルとコピーの線引きは「計画値か観測値か」。** 重量を引き継ぐのはそれが次のセットの計画値だから（[セット追加は直前行の重量をコピーして回数欄へフォーカスする](set-entry-prefill-and-focus.md)）。メモは観測値なので、複製すると起きていない観測を捏造する。`copy_day` が `ExerciseLog` を clone せず `at` を持ち込まない理由（[`at` を `Option<i64>` にし当日入力時のみ埋める](../data-model/at-optional-same-day-only.md)）と同型。

> **→ 線を引き直した（[コピーは種目メモとセットメモを持ち込む（体調メモと体重は持ち込まない）](copy-carries-the-notes.md)）。** 「計画値か観測値か」ではなく**「過去のログを再現するか、次の 1 本を作るか」**。`+ セット` が作るのはまだ起きていない次のセットなので観測が存在せず、この段落の論がそのまま当たる。`copy_day` が `at` を持ち込まない話も**そのまま正しい** — `at` は今も運ばず、`seed_day` の引数を `at` を持たない型（`core::Seed`）にして型で守るようにした。

**`aria-expanded` には文字列を渡す。** 列挙属性なので真偽属性として扱われると `false` のとき属性ごと消え、「折りたためること」が支援技術から消える。`menu.rs` のアコーディオン（[種目タブを部位の折りたたみ一覧にし、1 つだけ開く](menu-groups-as-single-open-accordion.md)）と同じ書き方。

**メモ欄には必ず `kb_focus` / `kb_blur` を付ける。** メモ欄は `inputmode` を持たない = IME 付きフルキーボードが出るので数値欄より背が高く、付け忘れの被害が大きい（[キーボード表示中はボトムタブを隠す](../pwa/hide-tabs-when-keyboard-open.md)）。E2E で直接見る。

## 結果（トレードオフ）

**開いた瞬間フッタが下がる。** 3 セット・メモ未入力で約 200px。トグルがあった座標に破壊的操作（`remove-set` / `close-card`）が来ないことを E2E で固定した。

**薄字 12px → 入力欄 16px で字が跳ねる。** 16px は iOS のズーム閾値なので下げられない。左端は揃えたので横には動かない。

**長いメモは静止時に折り返してカードが伸びる。** 省略しないと決めた代償。

**リロードするとメモ欄は閉じる。** 追記には 1 タップ余分にかかる。

**行削除でその行のメモも消える。** 数値より打ち直しのコストが高いが、確認を挟まない規則を曲げないほうを採った。

## 検討した代替案

**行ごとにメモのトグルを置く（✕ の左に薄いアイコン）。** 入口がセット行の数だけ増え、44px のタップ標的が 1 列増えて 393px 幅で行が折り返す。「存在感を薄く」の逆。

**`textarea`（複数行）にする。** 高さが可変で行が跳ね、セット行が押し下げられる。1 行で足りる用途に対して代償が大きい。

**トグルをヘッダ右端に置く。** 既存 E2E（`card-head button` が 0 件）が却下しているうえ、旧「カード削除の入口」の事故地点と同じ列。

**トグルを `+ セット` の隣に置く。** トレ中いちばん押すボタンの視野にメモが常駐する。`justify-content` も変えることになる。

**種目メモを `.last-row` の直下に置く（当初のワイヤー）。** 12px `--muted` が 2 行連続して前回の記録と混ざる（決定 4）。

**値があれば自動で開く（`ConditionRow` の作法を継ぐ）。** カードが恒久的に約 200px 高くなる（決定 2）。

**薄字をタップして開く。** 実質「行ごとの入口」になり、44px の標的が必要になって薄字が薄字でなくなる。

**回数が無くてもメモを保存する。** `0×0` のゴーストセットが復活し、指標・ドット・コピーが汚染される（[数値入力に `type="number"` を使わない](text-input-not-number.md) が潰した経路）。

**薄さを `opacity` で作る。** 非テキストの 3:1 を割り、ダークで消える。
