# 静的メタデータを英語に統一し、`<html lang>` は実行時に切り替える

- **状態**: 採用
- **日付**: 2026-08-19
- **カテゴリ**: seo
- **関連**: [クローラ向けメタデータを本番 URL のハードコードで持ち、オフラインシェルから外す](crawler-metadata-and-hardcoded-origin.md), [manifest の URL を全て相対にする](../pwa/manifest-relative-urls.md), [ルーターを使わずタブを enum signal で切り替える](../architecture/no-router-tab-enum-signal.md), [言語はブラウザに従い、選んだらそれを優先する](../ux/language-follows-the-browser-then-the-setting.md)

## 背景

アプリ本体が日英を実行時に切り替えるようになった
（[言語はブラウザに従い、選んだらそれを優先する](../ux/language-follows-the-browser-then-the-setting.md)）。
一方 `index.html` と `public/manifest.webmanifest` のメタデータは**静的**で、
配信されるファイルは 1 つしかない。ここに何語を書くかを決める必要がある。

[クローラ向けメタデータを本番 URL のハードコードで持ち、オフラインシェルから外す](crawler-metadata-and-hardcoded-origin.md) は
「`<title>` は `fitness-memo` のままにし、日本語のキーワードは description / og:title /
JSON-LD が担う」と決めていた。**この前提が今回の変更で偽になる。**

## 決定

**静的メタデータは英語で 1 本に揃える。**

| 対象 | 変更 |
|---|---|
| `<html lang>` | `ja` → `en` |
| `meta[name=description]` | 英語 142 字 |
| `og:locale` | `ja_JP` → `en_US` |
| `og:title` / `og:description` / `og:image:alt` | 英語 |
| JSON-LD `description` / `inLanguage` | 英語 / `en` |
| `<noscript>` | 英語 `h1 + p×4` + 日本語 1 段落 |
| manifest `description` / `lang` | 英語 125 字 / `en` |

**アプリ名 4 点セット**（`<title>` / `apple-mobile-web-app-title` / manifest の `name` と `short_name`）は
**元から英語なので触る箇所が無い。**

**日本語は 2 箇所だけ意図的に残す。**

- JSON-LD の `alternateName: "筋トレメモ"`
- `<noscript>` 末尾の `<p lang="ja">` 1 段落

**実行時に `document.documentElement.lang` を UI の言語へ書き換える。**

**`hreflang` は置かない。**

## 理由

- **静的な層は 1 言語しか持てず、混在が一番悪い。** `lang="ja"` のまま description と
  `og:locale` だけ英語にすると、配信される文書が自己矛盾する。検索エンジンの
  ページ言語判定が割れるので、どちらか一方に倒すしかない。
- **Googlebot は既定で `Accept-Language: en-US` で来る。** ブラウザ言語で切り替わるアプリは、
  クローラに対して英語をレンダリングして見せることになる。`lang="en"` は
  **レンダリング後も生き残る値**で、静的な宣言と実際に見えるものが一致する。
- **実行時の上書きは任意ではなく必須。** スクリーンリーダーは `lang` から読み上げ音声を選ぶので、
  日本語の画面が `lang="en"` のままだと英語音声で読まれて使い物にならない。
  これはアクセシビリティの欠陥であって、あれば良い機能ではない。
  実装は `App` の `Effect`（`src/views/mod.rs`）に置いて、切り替えのたびに追随させる。
- **`alternateName` は schema.org がこのために用意した場所。** `inLanguage` は
  **ページ本文の言語**を指すもので、グラフ内のすべてのリテラルの言語ではない。
  英語ページに日本語の別名が載るのは well-formed な構造化データであって、不整合ではない。
  消すことで「より英語になる」のではなく、単に**情報が欠ける**。
- **消すと日本語の機械可読トークンがページから全滅する。** アプリ本体は日本語のブラウザには
  日本語で出続けるのに、日本語話者がこのアプリに辿り着く手掛かりが 1 つも無くなる。
  実利のある損失に対して、得るものがゼロ。
- **残すコストがゼロ。** `e2e/seo.spec.mjs:87` が無変更で通り、**その行が通ること自体が
  「英語化の巻き添えで消していない」証拠**になる。同じ理由で noscript 側にも
  日本語を 1 段落だけ残した。この 2 つのアサーションには「これは見張り番であって
  移行漏れではない」とコメントを書いてある。
- **noscript は JS を実行しないクローラ（LLM 系を含む）に対する本文。** その読者は
  実行時に切り替わる日本語 UI を絶対に見ない層なので、ここに 1 段落残す価値が最も高い。
  scripting 有効な文書では noscript の中身は要素にパースされないので、
  この `lang="ja"` は狙った読者にだけ効く。
- **noscript の `h1` は説明句付きに格上げした**（`fitness-memo — an offline workout log`）。
  4 点セットの外で、通常のブラウザでは不可視なので説明を足すのは無料。
  日本語版は `fitness-memo（筋トレメモ）` で同じ効果を得ていた。
- **`hreflang` は存在しない URL を指す嘘になる。** ルーターを持たないので
  （[ルーターを使わずタブを enum signal で切り替える](../architecture/no-router-tab-enum-signal.md)）
  言語別 URL が 1 つも無い。`og:locale:alternate` も同じ理由で置かない
  （Facebook が `?fb_locale=` を取りに来ても、その URL は存在しない）。
- **description の長さ制約を 80〜160 に置き直した。** `e2e/seo.spec.mjs` のコメント自身が
  「日本語のスニペットはモバイルで全角 50〜60 字ほどで切られる」と根拠を書いており、
  **50〜120 という数値が言語依存であることを認めていた。** 英語は 1 文字あたりの情報量が
  約半分で、Google の英語スニペットの切り詰めは 155〜160 字。意図（1 文で完結する下限と、
  際限なく伸ばさない上限）は保ったまま数値だけ移す。

## 結果（トレードオフ）

- **日本語クエリでの被検出性が `alternateName` と noscript 1 段落だけになった。**
  検索流入を実測して足りなければ再検討する。
- **Android の日本語ユーザーが PWA をインストールするとき、プロンプトの説明が英語になる。**
  manifest の `description` は Chrome のインストールダイアログに出る。
  iOS はこのフィールドを無視し、iOS が主対象なので影響範囲は小さいが、
  **この PR で唯一の、ユーザーに見える退行**である。
- **`e2e/seo.spec.mjs` に「意図的に残した日本語」が 2 箇所ある。** 次に読む人には
  移行のやり残しに見える。コメントで見張り番だと書いたが、規律で守るしかない。
- **静的な `lang` と実行時の `lang` が食い違う瞬間がある。** wasm がロードされて
  `Effect` が走るまでの間、日本語の端末でも `lang="en"` が立っている。
  その間に支援技術が読むものは無い（`body` が空）ので実害は無い。
- **この ADR は [クローラ向けメタデータを本番 URL のハードコードで持ち、オフラインシェルから外す](crawler-metadata-and-hardcoded-origin.md) の決定 3 を一部改訂する。**
  ハードコード origin の決定自体（絶対 URL / オフラインシェルからの除外）は無変更で `採用` のまま。

## 検討した代替案

**日本語のまま据え置く**: 変更がゼロで最も安全。しかし README とリポジトリ description を
英語にした後でここだけ日本語だと、リンクを貼ったときのカードが日英で割れる。
そもそもユーザーの要求が「メタデータも英語に」だった。却下。

**description だけ日英併記にする**: 両方の検索に当たりそうに見える。しかし
120 字（あるいは 160 字）の中に 2 言語を詰めると、**どちらの言語でも文が完結しない。**
スニペットは冒頭で切られるので、後半に置いた言語は実質出ない。却下。

**`?lang=en` の 2 URL を作って `hreflang` で結ぶ**: 検索エンジンに対して最も正しい形。
しかしルーターが無く、SW の precache が 2 倍になり、canonical をどちらにするかで
また判断が要る。1 画面のアプリに払うコストではない。却下。

**`<html lang="ja">` のまま英語のメタデータを置く**: 既存ユーザーの読み上げ言語が
変わらないので一見安全。しかし配信される文書が自己矛盾し、ページ言語判定が割れる。
実行時に上書きする以上、静的な値は「クローラが見る既定値」として英語であるべき。却下。

**noscript を完全に英語にして日本語を全廃する**: 「英語に統一」の言葉どおりで一貫している。
しかしそうするなら `alternateName` も論理的に消すことになり、日本語 UI を持つアプリの
ページから日本語の手掛かりが全滅する。一貫性のために実利を捨てる形になる。却下。
