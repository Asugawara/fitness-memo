# ADR-0006: `at` を `Option<i64>` にし当日入力時のみ埋める

- **状態**: 採用
- **日付**: 2026-08-08
- **カテゴリ**: data-model
- **関連**: [ADR-0005](0005-session-keyed-by-local-date.md), [ADR-0054](0054-elapsed-in-local-calendar-days.md)（表示規則を改訂）

> **改訂**: `at` を `Option<i64>` にし当日入力時のみ埋める、という中核の決定は生きている。
> ただし **`Elapsed` の型と表示規則は [ADR-0054](0054-elapsed-in-local-calendar-days.md) で
> 置き換わった。** `Elapsed` は private フィールドの struct になり、日数は経過ミリ秒ではなく
> 日付キー（ローカル暦）から出す。「2日5時間」形式は廃止し、日を跨いだら日数表示になる。
> 以下の「決定」節のコード片と表示例はその点で古い。

## 背景

要件に「最後のトレーニングからの時間を表示したい」がある。「時間」と言われているので日粒度（3日前）ではなく時間粒度（2日5時間）が期待されている。

一方で、要件には「カレンダーに対して、どの日付にどの筋トレ項目をしたかを追加できる」もあり、**過去日のバックフィル**（8/4 に 8/1 の記録を入れる）を明示的にサポートする必要がある。

セッションは日付文字列 `"YYYY-MM-DD"` をキーにした `BTreeMap` で持つ（ADR-0005）。ここに時刻 `at: i64` を無条件で足すと、「いつトレーニングしたか」の真実源が日付キーと `at` の**2つ**になる。

## 決定

`ExerciseLog.at` を **`Option<i64>`** とし、**その日が「今日」であるときの入力に限って `Some(epoch ms)` を書く**。過去日のバックフィルでは `None` のままにする。

経過時間の算出はこの型で分岐させる。

```rust
pub enum Elapsed { Exact(i64 /* 経過ms */), Days(i64) }

/// logs が非空の最新セッションを見る。
/// そのログに Some(at) があれば Exact(now_ms - max(at))、なければ Days(today - 日付キー)
pub fn elapsed_since_last(db: &Db, now_ms: i64, today: NaiveDate) -> Option<Elapsed>;
```

表示は `Exact` → 「2日5時間」、`Days` → 「今日 / 昨日 / N日前」。

## 理由

`at` を無条件に `Date.now()` で埋めると、次の壊れ方をする。

- 8/1 にトレーニングしたが記録し忘れ、8/4 に日付を 8/1 に変えて入力する（計画が推奨する操作）
- 期待: 「最後のトレーニングから 3日」
- 実際: `at` が 8/4 の時刻なので「たった今」と表示され、**明示要件の出力が嘘になる**。部位チップも `胸 0d` になる

`Option` にして「当日入力時のみ埋める」と決めると、通常の使い方（トレーニング中か直後に記録する）では時間粒度が出て、バックフィルでは正直に日粒度へ落ちる。型が「この記録は時刻を持たない」ことを表現するので、実装側で取り違えようがない。

## 結果（トレードオフ）

- バックフィルした記録は時間粒度を持てない。これは情報として存在しないので、偽の精度を出すよりよい。
- 表示ロジックに分岐が 1 つ増える。`Elapsed` enum に閉じ込めてあるので呼び出し側は `humanize()` を呼ぶだけでよい。
- `cargo test` で Exact と Days の両分岐を必ずテストする。E2E でも「前日に記録 → 今日タブで『昨日』相当が出る」を検証する（smoke 4）。ここを見ないとこのバグはすり抜ける。

> **この検証計画には穴があった**（[ADR-0054](0054-elapsed-in-local-calendar-days.md) で判明）。
> 「両分岐をテストする」を満たしていたのに、**`at` があって日を跨ぐ**ケースがどちらにも
> 無かった。ユニットテストは 8/6 → 8/8 という「暦の日差 2」と「経過ミリ秒 / 24h = 2」が
> 偶然一致する組み合わせを使い、E2E の `seedPastLogs` は `at: null` 既定でバックフィルしか
> 作れなかった。分岐を数えるだけでは足りず、**その分岐の中で日境界を跨がせる**必要がある。

## 検討した代替案

**`at: i64` を無条件で持つ**: シンプルだがバックフィルで嘘をつく。却下。

**`at` を廃止し全て日粒度にする**: 真実源が 1 つになり最もシンプル。ただし要件の「時間」を満たせなくなる。通常利用では時刻が取れるのだからそれを捨てる理由がなく、却下。
