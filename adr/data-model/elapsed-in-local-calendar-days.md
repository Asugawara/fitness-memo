# 経過日数をローカル暦の日差にし、時刻粒度を同じ日の中だけに閉じる

- **状態**: 採用
- **日付**: 2026-08-09
- **カテゴリ**: data-model
- **関連**: [`at` を `Option<i64>` にし当日入力時のみ埋める](at-optional-same-day-only.md)（表示規則を改訂）, [セッションをローカル日付文字列で BTreeMap に持つ](session-keyed-by-local-date.md), [グラフの座標計算を `chart_layout` に切り出してテスト可能にする](../architecture/chart-layout-as-a-testable-module.md)

## 背景

[`at` を `Option<i64>` にし当日入力時のみ埋める](at-optional-same-day-only.md) は経過時間を次の型で表した。

```rust
pub enum Elapsed { Exact(i64 /* 経過ms */), Days(i64) }
```

`Exact` が持つのは**経過ミリ秒**だけで、暦の日付は持たない。ところが画面には日数を出す場所がある（部位チップの `胸 3d`、濃淡の `data-recency`）。日数を持たない値から日数を出すために、`views/mod.rs` は次を書いた。

```rust
Elapsed::Exact(ms) => ms / 86_400_000,
```

これは**トレーニングした時刻の 24 時間後に繰り上がるローリング日数**であって、暦の日差ではない。

- 8/8(金) 20:00 に胸 → 8/9(土) 08:00 に開く → 経過 12h → `12h / 24h = 0` → チップが「今日」（実際は昨日）
- 繰り上がりはトレ時刻 + 24h に起きる。朝 9 時にトレーニングする人なら翌日 09:00 JST = **ちょうど 00:00 UTC**

このため「アプリが UTC で日付を計っている」ように見えた。実際には `Local::now()` は正しくローカル日付を返しており（[セッションをローカル日付文字列で BTreeMap に持つ](session-keyed-by-local-date.md)、chrono の `wasmbind` も有効）、壊れていたのは日数の導出だけだった。

穴が残った理由は 2 つある。

- **`Exact` 分岐の日数計算がテストされていなかった。** ユニットテストの `elapsed_since_last_takes_the_exact_branch_when_at_is_some` は 8/6 → 8/8 を使っており、暦の日差 2 と `ms / 86_400_000` = 2 が偶然一致していた。E2E の `seedPastLogs` は `at: null` 既定なので `Days` 分岐しか作れず、「`at` があって日を跨ぐ」ケースはどちらにも無かった
- **バグの居場所が `cargo test` の外だった。** `short_elapsed` / `recency_class` は `views` = `#[cfg(target_arch = "wasm32")]` gate の内側にあり、ホストのテストが一度も触れていなかった

## 決定

**`Elapsed` を private フィールドの struct にし、日数は必ず日付キー（ローカル暦）から導く。**

```rust
pub struct Elapsed {
    /// `today - 日付キー`。常に 0 以上
    days: i64,
    /// 当日入力の `at` があるときだけの経過ミリ秒。**日数の導出には使わない**
    ms: Option<i64>,
}

impl Elapsed {
    /// 唯一の生成口
    pub fn since(today: NaiveDate, date: NaiveDate, last_at: Option<i64>, now_ms: i64) -> Self;
    /// 画面が日数を出す唯一の経路
    pub fn days(self) -> i64;
}
```

表示規則も揃える。**日を跨いだら日数、同じ暦日の中だけ時刻粒度**。

- `days >= 1` → 「昨日」「3日前」
- `days == 0` → 「たった今」「45分」「12時間」（`at` が無ければ「今日」）

`short_elapsed` / `recency_class` は `core` へ移し、`cargo test` の対象にする。

## 理由

- **enum ではこのバグを型で防げない。** Rust の enum はヴァリアントのフィールドを private にできないので、`Exact { ms, days }` にしても呼び出し側は `ms / 86_400_000` を書ける。struct + private フィールドにして初めて「同じ導出を書けない」ことが型で保証される。ドキュメントとレビューで守るのは、今回それが破れた以上もう選べない
- **生成口を `since()` 1 つに絞ると、日数と時刻粒度が食い違う状態を作れない。** 両方を同じ場所で同じ入力から導くので、「片方だけ渡して不整合にする」余地が残らない。`elapsed_matching` は `today` と `date` を既にスコープに持っているので追加コストはゼロ
- **ヒーローとチップが違う日を指さなくなる。** 旧実装では 8/6 20:00 の記録を 8/9 08:00 に見ると、ヒーローが「2日12時間」でチップが「3d」だった。日数の出所を 1 つにすれば構造的に一致する
- **`short_elapsed` / `recency_class` を core に移すのは [グラフの座標計算を `chart_layout` に切り出してテスト可能にする](../architecture/chart-layout-as-a-testable-module.md) と同じ論法。** テストできない場所にロジックを置かない。今回のバグはまさに「cfg gate の内側だから `cargo test` が届かなかった」ものだった

## 結果（トレードオフ）

- **「2日5時間」形式を廃止した。** [`at` を `Option<i64>` にし当日入力時のみ埋める](at-optional-same-day-only.md) が要件「最後のトレーニングからの時間」の根拠にしていた表記が消える。日数部分がローリング日数だった以上、この形式は正しく直せない（「3日12時間」は 84 時間を意味してしまう）
- **時刻粒度は現状の配線では画面に出ない。** `views/day.rs` の `before_today` が今日のセッションを外した snapshot を渡すため、`elapsed_matching` が見つけるのは必ず昨日以前で `days >= 1` になる。分岐を残しているのは、取り込んだデータと将来の再配線に対する防御（ユニットテストで検証する）。結果として **`at` は表示にほぼ効かなくなり、データの正直さとエクスポートのための情報になった**
- **23:50 にトレ → 00:20 に開くと「昨日」。** 経過 30 分でも暦では 1 日。暦日セマンティクスの対称コストで、[セッションをローカル日付文字列で BTreeMap に持つ](session-keyed-by-local-date.md) が既に受け入れている「深夜 0 時を跨いだトレーニングは 2 日に分かれる」と同じ性質
- **`at` が日数表示に効かなくなったので、`copy_day` の `at` 漏れの被害が縮んだ。** 以前は日数がまるごと嘘になったが、今は同じ日の中の時刻表記だけが嘘になる。ただし **`ExerciseLog` を clone してはいけないという規則は維持する**（データの正直さは表示の都合とは別に守る）
- **`at` 付き記録の濃淡が 1 段階「古い」側へ寄る。** 8/7 20:00 を 8/9 08:00 に見ると `fresh` → `recent`。これは補正であって退行ではない。`data-recency` の値集合は変わらないので CSS は無変更
- **[セッションをローカル日付文字列で BTreeMap に持つ](session-keyed-by-local-date.md) は据え置く。** タイムゾーンは端末ローカルに追従したままで、JST 固定にはしない

## 検討した代替案

**`enum { Exact { ms, days }, Days(i64) }` + `days()` アクセサ**: 差分が最小で既存の分岐構造も残る。しかし enum のヴァリアントのフィールドは private にできないため、呼び出し側は今までどおり `ms / 86_400_000` を書ける。**再発を型で止められないので却下**。

**`pub struct { pub days, pub exact_ms }`**: 同上。フィールドが見える限り同じ導出を書ける。加えて `days` と `exact_ms` を別々に組み立てられるので、食い違った値を作る新しい穴が増える。却下。

**表示を全部 `at` 起点のローリング日数に統一する**: 一貫はするが、`at: None` のバックフィルが表現できない。さらにカレンダーの日付（暦日）とチップの日数（ローリング）が食い違い、[セッションをローカル日付文字列で BTreeMap に持つ](session-keyed-by-local-date.md) の「1 日 = 1 セッション、日付はローカル日付」という境界規則を裏切る。却下。

**タイムゾーンを JST（+09:00）に固定する**: 端末設定に関係なく日本時間を保証でき、`chrono` の default features を削ると黙って UTC になるという [セッションをローカル日付文字列で BTreeMap に持つ](session-keyed-by-local-date.md) の地雷も消える。しかし今回の不具合の原因ではなく（`Local::now()` は正しく動いていた）、[セッションをローカル日付文字列で BTreeMap に持つ](session-keyed-by-local-date.md) の「タイムゾーン移動は現地日付に従う」という決定を覆すことになる。バグ修正と抱き合わせにする理由が無いので却下。

**`days == 0` かつ `ms >= 24h` を 23 時間に丸める**: `at` と日付キーが矛盾したデータ（壊れたバックアップの取り込み等）への対処。丸めるより**日付キーを勝たせて「今日」に落とす**ほうが、真実源が 1 つであることと整合する。後者を採用した。
