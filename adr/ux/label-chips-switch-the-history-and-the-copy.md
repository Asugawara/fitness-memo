## 背景

[ラベルの定義を種目に置き、ログには ID の印を 1 つだけ付ける](../data-model/labels-on-the-exercise-and-a-mark-on-the-log.md) がデータの置き場所を決めた。残るのは画面の問いで、3 つある。

1. **今日の狙いをどこで選ぶか。** マシンの前で 1 タップで選べる必要がある
2. **選んだ狙いの「前回」をどう見せるか。** 見せ方が変わるなら、コピーの中身も同時に変わらなければ嘘になる
3. **定義（作成・改名・削除）をどこに置くか**

制約は [マシンのピンは種目に持たせ、メモのトグルに相乗りさせる](machine-pins-on-the-exercise.md) が実測で確定させたものをそのまま継ぐ:

- カード内に 44px のタップ標的を新設できる余地は乏しい（どこに作っても 44px × カード枚数だけ縦に純増し、5 種目で 220px）
- `.card-head` は `e2e/smoke.spec.mjs` / `e2e/pins.spec.mjs` / `e2e/interval.spec.mjs` の 4 箇所が `button` を 0 件で固定している。しかも [記録タブのカードとセットをドラッグで並び替え、`Vec` の並びをそのまま保存する](drag-to-reorder-in-record-tab.md) の掴み口（`touch-action: none` + 長押し 250ms）
- `.card-foot` は 3 者が別の列にいて、393px 幅の空きが 58px しか無い

継げないのは 1 点。**ピンとインターバルは「閉じていても薄字で読めて、値を直すときだけ開く」ものだが、ラベルは触ることが目的**である。この差がすべての決定を分ける。

## 決定

### 1. チップ行は `.card-head` の直後・`.last-rows` の直前に常設する

```
ベンチプレス                    胸
[指定なし][H][█P█][S]
Power  9/2 (火)   100×3  100×3    600
```

読み順が「種目名 → ラベル → そのラベルの前回 → セット → 合計」で**因果順**になる。上から下へ読むと「何をどの狙いで、前回はこうだった」が 1 本の文になる。

**`.card-head` の中には置かない。** e2e が 4 箇所で `button` を 0 件に固定しているのは偶然ではなく、あそこがドラッグの掴み口だから。中にボタンを入れると `routine.rs` の `.rtn-grab` 方式でヘッダを割ることになり、[マシンのピンは種目に持たせ、メモのトグルに相乗りさせる](machine-pins-on-the-exercise.md) が実測で却下した形（ヘッダ 24px → 44px、5 枚で 100px）に戻る。種目名の長さで折り返しが変わる問題もある。

**`note_open`（`＋ メモ`）に相乗りさせない。** ピンとインターバルが向こう側にいるのは、あれが「閉じていても薄字で読めて、値を直すときだけ開く」ものだから。ラベルは**マシンの前で「今日は Power」を選ぶのが最短距離の一部**で、開く 1 タップを挟むと機能の意味が薄れる。[マシンのピンは種目に持たせ、メモのトグルに相乗りさせる](machine-pins-on-the-exercise.md) 決定 2 の隣人だが、**逆の判断になる**のはこの性質の差による。

### 2. ラベルが 1 つも定義されていない種目では**ブロックごと描かない**

プリセット 28 種目は全部ラベル 0（[ラベルの定義を種目に置き、ログには ID の印を 1 つだけ付ける](../data-model/labels-on-the-exercise-and-a-mark-on-the-log.md) 決定 4）なので、**既存利用者の画面は 1px も動かない**。定義した種目でだけチップ 1 行 50px（44 + gap 6）+ `margin-top` 8px が純増する。

[前回までの記録を日付で出し、何回分出すかを表示設定にする](past-records-by-date-with-a-count-setting.md) の「既定 / 上限 / 明示的なオプトイン」三点セットと同じ形で、**縦の増分を払うのは機能を使うと決めた人だけ**。`e2e/label.spec.mjs` の 5 番が `.lbl-row` 0 件 + `data-labels` なし + `.last-rows` の `margin-top: 4px` + 3 列のままを実測で固定している。

行数はラベル名の長さで 2〜7 行に振れる（カード内側 339px に対し、1 文字チップなら 1 行 5 個、`"Hypertrophy"` なら 2 個）。`MAX_LABELS = 6` は**取り込みの門番であって、カードの高さの保証ではない**。

### 3. 先頭に「指定なし」チップを置く。**これは第一級の状態**

`LabelFilter::Any`（絞らない）で、従来どおり全ログから前回を引く。**常に可視**で、既定の選択でもある。

**文言は「指定なし」/ "Any"。「ラベルなし」にしない。** これは「絞らない」であって「ラベルが無いログだけ」ではない。6 か月ラベルなしで記録 → 今日 H/P/S を定義 → 以後全部付ける、という利用で `Unlabeled` の意味だと**半年前の記録が出る**。`Any` なら昨日が出る。既存利用者の体験を変えないという要件はこちらでしか満たせない（データ側の却下理由は [ラベルの定義を種目に置き、ログには ID の印を 1 つだけ付ける](../data-model/labels-on-the-exercise-and-a-mark-on-the-log.md)）。

`i18n.rs` の `the_any_label_chip_reads_apart_from_the_label_row_itself` が、チップの語と行の `aria-label` が同語にならないことを両言語で見る。

### 4. 履歴が無いラベルは**フォールバックしない**

`Only(S)` で履歴 0 件なら既存の `no_last_log`（「記録なし」）+ コピーボタン非表示。**ラベルなしの前回へは落ちない。**

落とすと、コピーボタンが「表示と違うものを流し込む」ことになる。[「前回をコピー」はセットが空のときだけ出す](copy-button-only-when-empty.md) が消した 3 問題（置換か追記か / 誤タップで入力済みを失う / undo の必要性）が、**別の入口から戻ってくる** — ボタンの隣に「記録なし」と書いてあるのに押すと `70×10` が 3 行入る、という形で。

回復手段は決定 3 の「指定なし」チップ 1 タップ。**画面の中に常に見えている**ので、行き止まりにならない。

### 5. `uses_weight` はラベルで絞らない

「この種目は重量を使うか」は**種目の性質**でモードの性質ではない。絞ると `[S]`（履歴 0 件）に切り替えたとたんに「重量未入力」の警告が全行から消え、`[H]` に戻すと出てくる。

そこで `history`（絞り込み後）ではなく、**無絞りの `core::last_log_before` を引く専用 Memo** に差し替えた。[前回までの記録を日付で出し、何回分出すかを表示設定にする](past-records-by-date-with-a-count-setting.md) が「表示設定は表示だけを変える」として `first()` 規則を据えた判断を、ラベルにも降ろしたもの。既存の `last_logs_before_and_last_log_before_agree_on_the_first_entry` が同値を保証しているので、挙動は 1 バイトも変わらない。

`show_copy` は**絞り込み後の** `history` を読む（決定 4 と噛み合わせるため）。

### 6. ラベル名は履歴行の**独立した 4 列目**にし、列幅を cap する

`.when` と同じ span に入れると、日付列の `max-content` がラベル名で決まってセット列の開始位置がずれ、[前回までの記録を日付で出し、何回分出すかを表示設定にする](past-records-by-date-with-a-count-setting.md) 決定 6（subgrid で桁を縦に揃える）が無効になる。**独立した 4 列目**にすればラベル列の幅は全エントリのラベル名で 1 回決まり、日付列は日付だけで決まるので**桁は縦に揃ったまま**。

```css
.last-rows[data-labels] { grid-template-columns: max-content max-content 1fr max-content; }
.last-row .label { max-width: 6em; overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
```

**列幅の cap が要る。** ラベル列は**表示中の全行の最長ラベル**で決まるので、「指定なし」で 12 文字のラベルが 1 本混ざると `.sets` に残る幅が 234px → 80px になり、`100×3` が 2 本で折り返して「数字を縦に読む」が薄れる。6em で列を 72px 以下に抑えると `.sets` が 152px 以上残り、`100×3` 4 本 / `100×10` 3 本が 1 行に収まる。全名はチップ行に常に出ているので文脈は失われない。`e2e/label.spec.mjs` の 9 番が `getClientRects().length === 1` と `.when` の x 座標一致を**実測**で固定している（計画時の値はフォントメトリクスからの推定だった）。

**★ 実装規約: `data-labels` 属性の有無と `<span class="label">` の描画は、必ず同じ `has_labels` Memo 1 本から出す。** subgrid 軸には implicit track が無いので、3 トラックの親に 4 セル入れると 4 個目が次の行へ落ち、4 トラックに 3 セルだと `.metric` が `1fr` 列に座る。「ラベル定義はあるがその日のログは `label: None`」の行では**空の span を描く**（省いてはいけない）。「記録なし」の 1 span 行はその行しか無いので影響を受けない。

`.last-rows` の `aria-label` は選択中に `Lang::past_records_of("Power")`（「Power の前回までの記録」）へ切り替える。表記が日付になると「これは過去の記録だ」の語が画面から消えるので、そこを補う `role="group"` の文言（決定は同じ ADR）にラベル名を載せる。

### 7. 選択の真実源は `ExerciseLog.label`。**ラベルだけでは `Db` に何も書かない**

カードは `label_sel: RwSignal<Option<LabelId>>` を持ち、`db.with_untracked` で今日のログから初期化する（`initial` / `note0` / `pins0` / `interval0` と同じパターン）。チップのタップは**同値ガード** → `set` → `commit()`（ガードが無いと二度押しで `save_debounced` が再武装される）。

**`write_log` の刈り取り条件（`sets.is_empty() && note.trim().is_empty()` なら remove）は変えない。** つまりラベルだけのカードは `Db` に 1 バイトも作らない。**これが最重要。**

- 作ると `dedupe_logs` の `!l.is_empty()` が次回起動で消して「保存と表示が食い違う最悪の形」になる
- それを避けて `ExerciseLog::is_empty` にラベルを入れると、逆にセット 0 本のゴーストログが永続して**その日が候補リストから永久に外れる**

この設計なら `is_empty` / `is_trained` / `has_logs_on` / `copyable` / `has_content` を**1 行も変えずに済む**。`e2e/label.spec.mjs` の 4 番が `localStorage` を直接読んで `sessions` にログが生えていないことを見る（設計の唯一の可視証明）。

**`write_log` の `Some(log)` 枝は `log.label = label` の無条件代入。** 取り込みの「空のときだけ埋める」とは規則が違う — あちらは他人のファイルとの合流で、こちらは**目の前の利用者の選択**。`if label.is_some()` にすると `[P]` → `[指定なし]` が `Db` に届かず、リロードで `[P]` に戻る。

**トレードオフ（仕様として明記）**: セットを 1 本も打っていない状態では、**リロード・タブ往復・日付移動**で「指定なし」に戻る。`DayEditor` はタブ切替で破棄され、セット 0 のカードは `load_cards` が `session.logs` から引くのでカードごと消える。**既存の空カードと同じ階級**で、新しい種類の損失ではない。

### 8. 削除済みラベルを選んだ状態は `filter` Memo で門番する。**`Db` は触らない**

今日 `[P]` で記録 → 設定で `P` を削除 → 記録タブへ戻ると `label_sel = Some(消えた ID)` になる。手当てしないと**セットがあるのに「記録なし」でどのチップも点灯しない**（宛先が読めない状態）。

`filter` Memo が `Only(id)` を `labels` で門番し、無ければ `Any` として引く。**チップの点灯も同じ `filter` から出す** — `label_sel` を直接見ると `Any` で引いているのにどのチップも点かない。「指定なし」が点灯して履歴が戻るところまでが 1 つの決定（`e2e/label.spec.mjs` の 8 番）。

**`Db` の値は書き換えない**（[ラベルの定義を種目に置き、ログには ID の印を 1 つだけ付ける](../data-model/labels-on-the-exercise-and-a-mark-on-the-log.md) 決定 11 の「宙に浮いた参照は残す」と両立させる）。相手のファイルを取り込めば `P` が生き返り、履歴も戻る。

### 9. `labels` Memo を 1 本にして、行の中で `db` を読まない

```rust
let labels = Memo::new(move |_| db.with(|d| d.exercise(ex).map(|e| e.labels.clone()).unwrap_or_default()));
let has_labels = Memo::new(move |_| labels.with(|ls| !ls.is_empty()));
```

チップ行・履歴行のラベル名解決・`has_labels` の 3 つが全部これから引く。行の中で `db.with(|d| d.exercise(ex)…)` と書くと**そのクロージャが `db` を購読**し、**どのカードの 1 打鍵でも全カードの履歴行が作り直される**。`pins` / `interval` の Memo が同じ理由で存在している。

### 10. `copy_last` は選択が「指定なし」のときだけラベルを引き継ぐ

`[P]` を選んでコピーする通常経路では元も先も P なので何も起きない。「指定なし」で見ていて、コピー元のログに `Some(id)` が付いていたときだけ `label_sel` に載せる。

[コピーは種目メモとセットメモを持ち込む（体調メモと体重は持ち込まない）](copy-carries-the-notes.md) 決定 4「コピーは既に何か書いてある場所には書かない」の**4 つ目の適用先**（`ex_note` / セットメモ / `copy_day` の `has_logs_on` ガードに続く）。`ex_note` と違って DOM の直接更新は不要 — `class:on` が `label_sel` を追跡しているので自動で追いつく。

### 11. 定義（作成・改名・削除）は**設定タブの種目編集シートだけ**に置く

`ExerciseEditor` が担当するのは「種目マスタの同一性と可視性」で、ラベルは**その種目のセッションの分類体系** — 名前 / 部位 / アーカイブと同じ棚。定義は種目ごとに生涯 1 回で、**マシンの前で必要になるものではない**。

ピンが `ExerciseEditor` に無いのは「マシンをどう物理的にセットするか」だから（[マシンのピンは種目に持たせ、メモのトグルに相乗りさせる](machine-pins-on-the-exercise.md) 決定 9）。ここでも**隣人だが逆の判断**になる。副産物として、あの ADR が「本当の穴」と認めた点（アーカイブ済み種目も直せる）が最初から塞がる。

シート側の作法:

- **Db 書き込みは `on:input` ではなく `on:change`（blur / Enter）。** `PinRow` は毎打鍵 commit だが、それを写すと既存 `P` があるとき `Power` と打つ途中の `P` が重複になる。毎打鍵を止めないと `Only` の名前解決が曖昧になって TSV 往復のたびに `P` が増える
- **重複チェックは新規追加と改名の両方に通す**（片方だけだと裏口が残る）。重複していたら書かずに直前の保存値へ戻し `.warn-box` を出す。**巻き戻すときは DOM の `value` も直す** — `value=` は初期値を 1 度読むだけなので、signal を書いても入力欄は重複した値のまま残り、次の 1 打鍵で古い値が保存される（`ex_note_ref` とまったく同じ事情）
- **削除は確認を挟む。** `remove_pin` に確認が無いのは消えるのが数字 1 個だから。ラベルの削除は**数か月ぶんの履歴のまとまりが不可視に外れる**。`GroupEditor` / `routine.rs` と同じ**インライン `warn-box`** なので「シートの中のシート」にならない。文言に「同じ名前で作り直しても過去の記録には戻りません」を含める（ID が変わる。本物の罠）
- `MAX_LABELS` に達したら `＋` を出さない（押しても何も起きないボタンを作らない）
- 名前入力は `type="text"`（`inputmode` なし = IME 付きフルキーボードが出るので `kb_focus` / `kb_blur` は必須）
- ✕ / ＋ / 確認ボタンのすべてに class を付ける（`e2e/smoke.spec.mjs` が `[data-testid=settings-sheet] button:not([class])` を 0 件で固定している。[`color-scheme` を宣言し、クラスなしの `<button>` を作らない](declare-color-scheme-for-ua-widgets.md)）
- **並べ替えは持たない。** `Vec` 順 = 表示順。要素は 2〜4 個なので ✕ → ＋ の 2 タップで足りる

### 12. CSS は新しい接頭辞 `.lbl-*`。`.opt` のクラス名を共有しない

`.opt` は設定シートの部位選択専用で、3 つ目の画面で共有すると将来の設定側の変更がカードを黙って壊す（`.rtn-*` が「あの画面固有」として存在する規約に倣う）。

**`.opt.on` のトークンは 1 文字も変えない**（「選択中」がアプリ全体で同じ絵に見えることが読みやすさそのもの）。`.opt` との差分は 2 つだけ:

- `min-width: 44px` — 1 文字ラベル `H` は `padding: 0 12px` だけでは 44px を割る
- `font-size: 13px` — `.opt` は指定を持たず 15px を継ぐ。カードの中の副次的な操作なので 1 段落とす

**折り返す**（横スクロールにしない）。隠れているチップがあることが静止時に読めない。

44px の判定は E2E 側で `Math.round(box.height) >= 44` と丸める（Pixel 7 の DPR 2.625 で `43.99993896484375` になる既知の教訓）。

### 13. 推移タブはスコープ外

グラフも記録テーブルもラベルを見ない。別 PR（`exercise_series` / `group_series` / `pick_series` / `restore_pick` / `UiState.progress_*` に一切触っていない）。

## 理由

**チップを選ぶと履歴とコピーが同時に切り替わる**という 1 つの操作に畳んだのが、この機能の中心。ラベルごとにコピーボタンを並べる案（`[H をコピー][P をコピー][S をコピー]`）は同じことを 3 つのボタンで言うが、(a) 44px × 3 が縦に増え、(b) 履歴表示が「どれをコピーするか」と一致しなくなり、(c) 押す前に「前回はどうだったか」が読めない。**表示と行き先が常に一致していること**が、[「前回をコピー」はセットが空のときだけ出す](copy-button-only-when-empty.md) が守った性質そのものなので、そこに乗せた。

**定義 0 の種目で 1px も動かない**ことを 2 つの層（データ側の「プリセットに配らない」と画面側の「ブロックごと描かない」）で保証したのは、この機能を使わない大多数にとってこのリリースが**存在しないのと同じ**であるべきだから。

**空ログを作らない**という制約が、既存の 5 つの判定式（`is_empty` / `is_trained` / `has_logs_on` / `copyable` / `has_content`）を 1 行も触らずに済ませている。代わりに「セット 0 では選択がリロードを越えない」を仕様として受けた。既存の空カードと同じ階級なので、利用者から見て**新しい種類の挙動が増えていない**。

**4 列目にして cap する**のは、[前回までの記録を日付で出し、何回分出すかを表示設定にする](past-records-by-date-with-a-count-setting.md) 決定 6 が「数字を縦に読む」ために払った設計を壊さないため。ラベル名を出すこと自体が目的ではなく、**選択中でない行の狙いが読めること**が目的なので、6em で切って ellipsis にしても機能は満たされる（全名はチップ行にある）。

**管理 UI を設定タブに置く**のは、定義が生涯 1 回の操作でトレ中の動線に属さないから。ピンと逆の判断になるのは、ピンが「マシンの前で読む値」でラベルが「マシンの前で選ぶ値」という差による — **読むものは近くに、決めるものは奥に**。

## 結果（トレードオフ）

**定義した種目のカードが 50px 高くなる。** ラベル名が長いと 2 行以上になり、最悪 7 行（350px）。払うのは機能を使うと決めた人だけだが、上限 6 本は**高さの保証ではない**。

**セットを打つ前の選択は永続しない。** リロード・タブ往復・日付移動で「指定なし」に戻る。決定 7 の明示的な対価。

**履歴行のラベル名が 6em で切れる。** 12 文字のラベルは `あいうえおかき…` になる。全名はチップ行にあるが、履歴だけを見ている人には読めない。

**「指定なし」が「ラベルなしのログだけ」を意味しない。** ラベルを全部付けた運用では「指定なし」と `Only` の履歴が同じになり、チップの意味が薄れる。既存利用者の体験を守るほうを採った対価。

**削除済みラベルを選んだ状態が `Db` に残る。** 画面は「指定なし」を見せるが、保存されている `label` は消えた ID を指したまま（そのログを次に commit すると書き戻される）。相手のファイルを取り込めば生き返る側の性質なので許した。

**`＋ メモ` のラベルは実態から離れたままで、ラベルはその外にある。** カードの下部が「準備（ピン → インターバル）→ 観測（メモ）」の 2 段だったのに対し、上部に「分類（ラベル）」の段が増えて 3 つの層になった。

**推移タブでラベル別に見られない。** 「Power だけの重量推移」はこの PR では見えない。別 PR。

**設定タブのシートが縦に伸びた。** 名前 / 部位 / ラベル / アーカイブの 4 ブロックになり、iPhone 15 Pro では下端が畳の外に出る（シートはスクロールするので届く）。

## 検討した代替案

**ラベルごとにコピーボタンを並べる。** 押す対象が明示的で、履歴の切り替えという概念が要らない。しかし 44px × 3 が縦に増え、履歴表示と行き先が一致しなくなる（理由に書いたとおり）。却下。

**チップ行を `.card-head` の中（種目名の右）に置く。** 縦が 1px も増えない。しかし e2e が 4 箇所で `button` 0 件を固定しており、そこはドラッグの掴み口。[マシンのピンは種目に持たせ、メモのトグルに相乗りさせる](machine-pins-on-the-exercise.md) が実測で却下した形（ヘッダ 24px → 44px、5 枚で 100px）に戻る。種目名の長さで折り返しも変わる。却下。

**`note_open`（`＋ メモ`）に相乗りさせる。** 新しい常設要素が 0 個で、[マシンのピンは種目に持たせ、メモのトグルに相乗りさせる](machine-pins-on-the-exercise.md) の予算をまた 1 つも使わない。しかしマシンの前で「今日は Power」を選ぶのに開く 1 タップが挟まる。**触ることが目的**のものを開閉の裏に置くと機能の意味が薄れる。却下。

**`<select>` にする。** 縦が 44px 1 行で済み、ラベルが何本でも高さが変わらない。しかし (a) 現在の選択以外が読めない（「他にどんな狙いがあるか」がタップ前に分からない）、(b) 1 タップで切り替えられない（開く → 選ぶの 2 手）、(c) 推移タブの 2 セレクタと違って**カード 1 枚ごとに 1 つ**なので 5 枚で 5 個並ぶ。却下。

**ラベル名を `.when` と同じ span に入れる（`Power 9/2 (火)`）。** 列を増やさずに済み、CSS が 1 行も増えない。しかし日付列の `max-content` がラベル名で決まり、セット列の開始位置が行ごとにずれる。[前回までの記録を日付で出し、何回分出すかを表示設定にする](past-records-by-date-with-a-count-setting.md) 決定 6 が subgrid で払った設計が無効になる。却下。

**ラベル列を cap しない。** 全名が読める。しかし 12 文字のラベル 1 本で `.sets` が 234px → 80px になり、`100×3` が 2 本で折り返す。「数字を縦に読む」が薄れるほうが損失が大きい。却下。

**履歴が無いラベルでラベルなしの前回へフォールバックする。** 「記録なし」を見る回数が減る。しかしコピーボタンが表示と違うものを流し込むことになり、[「前回をコピー」はセットが空のときだけ出す](copy-button-only-when-empty.md) が消した 3 問題が別の入口から戻る。却下（決定 4）。

**`uses_weight` も絞り込み後の `history` から引く（現状のコードのまま）。** 変更が 0 行で済む。しかし `[S]`（履歴 0 件）に切り替えたとたんに「重量未入力」の警告が出入りする。[前回までの記録を日付で出し、何回分出すかを表示設定にする](past-records-by-date-with-a-count-setting.md) の「表示設定は表示だけを変える」に反する。却下。

**ラベルだけのカードでも `Db` に書く（`is_empty` にラベルを入れる）。** 選択がリロードを越える。しかしセット 0 本のゴーストログが永続して**その日が候補リストから永久に外れる**（データ側の却下理由は [ラベルの定義を種目に置き、ログには ID の印を 1 つだけ付ける](../data-model/labels-on-the-exercise-and-a-mark-on-the-log.md)）。却下。

**削除済みラベルを選んだ状態を `Db` の書き換えで直す（`label_sel` の初期化時に `None` を書き戻す）。** 画面の状態が単純になる。しかし「宙に浮いた参照は残す」方針と衝突し、相手のファイルを取り込んだときに生き返るはずのものが消える。読み出し側の門番で足りるので却下（決定 8）。

**記録タブのチップ行に `＋` を置いて、その場でラベルを作れるようにする。** マシンの前で思いついた狙いをすぐ足せる。しかし (a) 44px の標的が 1 つ増え、(b) IME 付きの入力欄がカードの中に生えてキーボードがボトムタブを覆い、(c) 重複チェックと上限の警告をカード内に出す場所が無い。定義は生涯 1 回なので設定タブで足りる。却下（決定 11）。

**ラベルに色を持たせる。** チップが一目で区別でき、履歴行も色で読める。しかし部位の `--chip-0..3` の 4 段濃淡と意味が競合し（「色 = 部位」という既存の読み方が崩れる）、色覚の配慮も別に要る。`--accent` 1 色で「選択中」を表すほうが既存の絵と揃う。却下。

**ラベルの並べ替え（D&D）を持たせる。** 使用頻度順に並べられる。要素が 2〜4 個なので ✕ → ＋ の 2 タップで足り、[記録タブのカードとセットをドラッグで並び替え、`Vec` の並びをそのまま保存する](drag-to-reorder-in-record-tab.md) の機構をシートの中に持ち込む対価に見合わない。却下。

**`Routine` にラベルを持たせる（メニュー展開時に狙いも決める）。** 「Power の日」を 1 タップで開ける。しかしメニューの展開は種目ごとに**別々の不可視の日**から引くので、ラベルを押し付けると来週その狙いの履歴が汚れる（`Seed::without_label` が落としている理由そのもの）。メニューは種目の集合であって狙いの宣言ではない。却下。
