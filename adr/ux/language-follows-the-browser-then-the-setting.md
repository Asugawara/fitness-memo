# 言語はブラウザに従い、選んだらそれを優先する

- **状態**: 採用
- **日付**: 2026-08-19
- **カテゴリ**: ux
- **関連**: [設定タブの入口を節の一覧にし、中身は 1 階層下ろす](settings-as-a-list-of-sections.md), [フォーカスリングを明示し、記録タブの見出しを 1 本の階層にする](focus-ring-and-heading-order.md), [UI の状態を `Db` に入れず別キーに置く](../storage/ui-state-in-separate-key.md), [i18n crate を入れず、`src/i18n.rs` の struct + `const` 2 枚で文言を持つ](../architecture/i18n-hand-rolled-string-table.md)

## 背景

日英 2 言語に対応するにあたり、**初回に何語で出すか**と**どこで切り替えるか**を決める必要がある。

既存のユーザーは全員日本語で使っている。ここが変わると、アプリを開いた瞬間に
知らない言語の画面が出て、しかも「言語」という語自体が読めない状態で設定を探すことになる。
一方で公開先は GitHub Pages の英語圏可視のリポジトリで、英語話者が開く可能性も同じだけある。

## 決定

**解決順序を「明示的に選ばれた値 → ブラウザの申告 → 英語」の 3 段にする。**

```rust
let lang = storage::saved_lang().unwrap_or_else(browser_lang);
```

- `saved_lang()` は `fitness-memo/ui/v1` の `lang` フィールド。設定画面で選んだときだけ入る
- `browser_lang()` は `navigator.language` の **primary subtag** が `ja` なら日本語、他は全部英語

**切り替えは設定トップの 5 行目 + サブページに置く。**

```
設定
  エクスポート / インポート           ›
  トレーニングメニュー           2   ›
  種目                        28   ›
  ホーム画面への追加のしかた           ›
  言語                     日本語   ›     ← 追加
```

サブページは `back_head` + 既存の `.segmented`（推移タブの指標 / 期間と同じ部品）。

**`<html lang>` を UI の言語に同期させる。**

**英語の日付は月名の略記にする**（`Aug 8 (Fri)`）。

## 理由

- **既存ユーザーの体験が 1 ミリも変わらない。** 日本語のブラウザは `ja-JP` を申告するので、
  何もしなければ今までどおり日本語で出る。「英語対応を入れたら日本語のユーザーが困る」
  という移行リスクが構造的に発生しない。
- **`starts_with("ja")` にしてはいけない。** `jam`（ジャマイカ・クレオール）、`jav`（ジャワ語）、
  `jbo`（ロジバン）が日本語として通る。区切り（`-` / `_`）で切って primary subtag だけを比べる。
  判定本体は `i18n::from_bcp47` に置いてホストのテストで固定した。
- **知らない言語は英語に倒し、壊れた保存値は「未設定」に倒す。** `from_bcp47` と `parse_saved` を
  分けたのはこの非対称のため。前者は「日本語だと分かったときだけ日本語」が正しい既定だが、
  後者で英語に固定してしまうとブラウザ言語に戻る道が塞がる。
- **保存値は `Option<Lang>` ではなく `Option<String>` で持つ。** 知らない綴り（手で編集された、
  将来の言語が書いた）が入っていると `Lang` の deserialize が失敗し、
  **`UiState` 全体のパースが落ちて `install_hint_dismissed` まで巻き添えで消える。**
  文字列で受けて寛容に解けば、知らない値は「未設定」に落ちるだけで済む。
- **`Db` ではなく `UiState` に入れる。** 言語は端末に属していてデータに属していない。
  [UI の状態を `Db` に入れず別キーに置く](../storage/ui-state-in-separate-key.md) が課した 3 条件
  （`Db` を参照しない / 失われても害がない / 移行も退避も持たない）を全部満たす。
  失われてもブラウザ言語に戻るだけ。
- **`.row-count` に件数ではなく現在値を出す。** iOS の設定アプリと同じ形で、入る前に
  今が何語かが読める。[設定タブの入口を節の一覧にし、中身は 1 階層下ろす](settings-as-a-list-of-sections.md) の
  「0 件でも出す — 入って初めて分かるより速い」と同じ意図をそのまま流用できた。
- **表記は必ず endonym（その言語自身での綴り）。** 「Japanese」と英語で書くと、
  **英語を読めない人が自分の言語を選べない。** これは言語切り替え特有の落とし穴で、
  他の設定項目には無い制約になる。
- **末尾に置く。** 先頭は「データを失う前に見つけてもらう」ためのエクスポート / インポートで
  固定されているし、言語は一生に一度の操作なので探しに来る頻度が最も低い。5 行はスクロール無しで見える。
- **`<html lang>` の同期は任意ではなく必須。** スクリーンリーダーはこの属性から読み上げ音声を選ぶので、
  日本語の画面が `lang="en"` のままだと英語音声で読まれて使い物にならない。CJK のフォント選択にも効く。
  静的な値は `en`（クローラ向け、[静的メタデータを英語に統一し、`<html lang>` は実行時に切り替える](../seo/static-metadata-in-english.md)）で、
  実行時に上書きする。
- **英語で `8/8` を使わない。** 米式 M/D と英式 D/M は見た目が同じで意味が違うので、
  8 月 8 日以外は読み手のロケール次第で別の日に読める。月名の略記にすれば曖昧さが構造的に消える。
  カッコ付き曜日の形（`Aug 8 (Fri)`）は日本語と揃えてあるので、CSS もレイアウトも動かない。
- **1M / 3M / 6M / 1Y は両言語で同じ。** 記号に近い短縮なので、日本語だけ「1ヶ月」に広げると
  セグメントの幅が揃わなくなる。訳すのは「全期間 / All」だけ。

## 結果（トレードオフ）

- **`navigator.languages`（優先順の配列）を見ないので、第 2 希望が日本語の人には効かない。**
  ブラウザの言語が `en-US, ja` の人は英語で始まる。設定で 1 回選べば済む話なので、
  `js_sys::Array` の走査を足すほどではないと判断した。
- **E2E のロケールを固定する必要が生じた。** Playwright の既定は en-US なので、
  `playwright.config.mjs` に `locale: 'ja-JP'` を書かないと既存 spec の日本語の期待値
  67 行が一斉に落ちる。`scripts/shots.mjs` も同じで、こちらは忘れると
  seed が日本語の種目名を引いているので**撮影自体が落ちる**。
  `timezoneId` と同じ「揃えないと意味が変わる」種類の設定が 1 つ増えた。
- **言語が 3 つ目に増えると segmented が窮屈になる。** 2 択だから成立している形なので、
  そのときはリスト + チェックマークに変えることになる。
- **英語 UI で日本語の種目名が並ぶ状態が普通に起きる。** 既存ユーザーが英語に切り替えると
  「Bench Press」ではなく「ベンチプレス」が並ぶ
  （[プリセット名は初回投入の言語で固定し、ユーザーデータとして扱う](../storage/preset-names-are-user-data-seeded-once.md)）。
  意図した挙動なので、言語サブページに注記を出して先に伝えている。
- **「言語」の行だけ、右端の意味が他と違う。** 他の 3 行は件数、ここだけ現在値。
  iOS の設定アプリで見慣れた形なので誤読はしないと判断したが、規則としては揃っていない。

## 検討した代替案

**常に日本語を既定にし、英語は opt-in**: 既存ユーザーへの影響がゼロで、挙動も最も単純。
しかし英語話者が開いたときに、読めない言語の画面から「言語」という読めない語を探すことになる。
公開先が英語圏可視である以上、これは実質「英語対応していない」のと変わらない。却下。

**常に英語を既定にし、日本語は opt-in**: 海外向けに振り切る形。しかし現在のユーザーは
全員日本語で、全員が初回に困る。得るものに対して払うものが大きすぎる。却下。

**設定トップの行の中にインラインの segmented を置く**（サブページを作らない）: タップ 1 回で切り替わる。
しかし [設定タブの入口を節の一覧にし、中身は 1 階層下ろす](settings-as-a-list-of-sections.md) が明記した
「4 行とも『押すと先がある』もので揃っている」を壊し、リストの押下対象が行なのか
中のコントロールなのか読めなくなる。1 行だけ挙動が違う一覧は、他の 4 行の読み方まで曖昧にする。却下。

**ラベルを「言語 / Language」と両言語併記にする**: 読めない言語で起動した人の発見性は最高。
しかし `.row-count` に endonym（日本語 / English）が既に出ているので視覚的な手がかりは足りており、
1 行だけ表記規則が違うほうが目立つ。却下。

**`?lang=en` の URL 上書きを足す**: E2E から言語を指定できて楽になる。しかし本番に出る
テスト専用の口で、ルーターを持たない構成（[ルーターを使わずタブを enum signal で切り替える](../architecture/no-router-tab-enum-signal.md)）に
クエリ解釈を持ち込むことになる。Playwright の `locale` で足りるので不要。却下。

**日付を `Intl.DateTimeFormat` に任せる**: ロケールごとの正しい書式が無料で手に入る。
しかし wasm から呼ぶには `js-sys` の宣言が増え、**出力がブラウザとロケールで揺れるので
テストで固定できない**。`chart_layout` や `fmt_date` をホストのテストで押さえてきた方針
（[グラフの座標計算を `chart_layout` に切り出してテスト可能にする](../architecture/chart-layout-as-a-testable-module.md)）と噛み合わない。却下。
