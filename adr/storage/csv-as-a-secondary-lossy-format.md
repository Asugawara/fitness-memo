# CSV を二次形式として足し、正は JSON のままにする

- **状態**: 採用
- **日付**: 2026-08-13
- **カテゴリ**: storage
- **関連**: [書き出しは共有シートを主経路にし、iOS では `<a download>` を使わない](share-sheet-over-download.md)（書き出しの経路）, [公開リンクの Google スプレッドシートを URL で取り込む](import-from-published-sheet-url.md)（取り込みの経路）, [表からの取り込みは利用者に何も聞かない](../ux/spreadsheet-import-asks-nothing.md)（取り込みの UI）, [ID を 60 bit 乱数にし、プリセットには固定 ID を与える](../data-model/random-ids-for-safe-merge.md), [localStorage の単一キーに JSON 全体を持つ](localstorage-single-key-json.md)

## 背景

書き出し / 読み込みは JSON 1 形式だけだった（`core::export_json` / `core::parse_import`）。控えとしては過不足がない — 保存形式そのものなので、`storage::save` が書くバイト列と 1 バイトも変わらない。

一方で JSON では**できないことが 2 つ**残っていた。

1. **記録を表計算で見る。** ピボットや自作のグラフで眺めたいとき、JSON は開く手段がない
2. **他アプリからの移行。** [他アプリからの移行はスクショの文字起こしを貼り付けて受ける](../ux/migrate-by-ocr-paste.md) は破棄され、`src/import_text.rs` は撤去された。以来、外から記録を持ち込む経路は**存在しない**

どちらも「1 行 = 1 セット の表」が間に入れば解ける。しかも 2 つ目は、整形の責務を**人間と表計算アプリに渡す**ことになるので、[テキスト取り込みは「足すだけ」に固定し、部位を増やさず、`at` を書かない](../data-model/text-import-is-merge-only.md) が「どちらに倒しても割に合わない」と諦めた問題に、別の角度から答えることになる。

## 決定

**CSV / TSV を足す。ただし「二次形式」と位置づけ、正は JSON のままにする。**

```
日付,部位,種目,セット,重量kg,回数,セットメモ,種目メモ,体重kg,当日メモ
2026-08-01,胸,ベンチプレス,1,60,10,,フォーム確認,70.5,調子よい
2026-08-01,胸,ベンチプレス,2,62.5,8,きつい,フォーム確認,70.5,調子よい
```

同時に 6 つを決める。

1. **`core::export_json` は分岐させない。** CSV は `sheet::export_csv` という別関数にする
2. **ID 列を出さない。** 突き合わせは名前で行う
3. **列はヘッダ名で解決する。位置に依存しない**
4. **取り込みは「足すだけ」に固定する。** `Mode::Replace` を描画せず、`apply` 側でも `Source::Csv` なら `Mode::Merge` に落とす
5. **UTF-8 BOM を付ける**（日本語環境の Excel が UTF-8 と判るため）
6. **`sheet` を独立モジュールにする。** `leptos` / `web-sys` を触らず、`cargo test` が全部を検証する
7. **書き出しの経路は共有シート / ダウンロードだけにする。** クリップボードには落とさない（下記）

## 理由

### なぜ `export_json` を分岐させないのか

`core.rs` は「**エクスポート形式 = 保存形式**をこの 1 関数に固定する」と書いている。理由も併記されている —「別形式を作ると、保存側の変更に追随し忘れて『書き出したファイルが読み戻せない』が静かに起きる」。

CSV を `export_json` の引数やモードにすると、この固定が崩れる。**別関数として並べれば、JSON 側の不変条件はそのまま残る。**

### なぜ ID を書かないのか

ID は 12 文字の Crockford base32 文字列（[ID を 60 bit 乱数にし、プリセットには固定 ID を与える](../data-model/random-ids-for-safe-merge.md)）。表に出すと 3 つの問題が起きる。

- **見苦しい。** 表計算で開いたときに、意味のない列が一番目立つ場所に並ぶ
- **編集で壊れる。** 行をコピーして日付だけ変える、という自然な操作で ID が重複する
- **数値化されうる。** スプレッドシートは数字だけの文字列を数値と解釈する。12 桁の数値は精度の範囲内なので黙って通り、先頭のゼロだけが落ちる

代わりに名前で突き合わせる。プリセット 28 種目は全端末で固定 ID なので、**実データの大半は名前一致から固定 ID に戻せる**。ユーザーが自分で足した種目も、同じ端末に対して書き戻す限り名前で当たる。

### なぜ列を名前で引くのか

**書き出したファイルは利用者の手元に残り続ける。** [ID を 60 bit 乱数にし、プリセットには固定 ID を与える](../data-model/random-ids-for-safe-merge.md) が「ユーザーの iCloud Drive に保存されたら、その形式をアプリの寿命の間ずっとサポートし続けなければならない」と書いたのと同じ制約が、CSV にもかかる。

位置で読むと、列を 1 つ足した瞬間に古いファイルが読めなくなる。名前で引けば、**利用者が自分用の列を足しても、並べ替えても読める**。`COLUMNS` の名前を変えないことだけが将来の制約になる（足すのは末尾だけ、という規則を doc コメントに書いた）。

### なぜ「足すだけ」に固定するのか

CSV は **ID・色・並び順・`archived` を持たない**。「置き換える」を許すと、取り込んだ瞬間に部位の色と種目の並び順が黙って消える。しかも消えたことは画面上どこにも出ない（記録は全部あるので、要約の数字は一致する）。

[テキスト取り込みは「足すだけ」に固定し、部位を増やさず、`at` を書かない](../data-model/text-import-is-merge-only.md) は OCR の読み違いを理由に Merge 固定にした。理由は違うが、**外から来た不完全なデータで既存を全部消す理由が無い**という結論は同じ。

空の端末へ移す場合も Merge で結果は変わらない（プリセットは `seed` 済みなので、足すだけで全部入る）。

### 冪等性を自前で作らない

`core::merge_db` は同じ日・同じ種目でセットが違うとき、**連結せず [`log_rank`] の大きいほうを採る**。これは「同じファイルを 2 回入れるとセットが倍になる」を潰すために書かれたもので、CSV 取り込みもそのまま乗る。

撤去された `import_text.rs` は `contains_run` という専用の重複ガードを持っていたが、こちらは要らない。`importing_the_same_sheet_twice_does_not_duplicate_sets` が数で固定している。

### BOM を付ける理由

日本語環境の Excel は BOM が無いと UTF-8 を Shift_JIS と誤認して文字化けする。Google スプレッドシートと Numbers は BOM の有無どちらでも読む。

### 表を**クリップボードに落とさない**

TSV をクリップボードへ入れる「貼り付け用にコピー」を一度実装して、**撤去した。** 貼り付け先が自動で列に分けてくれるので最短に見えたが、測ったら成立していなかった。

週 3 回・5 種目 × 3 セットで:

| 期間 | 行数 | TSV |
|---|---|---|
| 1 年 | 2,340 | 90,054 文字 / 128 KB |
| 3 年 | 7,020 | 270,078 文字 / 384 KB |
| 10 年 | 23,400 | **900,162 文字 / 1.28 MB** |

3 つとも致命的だった。

1. **クリップボードは大域状態。** 直前にコピーしたものが黙って消える
2. **iOS のユニバーサルクリップボードは、近くの Mac / iPad にペーストボードを同期する。** 10 年分のトレーニング記録が他端末へ飛ぶ。[公開リンクの Google スプレッドシートを URL で取り込む](import-from-published-sheet-url.md) が「記録は外に出ない」と線を引いたそばから、**利用者が意図しない経路で外に出る**
3. **数年で破綻する。** 900k 文字をペーストボードに載せ、23,400 行を iOS の Sheets アプリに貼るのは現実的でない

しかも [書き出しは共有シートを主経路にし、iOS では `<a download>` を使わない](share-sheet-over-download.md) の `pick_route()` により、**CSV ファイルの共有はクリップボードを使わずサイズ制限も無い**。TSV コピーは既存経路の下位互換を 1 つ増やしただけだった。

**`Route::Clipboard`（共有シートが使えない端末）でも CSV を落とさない。** CSV の文字列を貼っても表計算は列に分けないので、大きな文字列を大域状態に置いた挙句に役に立たない。その端末では「共有できません」と言い、控えは JSON 側（`copy_text` + textarea）に任せる。

### セット番号の列を読まない

書き出しでは通し番号を出すが、取り込みでは**行の並び順**を使う。番号を読むと「重複したら」「飛んでいたら」という別の曖昧さを持ち込むことになり、しかも利用者が表で見ているのは並び順のほうである。

## 結果（トレードオフ）

- **`src/sheet.rs` を新設した**（実装 約 600 行 + 単体テスト 36 本）。`core.rs` は 3866 行あり、ここに足すと「純ロジックだが用途が違うもの」が混ざる。[グラフの座標計算を `chart_layout` に切り出してテスト可能にする](../architecture/chart-layout-as-a-testable-module.md) と同じ切り方にした
- **`core::normalize` を `pub(crate)` にした。** `sheet::parse` が取り込み境界で必ず通す必要がある（`drop_unrepresentable_weights` を経由しないと `3.5e38` が `inf` → `"weight":null` で保存され、次回起動から永久に読めなくなる）
- **CSV の列名が新しい永久サポート対象になった。** JSON のスキーマに加えて、もう 1 つ「勝手に変えられない形」が増えた
- **往復はロスレスではない。** 部位の色・種目の並び順・`archived`・`at` は CSV に出ないので、CSV → 取り込みで復元されない。だから「置き換える」を出さない
- **新規クレートはゼロ。** CSV パーサ（RFC4180）を自前で書いた。メモが自由記述なので引用符の中のカンマ・改行・二重引用符を必ず通す必要があり、そこは `csv_quotes_fields_containing_commas_quotes_and_newlines` と往復テストで固定してある
- **`transfer` の 3 関数に `mime` 引数が増えた。** `application/json` 決め打ちだったので、呼び出し側 2 箇所に `transfer::JSON` を書く変更が入った

## 検討した代替案

**`.xlsx` を出す**: 真の Excel ファイルなら列幅や日付書式が最初から整う。ただし `rust_xlsxwriter` は zip + XML で、wasm が概ね +200〜400KB 増える。このアプリはオフラインシェル 1.0MB を守るために [Service Worker はシェル全体を BUILD_ID で原子的に入れ替える](../pwa/sw-atomic-shell-swap.md) で `og.png` の 21KB を除外し、E2E 1 本まで書いている。**CSV で Excel / Numbers / Google スプレッドシートのすべてが直接開ける**以上、割に合わない。却下。

**JSON と CSV を 1 つのボタンにまとめて形式を選ばせる**: 押す前に「どっちだっけ」を考えさせることになる。控えを取る導線（JSON）は主ボタンのまま残し、CSV は区切り線の下の副ボタンに置いた。**用途が違うものを選択肢にしない。**

**ID 列を出して往復をロスレスにする**: 「置き換える」も許せるようになるが、上に書いた 3 つの壊れ方を招く。そもそも**ロスレスな控えは JSON が既にある**ので、CSV が担う必要がない。却下。

**CSV 取り込み専用の入口（ボタン / ファイル種別の選択）を作る**: 利用者に「これは JSON か CSV か」を選ばせると、選び間違いという新しい失敗を 1 つ増やすだけで得るものが無い。`stage()` が JSON → 表の順に試して自動で見分ける。

**`csv` クレートを使う**: 正しさは確実だが、`memchr` / `bstr` / `itoa` / `ryu` が wasm に載る。このリポジトリは [グラフライブラリを使わず SVG を自前で描く](../architecture/no-chart-library-hand-rolled-svg.md) や [アイコンに lucide を採り、`assets/icons/*.svg` を `include_str!` で埋め込む](../architecture/lucide-icons-as-included-svg.md) の通り、ランタイム依存を 1 つも足さない方針で通してきた。RFC4180 の読み書きは 70 行に収まる範囲なので自前にした。
