# ラベルに色を持たせ、推移タブのデータ点をその色で描く

- **状態**: 採用
- **日付**: 2026-09-10
- **カテゴリ**: ux
- **関連**: [チップでラベルを選ぶと履歴とコピーが切り替わる](label-chips-switch-the-history-and-the-copy.md)（決定 13 と却下案「ラベルに色を持たせる」をこの ADR が改訂）, [ラベルの定義を種目に置き、ログには ID の印を 1 つだけ付ける](../data-model/labels-on-the-exercise-and-a-mark-on-the-log.md)（データ側の決定。「推移タブはラベルを見ない」をこの ADR が改訂）, [推移タブの対象を「部位 + 種目」の 2 セレクタにする](progress-target-as-group-plus-exercise-selects.md)（絞り込みが載る面）, [グラフライブラリを使わず SVG を自前で描く](../architecture/no-chart-library-hand-rolled-svg.md)（点を自前で描いているから色を差せる）, [グラフの座標計算を `chart_layout` に切り出してテスト可能にする](../architecture/chart-layout-as-a-testable-module.md)（`Band.idx` の性質）, [`color-scheme` を宣言し、クラスなしの `<button>` を作らない](declare-color-scheme-for-ua-widgets.md)（`<input type="color">` とチップの契約）, [ドロップセットの段はメインセットの下の箱に出し、推移では既定で外す](drop-sets-as-a-box-under-the-main-set.md)（推移タブの注記の先例）, [手書きの文言表を 1 ファイルに置く](../architecture/i18n-hand-rolled-string-table.md)

## 背景

[チップでラベルを選ぶと履歴とコピーが切り替わる](label-chips-switch-the-history-and-the-copy.md) が記録タブにラベルのチップを置き、[ラベルの定義を種目に置き、ログには ID の印を 1 つだけ付ける](../data-model/labels-on-the-exercise-and-a-mark-on-the-log.md) がデータの置き場所を決めた。どちらも**推移タブを明示的にスコープ外にしている**（前者の決定 13、後者の結果「推移タブはラベルを見ない」）。

その結果、HPS トレーニング（Hypertrophy / Power / Strength）を実際に続けると推移タブが読めない。ベンチプレスの折れ線に `70×10`（H の 700）と `100×3`（P の 300）が交互に並ぶので、**グラフがジグザグにしか見えず、どの狙いも伸びているのか分からない**。「前回」は狙いごとに引けるようになったのに、月単位の推移だけが混ざったままだった。

やりたいことは 3 つ。

1. 推移タブのグラフを「すべて」/ ラベル 1 つ でチップ切り替えして見られる
2. ラベルごとに色を設定できる（部位の `Group.color` と同じ感覚で）
3. その色がグラフの**データ点**の色になる

前の ADR で「ラベルに色を持たせる」を却下したときの理由は 3 つあった。この ADR はそのすべてに答える形で判断を覆す。

- (a) **部位の `--chip-0..3` の 4 段濃淡と意味が競合する。** 実際にはその濃淡は `.chip[data-recency]`（記録タブの最近のメニュー候補）と `.cal-day.is-picked` のもので、ラベルの色が出るのは**設定シートの行と推移タブの 2 箇所だけ**。同じ画面に並ばない
- (b) **「色 = 部位」という既存の読み方が崩れる。** 部位の色を消費しているのは `views::settings` / `views::day` / `views::routine` / `views::calendar` の 4 箇所で、**推移タブには部位の色が 1 つも出ていない**。読み方が衝突する面が無い
- (c) **色覚の配慮が別に要る。** チップは名前を持っており、色は冗長な符号でしかない。線・軸・体重の破線は色を変えないので、色が読めなくてもグラフの意味は 1 つも失われない

## 決定

### 1. `Label.color: String`（`#rrggbb`）を `#[serde(default)]` で足す

`skip_serializing_if` は**付けない**。`Exercise.labels` 自体が `skip_serializing_if` なので、ラベルを使っていない利用者の JSON はこのフィールドが増えても 1 バイトも変わらない（`model.rs` のバイト一致テストがそれを固定している）。付けると「色が空のラベル」と「色を持たない旧版のラベル」が JSON 上で区別できなくなり、表現できる形が 2 通りに割れる。

**既定色の門番は `core::clean_labels` の 1 箇所だけ。** 空文字や `#rrggbb` でない値はそこで `core::next_label_color` に置き換わる。`Exercise.labels` を書く経路は `normalize_exercises` / `set_labels` / `merge_labels` / `resolve_label` / `merge_db` の `..e` の 5 つしかなく、前 2 つは `clean_labels` を通り、後ろ 3 つはそれぞれの場所で同じ関数を呼ぶ。

**利用者が設定した有効な色は同色でも触らない。** 2 本を同じ色にしたのは選択であって壊れた値ではない。埋めるのは「持っていない」ときだけ。

**埋めるのは 2 パス目。** `clean_labels` は 1 パス目で空名を落として ID を整え、2 パス目で色を埋める。「使用済み」として数えるのは**残す行すべての有効な色**（後ろの行も含む）で、埋めた色もそこに足していく。前方だけを見て埋めると、`[色なし, #e0524a]` のように**無効な色が先・有効な色が後ろ**という並びで 1 本目がパレットの先頭を取り、2 本目は有効なので据え置かれて**同色 2 本**ができる。画面からは作れない（`add_label` が常に色を振る）が、手編集の JSON や色欄が一部欠けたファイルの取り込みでは起きうるので、「利用者が選んでいないのに重複する」経路をここで塞ぐ。

### 2. ラベル専用パレット `presets::LABEL_COLOR_CHOICES`（6 色）を新設する

`COLOR_CHOICES`（部位の色）を流用**しない**。ラベルの色が出る面には既に 2 つの固定色が居る。

| 固定色 | 用途 | 部位パレットの衝突相手 |
|---|---|---|
| `--accent: #2f6fd0` | 折れ線・ラベルなしの点 | `#2f7fd1`（背中） |
| `--muted` | 体重の破線 | `#6b7280`（体幹） |

`COLOR_CHOICES` の 2 番目は `#2f7fd1` なので、HPS の**2 本目（P）が無ラベルの点と見分けられない**。青系と灰を外した 6 色にしてこの衝突を型で消す。

```
#e0524a 赤 / #e0912a 橙 / #2fa06a 緑 / #7a56c9 紫 / #d4569b 桃 / #1f9e9e 青緑
```

赤・橙・緑・紫は部位パレットと同じ綴りだが、上記 (b) のとおり推移タブに部位の色は出ていないので衝突しない。

**`core::next_label_color(used) -> &'static str` は「未使用の最初の色」。** 位置ベース（`out.len() % 6`）だと ✕ で 1 本消してから ＋ で足したときに残った行と同じ色が生まれ、推移タブで 2 本のラベルが見分けられなくなる。6 色を使い切ったら重複を許して `n % 6` に落ちるが、`MAX_LABELS` が 6 でパレットも 6 色なので**現状この枝には到達しない** — 上限を増やしたときに関数が答えを返せなくなるのを避けるための逃げ道として置いてある。比較は大文字小文字を無視する。

**TSV に色列は足さない**（部位の色と同じ扱い。README の制限に書く）。取り込みで生まれたラベルには `resolve_label` がその場でパレットから振る。

### 3. `merge_db` の新規追加枝でだけ色を塗り替える

`merge_db` は `normalize` を呼ばないので `clean_labels` の門を通らない。2 台で独立に定義した 1 本目どうし（どちらもパレットの先頭色）をそのまま並べると、推移タブで区別できない 2 本になる。`merge_labels` の**新規追加の枝**で「不正な色 or こちらに既に居る色と衝突」なら塗り替える。

**同名寄せの枝は触らない。** あちらは `alias` を張って取り込み側の定義を捨てるので、こちらの色が勝つ（ログの `label` を「空のときだけ埋める」のと同じ、`mine` 優先の規則）。衝突していない有効な色は**そのまま採る** — あちらの端末で選んだ色を取り込みで黙って捨てない。

### 4. 設定シートのラベル行に `<input type="color">` を置く

名前入力の**前**に置く（丸い色見本 → 名前 → ✕ の順は推移タブのチップと同じ並びで、選んだ色がどこに出るかが読める）。書き込みは `on:input` で即 commit（部位の `group-color` と同じ）。`change_label` が `on:change` なのは重複判定のためで、色に重複の概念は無い。

`aria-label` は `Lang::color_of(name)`（「Power の色」/ "Colour of Power"）。**空名なら `settings.field_color` へ落とす** — `＋` の直後の行は名前がまだ無く、そのまま埋め込むと「 の色」という尻切れの読み上げになる。

`kb_focus` / `kb_blur` は付けない（色ピッカーは IME を出さないので、付けるとボトムタブが理由なく退避する）。

CSS は `.field .lbl-edit .lbl-color { width: 44px; min-height: 44px; padding: 2px }`。**詳細度 (0,3,0) が要る** — `.field input[type="color"]`（部位の 64px 幅）は (0,2,1) で、`.lbl-edit .lbl-color`（0,2,0）では負ける。44px まで詰めるのは 393px 幅に 色 + 名前 7.5em + ✕ + gap を収めるため。

**`commit_labels` では色だけ非対称にする。** 空名の行は**名前だけ**保存値を再送する（「✕ が唯一の削除経路」を守る規則）。色に同じフォールバックを書くと、**色を変えてから名前を打つ**という順序で必ず色が巻き戻る。`clean_labels` が色で行を落とすことは無いので、色は常に行の値を送る。

### 5. core に `SeriesPoint` と `*_points` を足し、既存の `*_series` は委譲にする

```rust
pub struct SeriesPoint { pub date: NaiveDate, pub value: f64, pub label: Option<LabelId> }
```

- `exercise_points(db, ex, m, from, to, d, filter)` — `find` の述語に `filter.passes(l)` を足し、`label: log.label` を載せる
- `group_points(..)` — `label` は常に `None`。**`LabelFilter` を引数に取らない**（ラベルは種目ごとに独立した体系なので、複数種目の合算に載せられる `LabelId` が存在しない、という表明）
- `pick_points(..)` — 同じ `match (p.exercise, p.group)`
- `aggregate_weekly_points(&[SeriesPoint])` — 値の集約は `aggregate_weekly` と**まったく同じ（合計・同じ週キー・同じ加算順）**

`exercise_series` / `group_series` / `pick_series` / `aggregate_weekly` は**シグネチャも挙動も変えず**、新関数への委譲にする（`last_log_before` → `last_log_before_with` と同じ「旧名は旧挙動、新名がパラメータ付き」の作法）。既存のユニットテストは 1 本も書き換えていない。

**週集約でラベルを残すのは「週内の全点が同じ 1 つのラベル」のときだけ。** 混ざった週に 1 色を選ぶと 3 分の 1 だけを指す色が週全体の点に付いて**色が嘘になる**。`Only` で絞れば週内は必ず同じラベルなので、「全期間」でもそのラベルの色は消えない。

`LabelFilter::passes` を `pub(crate)` にする（推移タブの**記録テーブル**が `pick_points` を通らず `db.sessions` を直接走るので、グラフと同じ絞りを掛けるには同じ述語が要る）。`is_hex_color` は `pub`（描画の直前の防御でも使う）。**`label_color` のような API は作らない**（使い手が無い）。

### 6. 推移タブの絞り込みは保存しない。種目を切り替えたら落とす

`label_sel: RwSignal<Option<LabelId>>` を `UiState` に足さない。指標・期間と同じ「今の見方」で、対象（`pick`）のような「どこを見ているか」ではない。保存すると、次に開いたとき記録があるのにグラフが空、という行き止まりを作れる。

**`commit` で `p.exercise` が変わったら `label_sel.set(None)`。** ラベルは種目ごとに独立した ID なので、持ち越すと門番が `Any` へ倒して「どのチップも点いていないのに隠れた選択が残る」状態になる（元の種目へ戻すと絞りが蘇る）。部位だけ変えたときは種目が据え置かれるので落とさない。

**門番 `filter: Memo<LabelFilter>`** は「種目を選んでいて、その ID がその種目の `labels` に実在する」ときだけ `Only` を出す。設定シートでラベルを消しても `label_sel` は `Some(消えた ID)` のまま残るので、素通しすると記録があるのにグラフが永久に空になり、チップ行からは戻し方も読めない（`views::day` の同型の門番と同じ理由）。

### 7. チップ行は `.selectors` の中に置き、それ自体を凡例にする

`.target-row` の直後・`metric-select` の前。**`Body` / `chart_body` の条件は 1 行も変えない** — 分岐を増やすと `Chart` が破棄・再生成され、読み取り点の選択が毎回リセットされる。

**ラベル定義が 0 本の種目・部位だけの選択では行ごと描かない**（「すべて」しか無い行は操作でも情報でもない）。

`.lbl-row` / `.lbl` / `.lbl.on` を記録タブ・設定シートと共有する（3 つ目の面）。**`.lbl` 自体は 1 文字も変えない** — flex 化すると `min-width: 44px` で広がった 1 文字チップ（記録タブの `H`）の文字が中央から左寄せへ退行する。`.dot` 側を `display: inline-block` で blockify する。追加するのは 4 ルールだけ。

```css
.selectors .lbl        { background: var(--surface); }   /* 隣の select と面を揃える */
.selectors > .lbl-row  { margin-top: 0; }                /* .selectors の gap と二重 */
.lbl > .dot            { display: inline-block; vertical-align: -1px; margin-right: 6px; }
.lbl.on > .dot         { box-shadow: 0 0 0 1px var(--accent-text); }
```

先頭の「すべて」チップにも `<span class="dot" style="--dot: var(--accent)">` を置く。これで**チップ行が完全な凡例**になる（「ラベルなしの点 = `--accent`」まで読める）ので、グラフの上に凡例のブロックを別に作らない。

`.segmented` は使わない（`flex: 1` で折り返さないので、ラベル名が長いと横に潰れる）。文言は ja「すべて」/ en "All labels" — `period_all`（"All"）・`all_groups` / `all_exercises` と同語にしない。記録タブの「指定なし」/ "Any" とも別語にする（**あちらのチップは今日のログの宛先も兼ねる**ので「絞らない」ではなく「付けない」の意味で、こちらは表示の絞り込みしか意味しない）。

記録テーブルは種目枝に `&& f.passes(l)` を足して同じ絞りに従う（部位枝は不変）。`stats` は `series` 派生なので自動追随。ドロップ注記（`hidden`）と体重は変えない。

### 8. `Chart` は色を外から受け取る。点だけが `--dot` を読む

`Chart` に第 4 プロップ `colors: Signal<Vec<Option<String>>>`（`series` と添字一致、`None` = 既定色）。**`Chart` から `Db` を引かない** — 引くと「座標計算 + 描画」だけだったこの部品が保存データに依存する。呼び側が `series` と同じ 1 本の `points` から作る（`pick_points` を 2 度呼ばない、`db.with` も増やさない）。

```css
.chart-dot          { fill: var(--dot, var(--accent)); }
.chart-dot.selected { fill: var(--surface); stroke: var(--dot, var(--accent)); }
```

`style="--dot:#rrggbb"` は **`<circle>` 自身**に置く。`--dot` は継承変数なので `.chart-wrap` や `<svg>` に置くと全点が同色になる。これが `views/chart.rs` の「見た目は CSS クラスに寄せる」規約の**唯一の例外**（利用者が選んだ色は取りうる値が有限でなく、クラスで表現できない）。

`colors` を作る側で `is_hex_color` を**もう一度**通して不正な値は `None` に落とす。`--dot:` が空文字で載ると `var()` のフォールバックが効かず**点が黒くなる**（`var()` は「値が空」を「未定義」と見ない）。

選択点（cursor group の `metric_dot`）も同じ添字で色を引く。`Band.idx` は系列の添字とは限らない（体重だけの帯がある）が、そのとき `Band.y` は `None` でこの丸は描かれない。添字は `[]` ではなく `get` で引く（wasm では panic = アプリが死ぬ）。

線・軸・体重の破線（`.chart-line` / `.chart-dot-weight` / `.chart-cursor`）は色を変えない。`chart_layout.rs` は 1 行も変えない。

## 理由

**色を点だけに載せたのが判断の中心。** 折れ線は「狙いをまたいだ推移」を繋ぐもので、点は「その日の狙い」を指す。線まで色を変えると系列が分かれたように見えるが、実際には 1 本の系列のままなので嘘になる（多系列にする案は下記のとおり却下）。点だけなら、色が読めない人にとってもグラフの意味は 1 つも変わらない。

**絞り込みと色は同じ 1 つの機能。** 色だけでは点が 3 色に散るだけで「P だけの推移」は読めず、絞り込みだけでは「すべて」表示のジグザグが説明されないままになる。チップで絞ると点数が 1/3 になるので、密表示（40 点）に当たらず 6M でも点の色が読める — **ラベルごとの推移はチップで絞って見るのが本線**で、色は「すべて」表示で混ざり方を読むためのもの。2 つが噛み合って初めて背景の問題が解ける。

**パレットを部位と分けたのは、衝突を運用ではなく型で消すため。** 「背中の青を選ばないようにする」は利用者の注意力に依存する規則で、`＋` を 2 回押すだけで破れる。候補から外せば破れない。

**チップ行を凡例そのものにしたのは、縦の予算を 1px も増やさないため。** 推移タブは既にセレクタ 2 つ + セグメント 2 つで上端が混んでいる。凡例のブロックを別に置くとグラフが下がる。チップは「名前 + 色見本」を既に持っているので、押せる凡例として二役を兼ねられる。

## 結果（トレードオフ）

**密表示（40 点超）では色が最新点にしか出ない。** 「すべて」表示で色が読めるのは 40 点以下で、HPS を週 3 で続けるなら約 3 か月ぶん。それを超えたら**チップで絞れば点数が 1/3 になり、6M でも非密になる**。密でも小さい点を描く案は却下した（3.5px 間隔に H / P / S が交互に並ぶと色の雑音にしかならない）。

**利用者が 2 本のラベルに同じ色を選べる。** 既定色は重複させないが、選んだ色は同色でも書き換えない（決定 1）。その場合、推移タブの点はその 2 ラベルのあいだで区別できなくなる。チップで絞れば分けて見られるので、行き止まりにはならない。

**ドロップ注記（`any_drops_in_scope`）はラベルで絞らない。** 「その対象・期間に段が在るか」はデータの事実で、ラベルの絞りは表示の設定。絞って 0 件になった状態でも注記が出ることがある。文言は「含めていません」なので嘘ではないが、非対称は意図的（`Drops` を受け取らない設計と同じ線）。

**「すべて」チップの丸は選択中に消えるので、縁を 1 本足した。** `.lbl.on` の背景は `var(--accent)` で、先頭チップの丸も `--accent` なので、**既定の状態（「すべて」が点いている）でちょうど丸が見えなくなる** — 凡例が初見でいちばん読めない、という一番まずい向きだった。`.lbl.on > .dot` に `box-shadow: 0 0 0 1px var(--accent-text)` を足して解いた。縁の色を `--accent-text`（`.lbl.on` の文字色）にしたので、コントラストは同じ面の文字と同じだけ確保される。`.lbl` / `.lbl.on` 自体のトークンは変えていない（`.opt.on` と揃える規約と、記録タブの 1 文字チップの寸法・中央揃えを守るため）。

**ライトモードの紫 `#7a56c9` は、選択中のチップ（`--accent: #2f6fd0` の背景）では 1px の縁だけが手掛かりになる**（輝度比は約 1.1:1 で、面としてはほぼ見分けが付かない）。選択中がどれかは背景の点灯で読めるので情報は失われず、グラフの点は `--surface` の上なので紫も読める（ダーク `#17181b` 上でも 6 色すべて 3:1 以上）。**`--accent-text` を触るときは `.lbl.on > .dot` の縁を消さないこと。**

**指標が 0 件のときは `<svg>` ごと無い。** `chart_layout::layout` は空の系列に対して空のレイアウトを返し、`Chart` は `<svg data-testid="chart">` ではなく `chart-empty` の段落を描く。つまり「絞って 0 件」の状態で `data-points="0"` は読めない。行き止まりの説明は記録テーブル側の `records-empty` が担い、グラフ側の `chart-metric-empty`（`empty_period_label`）が出るのは**体重が 1 件でもあって第 2 軸だけが残る**ときだけ。E2E はこの 2 経路を別々のテストで見ている。

**絞って 0 件のときの文言を 1 つ増やした**（`empty_period_label`）。「この種目の記録はありません」のままだと種目には記録が在るので嘘になり、「すべて」に戻せば見えることが読めない。

**推移タブのチップは絞り込み専用で、記録タブのチップは今日のログの宛先も兼ねる。** 見た目が同じ（`.lbl`）で意味が違うので、先頭の語を「すべて」と「指定なし」で分けた。同じ絵にしたのは「同じラベルという概念だ」と読めることのほうが重要だから。

**`Chart` のプロップが 4 つになった。** 呼び出しは 1 箇所しかないので必須プロップにしてある（省略できる形にする理由が無い）。

**設定シートのラベル行が 3 要素になった。** 393px 幅で 色 44px + 名前 7.5em + ✕ 44px + gap。12 文字のラベル名は今までどおり入る（`.lbl-name` の `width: 7.5em` は変えていない）。

**記録タブのチップには色を出さない。** カードの頭には既に部位の `.dot` が居るので、1 枚のカードに 2 つの色体系を置くことになる。記録タブでのチップの役割は「今日の狙いを選ぶ」で、色で区別する必要が無い（4 個以下で名前が読める）。

## 検討した代替案

**`.segmented`（指標 / 期間と同じセグメント）で絞りを出す。** 隣の 2 つと絵が揃う。しかし `.segmented` の子は `flex: 1` で折り返さないので、`Hypertrophy` のような長い名前が 4 つ並ぶと横に潰れて読めない。ラベル名は利用者が決める可変長なので、折り返す `.lbl-row` でなければならない。却下。

**`Chart` の中で `Db` を引いてラベルの色を解決する。** 呼び側が 1 プロップ短くなる。しかし「座標計算 + 描画」しか持たなかった部品が保存データに依存し、`chart_layout` を切り出したときに立てた境界を跨ぐ。却下。

**`pick_series` の戻り値に色を足す（`Vec<(NaiveDate, f64, Option<String>)>`）。** 新しい型が要らない。しかし既存の呼び側がすべて壊れ、`aggregate_weekly` / `aggregate_weekly_avg` / `chart_layout::layout` の署名まで波及する。旧名を旧挙動のまま残す作法（`last_log_before_with`）が使えなくなる。却下。

**ラベルごとに線を分ける（多系列）。** H / P / S の 3 本の折れ線が並び、それぞれの伸びが同時に読める。しかし (a) 320×160 の viewBox に 3 本 + 体重で 4 本が入り、`chart_layout` の帯・カーソル・読み取り点がどの系列を指すのか決められない、(b) 凡例が必須になり縦が増える、(c) `stats`（前回比 / ベスト / 平均）がどの系列のものか言えなくなる。チップで 1 本ずつ見る形なら既存の部品が全部そのまま使える。却下。

**TSV に色列を足す。** 書き出しから完全に復元できる。しかし部位の色も載せていない（[表計算で開ける TSV で書き出す](../storage/tsv-export-for-spreadsheets.md) の「落ちてよいのは名前から作り直せるもの」）。色は 1 タップで選び直せて、ぶら下がる記録が 0 件。16 列目を足す対価に見合わない。却下。

**週集約で色を混ぜる（週内の多数決、または混色）。** 「全期間」でも色が消えない。しかし多数決は 2:1 の週で少数側の記録を色から消し、混色は**パレットに無い色**を作って凡例と一致しなくなる。どちらも「その週の色」が何を指すのか説明できない。全点が一致するときだけ残す規則なら、色が出ていれば必ず正しい。却下。

**密表示でも小さい点（r=1.5）を描く。** 「すべて」表示でも色が読める。しかし 3.5px 間隔に H / P / S が交互に並ぶので、読めるのは「混ざっている」ことだけで、どの狙いが伸びているかは分からない。同じことをチップの絞り込みが正確にやる。却下。

**`COLOR_CHOICES`（部位の 6 色）を流用する。** パレットが 1 本で済む。しかし 2 番目の `#2f7fd1` が `--accent` と、6 番目の `#6b7280` が体重の `--muted` と見分けられない。HPS なら 2 本目が必ず当たる。却下（決定 2）。

**`.lbl` を flex コンテナにして丸と名前を並べる。** マークアップが素直になる。しかし `.lbl` は記録タブの 1 文字チップと共有していて、flex 化すると `min-width: 44px` で広がったチップの文字が中央から左寄せへ退行する。既存 E2E はチップの寸法しか見ていないのでこの退行を捕まえられない（この ADR の PR で `Range.getBoundingClientRect` の見張りを 1 本足した）。`.dot` 側を inline-block にすれば `text-align` の中央揃えが保たれる。却下。

**絞り込みを `UiState` に保存する。** 次に開いたときも同じ狙いが出る。しかし指標・期間を保存していないのと同じ理由（「今の見方」であって「どこを見ているか」ではない）に加えて、保存すると**記録があるのにグラフが空**の状態でアプリが起動しうる。却下（決定 6）。

**記録タブのチップにも色を出す。** 2 つの面で絵が揃う。しかしカードの頭に部位の `.dot` が居るので、1 枚のカードに 2 つの色体系が並ぶ。記録タブでのチップの役割は「今日の狙いを選ぶ」で、色は情報を足さない。却下。
