# インターバルは秒の整数 1 つを種目に持たせ、ピンの下に並べる

- **状態**: 採用
- **日付**: 2026-08-23
- **カテゴリ**: ux
- **関連**: [マシンのピンは種目に持たせ、メモのトグルに相乗りさせる](machine-pins-on-the-exercise.md)（すべての制約と作法を継ぐ相手）, [メモは種目カードのトグル 1 つで開き、閉じても薄字で残す](exercise-and-set-notes-behind-one-toggle.md)（入口と縦の予算）, [種目メモとセットメモを `ExerciseLog` / `SetEntry` に持たせ、空のメモは書き出さない](../data-model/notes-on-logs-and-sets.md)（スコープの対比）, [数値入力に `type="number"` を使わない](text-input-not-number.md), [表計算で開ける TSV で書き出す](../storage/tsv-export-for-spreadsheets.md), [TSV の見出しは UI の言語に従う](../storage/tsv-header-follows-the-ui-language.md), [取り込みは「足すだけ」に固定する](../storage/import-is-merge-only.md), [手書きの文言表を 1 ファイルに置く](../architecture/i18n-hand-rolled-string-table.md)

## 背景

種目ごとにセット間の休憩時間は決まっている。マシン種目は 60〜90 秒、デッドリフトやスクワットは 3 分。**この秒数を置く場所が無かった。**

置きたい情報の性質は [マシンのピンは種目に持たせ、メモのトグルに相乗りさせる](machine-pins-on-the-exercise.md) が扱ったものと**同一**である。日ごとの観測（「今日は肩が痛い」）ではなく、その種目に貼り付いて日をまたぐ設定値。だから背景・制約・却下された代替案のほとんどをあの ADR から継げる:

- カード内に 44px のタップ標的を新設できる場所は無い（どこに作っても 44px × カード枚数だけ縦に純増し、5 種目で 220px）
- ヘッダは `e2e/smoke.spec.mjs` / `e2e/pins.spec.mjs` が `.card-head button` を 0 件で固定している
- `.card-foot` は 3 者が別の列にいて、393px 幅の空きが 58px しか無い

継げないのは 1 点だけ。**ピンは「複数個の記号」だが、インターバルは「1 つの数値」**である。この差が決定 1・2 を分ける。

## 決定

### 1. `Exercise.interval_sec: Option<u32>`。秒の整数を 1 つだけ持つ

```rust
#[serde(default, skip_serializing_if = "Option::is_none")]
pub interval_sec: Option<u32>,
```

**`SCHEMA` も `storage::KEY` も上げない。** `model.rs` の規則そのままで、`#[serde(default)]` 付きの追加は旧版が未知フィールドとして黙って無視するので `migrate` が `Err` を返さない。上げると逆に旧版が `RestoreError::Unsupported` で退避し、**前方互換を積極的に壊す側になる**。`skip_serializing_if` により、インターバルを使わない利用者の JSON は**今までとバイト単位で同一**のまま（`exercise_omits_an_unset_interval_from_its_json` がリテラルで固定している）。

**`String` にしない。** ピンが `String` なのは穴に `A` や `赤` と刻んだマシンが実在するからで、秒数にその事情は無い。数値で持てば上限で丸められ、書き出しのセルも裸の数字になる。

**`Option` にする。** 「未設定」と「0 秒」を分けるため。0 秒は**スーパーセット（休まず次のセットへ）という正当な入力**で、`parse_reps` が 0 を落とすのとは前提が違う（あちらは `0×0` のゴーストセットが指標・ドット・コピーを汚染する）。`Session::body_weight` が「未計量」を `Option` で持つのと同じ立場。

**1 種目 1 つにする。** ピンは「シート高 3 / バー位置 3」のように複数の穴を上から順に触るので `Vec` に意味があった。インターバルに順序も並列も無い。複数にすると「ウォームアップ 60 / 本番 120」を書けるが、**どれがどれかを区別する語がチップに無い** — 数字が 2 つ並ぶだけで、読んだ側が意味を復元できない。

上限は 999 秒（`MAX_INTERVAL_SEC`）。これは UI の制限ではなく**取り込みのための門番**で、`MAX_PINS` と同じ立場。取り込んだ JSON には `u32::MAX` が入りうるので、丸めないと `4294967295秒` が薄字に出てカードが折り返す。

正規化は `core::normalize_exercises` / `core::set_interval` が `clean_interval` を共有する。**2 経路に分けて書かない** — 食い違うと「画面から打てるのに取り込みで丸められる」が起きる。

### 2. 入口を増やさない。ピン・種目メモと同じトグル 1 つで開く

`＋ メモ` を押すと、種目メモ・全セット行のメモ・ピン欄に加えて**インターバル欄も一緒に開く**。専用のトグルもアイコンも作らない。

これで**新しい 44px のタップ標的が 0 個**になる。[マシンのピンは種目に持たせ、メモのトグルに相乗りさせる](machine-pins-on-the-exercise.md) 決定 2 とまったく同じ判断で、あちらが「1 つも消費せずに済む」と書いた予算を今回も 1 つも使わない。`e2e/interval.spec.mjs` が `.card-head button` 0 件 / `.card-foot button` 2 個で固定している。

**タップで走るカウントダウンは作らない。** 今回は「値を置いて次回読む」メモまで。タイマーにすると (a) 走行中の状態をどこが持つか、(b) バックグラウンドでタイマーが凍結される（`adr/pwa/sw-update-on-visible.md` と `adr/storage/flush-on-visibilitychange.md` が 2 度踏んだ問題）、(c) 音とバイブレーションの許可、(d) 画面を閉じても鳴るのか、の 4 つが要る。**どれもこの ADR とは別の決定**なので、要望が出た時点で別に採る。値が保存されていれば、その日は素直に載せられる。

### 3. 位置はピンの下・種目メモの上

読み順が「準備（ピン → インターバル）→ 観測（メモ）」になる。

ピンと同じ段に置くのは、**両方が「その種目の設定」で、下の種目メモだけが「その日のこと」**だから。カードの下部が 2 段に分かれ、上の段（ラベル付き・種目に貼り付く）と下の段（ラベルなし・日に属する）で読み分けができる。`e2e/interval.spec.mjs` が DOM 順を `['pin-read', 'interval-read']` で固定している。

入力欄は `type="text"` + `inputmode="numeric"`（[数値入力に `type="number"` を使わない](text-input-not-number.md)）。`pattern` は付けない — 整数秒なのでセット行の回数欄と同じ。`maxlength` は 3（`MAX_INTERVAL_LEN`）で、**打てるのに保存で丸められる欄にしない**。`kb_focus` / `kb_blur` は必須。

### 4. 閉じている間もインターバルは薄字で読める

`インターバル 90秒` を 12px + `var(--muted)` で出す。`.pin-read` と同じ段・同じ左端。

**これが「タップして開く」より速い。** マシンの前に立った利用者はカードを見た時点で秒数を読み終えている。開くのは値を直すときだけ。

**`opacity` は使わない**（非テキストの 3:1 を割り、ダークで消える）。`e2e/interval.spec.mjs` が `{ fontSize: '12px', opacity: '1' }` で機械的に固定している。

単位は表示に含める（`90秒` / `90s`）。裸の `90` では秒か分か回数か読めない。**分:秒 に整形しない** — 決定 1 が秒の整数に決めた以上、表示だけ `1:30` にすると入力欄（`90`）と薄字（`1:30`）で同じ値が 2 つの表記を持ち、「打った値がそのまま出る」が崩れる。

### 5. 削除は ✕ ではなく空欄

欄が 1 つなので、消すのは「空にする」で足りる。**✕ ボタンを置かない**（タップ標的が 1 個増え、しかもすぐ隣の入力欄を空にすれば同じことができる）。空にすると `parse_interval` が `None` を返し、`set_interval` が未設定へ戻して薄字ごと消える。

### 6. 開閉状態は `storage::UiState` に入れない

`note_open` に相乗りしているので自動的にそうなる。種目ごとの開閉は `ExerciseId` の集合 = `Db` 参照になり、[UI の状態を `Db` に入れず別キーに置く](../storage/ui-state-in-separate-key.md) の前提から外れる。

### 7. TSV に `インターバル秒` / `Interval sec` 列（14 列目）を足す

書かないと**機種変更でインターバルだけ消える**。ピン列を足したときとまったく同じ理由で、ここはどこからも再構成できない利用者の入力。進化規則どおり末尾に足すだけで、既存 13 列の意味は変えない。

**その種目がファイル中で最初に現れた行にだけ書く。** 条件がピンと完全に同じ（「その種目の初出行」）なので、**書き終えた種目の集合を 2 本持たない** — `pins_written` を `ex_meta_written` に改名して 1 回の `insert` で両方を決める。列が増えるたびに集合が増えると、片方だけ `insert` を忘れる余地が生まれる。

種目マスタ行の「手つかずのプリセットは書かない」判定に `interval_sec.is_none()` を足した。**足さないと、記録にもメニューにも出てこないプリセットに付けた秒数だけが黙って消える。**

見出しの綴りは日英とも**足した時点で永久の外部仕様**（TSV は版番号を持てない）。単位を見出しに入れるのは `重量kg` / `体重kg` と同じ流儀で、セルは裸の数字。

### 8. 取り込みは上書きしない / 未設定なら埋める

`merge_db` の `fill_interval` と `parse_tsv` の `take_interval` の両方で、**手元が未設定のときだけ**入れる。

★ `merge_db` の **ID 一致の枝**がこの機能の成否を分ける。プリセットは固定 ID を持つので新品端末への復元は必ずそこを通り、その枝は取り込み側の `Exercise` を丸ごと捨てていた。直さないと記録は全部戻るのにインターバルだけ落ちる。

「未設定のときだけ」は `Option::is_none` で見る。`Some(0)` は入っている値なので上書きしない。

**読めないセルは黙って無視する。** シートで `1:30` や `90秒` と打ち直された値を 0 として取り込むと「休まない種目」に化ける。落とすほうが安全で、元の値はファイルに残っている。

### 9. 文言は `i18n.rs` の表に置く。**ついでにピンの 5 文字列も移した**

`interval` / `interval_unit` を `Day` に足した。あわせて `views/day.rs` に日本語でハードコードされていた**ピンの 5 文字列**（ラベル・薄字・`aria-label` 3 つ）も表へ移した。

ピン機能（2026-08-19）と i18n 化（同日）が同じ日で、ピン側が漏れていた。今回インターバルのラベルがすぐ隣に並ぶので、直さないと英語 UI で `ピン 3・5` / `Interval 90s` と**半分日本語の 2 行**になる。`e2e/i18n.spec.mjs` が両方の綴りを固定した。

英語は `Rest` ではなく `Interval` にした。TSV の見出しが永久の外部仕様になるので、`interval_sec` / `インターバル` / `Interval` / `Interval sec` を 1:1 に揃えて、後から名前がずれる余地を消す。

## 理由

**同じ性質の情報は、同じ場所・同じ作法で持つ。** ピンとインターバルはどちらも「その種目をどうセットするか」で、日をまたいで貼り付く。別の入口・別のスコープ・別の保存先に散らすと、利用者は「どれがどこに保存されるか」を 3 通り覚えることになる。決定 2〜8 がほぼ全部ピンの ADR の写しなのは手抜きではなく、**同型のものを同型に保つこと自体が設計**だという判断。

**「1 つの数値」と「複数の記号」は型で分ける。** 継げるところは全部継ぎ、継げない 1 点（多重度と型）だけを変えた。ここを揃えて `Vec<String>` にすると、上限も丸めもパースも失われ、意味の無い柔軟さのために TSV のセルが空白区切りになる。

**入口の数はカードの高さそのもの。** 1 日 5〜8 枚並ぶ画面では 44px の標的 1 個が 220〜352px の縦に化ける。3 回連続で「トグルを増やさない」を選んでいるのは趣味ではなく、トレ中のスクロール量を決める制約。

**メモとタイマーの間に線を引く。** インターバルは本来タイマーを呼ぶ機能だが、タイマーは「走行中の状態」を持つ。このアプリの他のどの機能も走行中の状態を持っていないので、それを入れる判断は独立させるべきだった。

## 結果（トレードオフ）

**薄字が 3 行並びうる。** ピン・インターバル・種目メモを全部持つカードは 12px の `--muted` が 3 行になる（約 48px）。[メモは種目カードのトグル 1 つで開き、閉じても薄字で残す](exercise-and-set-notes-behind-one-toggle.md) 決定 4 が避けた「トークンが同一な行の連続」に、ピンの ADR より深く踏み込んでいる。ラベルの有無（`ピン` / `インターバル` / 無し）で読み分ける。

**`＋ メモ` のラベルがさらに実態から離れた。** 押すとメモ・ピン・インターバルが開くが、ラベルは「メモ」としか言わない。フッタの間隔予算を守るほうを採った。

**カウントダウンが無い。** 「インターバル 90秒」と読んでも、計るのは利用者のストップウォッチ。決定 2 で意図的に落とした。

**分:秒 で読めない。** `180秒` は `3:00` より数えにくい。入力と表示で同じ値が 2 つの表記を持たないほうを採った。

**TSV が 14 列になる。** 既存のシートで列幅や数式の範囲を設定していた人は作り直しになる。

**リロードするとインターバル欄は閉じる。** 薄字が残るので情報は失われない（`note_open` と同じ）。

**0 秒と未設定の違いが画面から読み取りにくい。** `インターバル 0秒` と「行が無い」で区別するが、意図して 0 を入れた人以外には差が分からない。型で分ける（`Option`）ほうが取り込みとマージで正しいので、表示の曖昧さは許した。

## 検討した代替案

**`1:30` の形式で持つ / 表示する。** 3 分を `180` と打つのは桁が多い。しかし「数字だけを入力する」という要件そのものが崩れ（`:` を打つキーが数字キーパッドに無い）、入力欄と薄字で表記が 2 つに割れる。パースも `mm:ss` / `m:s` / `90` の 3 通りを受けることになる。却下。

**分単位にする。** `1` / `2` / `3` で足りて桁が最小になる。しかし 90 秒が打てない — 小数を許すと「数字だけ」から外れ、`Option<f32>` になって丸めと表示の桁が増える。ジムで実際に使う値の中心が 60〜120 秒なので、単位を分にすると表現できない値が最頻値になる。却下。

**ピンのように複数持つ（`Vec<u32>`）。** 「ウォームアップ 60 / 本番 120」が書ける。しかしチップに区別の語が無いので、数字が 2 つ並ぶだけで意味が復元できない。チップ列が 1 段増えてカードも伸びる。却下。

**ピンと同じ行に並べる（`ピン 3・5・2　インターバル 90秒`）。** 薄字が 3 行にならず、カードの高さが 1px も増えない。実測でも 393px 幅に収まる（約 200px）。**本人がこれを採らなかった** — ラベルが常に左端に揃うほうが読みやすいという判断で、縦 16px はその対価。反転は安い（`.pin-read` と `.interval-read` を 1 つの `<p>` にまとめるだけ）。

**`u32` を直に持ち、0 を「未設定」とする。** `Option` が消えてコードが 1 段浅くなる。しかしスーパーセット（0 秒）を表現できず、`skip_serializing_if` も書けないので**使っていない利用者の JSON が変わる**（既存のバイト一致テストが落ちる）。却下。

**種目に持たせず `ExerciseLog` に持たせる（その日のインターバル）。** 「今日は疲れているので長めに休んだ」を記録できる。しかし毎日入れ直すことになり、**次に同じマシンへ来たときに前回の値が出ない** — 「1 か所直せば全日に効く」という設定としての価値が消える。種目メモが既にその役をしているので、自由記述で足りる。却下。

**設定タブの種目編集シートにも編集口を置く。** `ExerciseEditor` が担当するのは「種目マスタの同一性と可視性」（名前 / 部位 / アーカイブ）。ピンと同じ理由で層が違い、モーダルシートの中は**マシンの前で開く場所ではない**。要望が出たら 1 行で足せる。却下。

**タップで走るカウントダウンを付ける。** トレ中の実用性はいちばん高い。決定 2 に理由を書いたとおり、走行中の状態・バックグラウンド凍結・音の許可・画面を閉じたときの挙動という 4 つの独立した決定が要る。**この機能を採らないのではなく、別に採る。**
